# Признаки детали и выбор стратегии поиска — D251

2026-11-11. Первый этап реализован. Новые правила поиска остаются предметом отдельных экспериментов.

## Что можно классифицировать

Для листа с подтверждёнными плоскими стенками и прямыми гибами достаточно небольшого набора **строительных элементов**: стенка с контуром, гиб с осью и параметрами, связь между ними. В существующем `SheetLayout` стенки и гибы уже образуют такой граф. Он сохраняет геометрию, а не только названия форм. Связный лист может содержать повторяющиеся цепочки, несколько ветвей и их комбинации. Даже если ограничить число гибов, одинаковый граф допускает множество разных размеров, торцов и зазоров. Одинаковые графы и контуры в одном сечении могут вести себя по-разному при гибке.

Поэтому у нас две разные задачи:

- **Описание формы:** подтвердить разбиение и выделить сколько угодно совместимых признаков. «Смешанная» форма может быть полностью поддержана, даже если у неё нет отдельного названия. Неоднозначное разбиение и геометрия вне текущей модели обрабатываются по существующим правилам неподдержанной геометрии.
- **Планирование:** для состояния листа и конкретной оснастки определить допустимые установки и их порядок. Один признак сам по себе не доказывает технологическую эквивалентность и не является ключом результата проверки.

## Предлагаемые границы в коде

1. **Подготовка по одному снимку детали.** Брать проверенный `SheetLayout` из существующего CAD-worker. Сохранять исходные идентификаторы гибов. Начать с численных признаков, для которых уже есть данные и потребитель: одиночная зона, параллельная цепочка, ветвление и глубина полок. Характерные комбинации могут перекрываться. Местные признаки (непрямой торец, общий ход, различный просвет вдоль оси) добавлять с отдельным правилом и проверочным случаем. Не размечать класс по имени файла, мировым осям или габариту.
2. **Выбор кандидатов в текущем состоянии.** Маска сформированных зон, выбранный инструмент, его реальные секции и разрешённые положения определяют, какие из подготовленных признаков сейчас уместны. Например, у коробки возвратная полка влияет на проход лишь после её формирования. Несколько правил могут менять порядок в одном поиске. Состояние «данных недостаточно» сохраняет общий путь. Отсев разрешён лишь при доказанном ограничении на рассматриваемый вариант, например при пустом интервале допустимых смещений с учётом фактической формы тел.
3. **Единая точная проверка и кэш.** Те же коллизии, опора, упоры, охват движения и правила публикации результата. Признаки формы и выбор стратегии не входят в ключ проверенного перехода. Для повторяющихся гибов сначала измерять повторы локальных вычислений, затем переиспользовать только подтверждённо эквивалентную подзадачу. Готовый вердикт остаётся привязан к точному состоянию и установке.

Внутренний модуль `RouteSheetFeatures` получает проверенный `SheetLayout` и возвращает маски соседства, ранги параллельной цепочки и глубину полок по исходным индексам гибов. Граф стенок строится один раз для обоих обходов в одном запросе. Подготовка выполняется на существующем CAD-worker после получения развёртки. Условия включения приоритетов, выбор начальной стенки цепочки, порядок проб и ключи проверенных переходов сохранены. Новые признаки подключаются к поиску по одному после измерений.

## Проверка покрытия и эффекта

На первой выборке фиксировать, какие признаки получены, к каким зонам они привязаны, где сработал общий путь, где исходное разбиение не поддержано. Взять уголок, открытый лоток, деталь с возвратными полками, волну с 16 гибами, смешанную деталь и случай с разным доступом по концам. Включить повороты, зеркальные варианты и близкие размеры: при изменении мировой ориентации структура должна сохраняться, а местные направления переноситься вместе с геометрией. На одном примере менять инструмент, на другом — промежуточное состояние при той же оснастке.

Результаты первого локального прогона Release на STEP.

| Модель | Результат анализа |
|---|---|
| Уголок | Одна зона, общий путь. |
| Открытая коробка | Четыре зоны с нулевой глубиной полок. |
| Волнистая панель | Параллельная цепочка из 16 зон. |
| Корпус пульта | Восемь зон, из них четыре внутренних. |
| Стойка с подрезами | Пять зон разных направлений, одна внутренняя. |

Для уголка, коробки и панели сравнили поиск без оснастки до и после переноса кода. Полностью совпали журнал попыток, итоговый порядок, стороны и число точных переходов (1, 4 и 16). Для корпуса и стойки этот прогон охватывал распознавание признаков на подготовленной развёртке. Журналы сравнения хранятся в `out/d251-route-features/`.

Сборки Linux Release и `dev-app` прошли. Успешны 12 целевых CAD-тестов, включая цепочки на 16, 24 и 32 гиба, совместные гибы, повёрнутую коробку, общую сборку и сапожки. При сравнении с исходными сборками совпали число проб и сведения о выбранной оснастке в тестах общей сборки и сапожков.

Для сравнения стратегий на открытых цепочках подходит BendSeq. Он принимает численное 2D-описание с ограничением до семи гибов. [Архитектура BendSeq](https://github.com/KanadeK/bendseq/blob/main/docs/architecture.md)

Пять опубликованных STEP BenDFM дали проверенную развёртку. Число распознанных гибов совпало с числом операций в исходных JSON авторов для всех пяти деталей (7, 2, 2, 7 и 8). Три модели имеют ветвления, две с непараллельными гибами используют общий путь. Это проверка разбора геометрии и признаков, а не сверка маршрутов или коллизий. [Модели и исходные данные BenDFM](https://github.com/UGent-CVAMO/bendfm/tree/2d18640505ac3cd1acc694c6f6ac9c289b6dd6c5/example_files)

Для нового правила сравнивать с прежним поиском при одинаковых бюджетах: долю найденных маршрутов, время до первого подтверждённого маршрута, число и время точных проверок, долю попаданий в кэш. Для небольших деталей сверять исход с контрольным перебором допустимых в модели установок. [Эксперимент D250](bend-route-search-optimization.md#приоритет-по-уже-согнутой-соседней-полке--эксперимент-d250) уже показал, что правдоподобный признак может менять порядок без выигрыша. Одной доли распознанных классов для решения о включении недостаточно.
