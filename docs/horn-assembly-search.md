# Подбор сборок с сапожками — D206

2026-11-06. Первоначальное предложение D206; **реализация D207 описана ниже**. Пользователь уточнил: настроенная секция с сапожком сохраняет рабочую кромку и может выполнять обычный гиб; её дополнительное освобождение у торца позволяет проходить соседней полке. Это не отдельная несовместимая категория инструмента для «особых» гибов.

Основа — [реализованные тела/редактор D205](horn-section-editor.md#реализовано--d205), [совместный подбор D167](route-assembly-search.md) и [сохранение общей сборки D174](common-assembly-search.md). Нет правил по артикулу 1063, имени STEP, числу гибов или частной длине полки.

## Пригодность и предпочтение

- Настроенный сапожок того же родительского DXF имеет контактную кромку по всей длине своей секции. При расчёте охвата используется **длина секции**, не вылет 27 мм и не длина радиуса. Выемка меняет только реальный объём за кромкой.
- `usableToolSegment` уже отличает поддержанную форму от учётного окончания без a/R/h. Не нужен сохраняемый флаг `canBendAsStraight`: возможность определяется существующим профилем, формой и результатом общего checker.
- Наличие прямого торца у детали не запрещает сапожок. Нехватка прямых секций не означает нехватку всей пригодной кромки, если есть реальные настроенные окончания.
- При новой равноценной сборке обычные секции — мягкое предпочтение. Уже выбранную/проверенную сборку с сапожками сохранять для обычных операций, когда это позволяет избежать изменения состава. Нельзя тратить бюджет на замену исправной общей сборки только ради меньшего числа сапожков.
- Геометрическая взаимозаменяемость не переносит паспортную допустимую нагрузку прямой секции на вырезанное окончание. Текущий модуль не рассчитывает прочность сапожка; это прежняя граница геометрической модели.

В первом охвате остаются ограничения D205: не более одного настроенного левого окончания первым и правого последним, внутри прямые секции. Отдельная целая секция-сапожок допустима. Это сознательно ограниченное семейство, а не доказательство невозможности иных физических сборок/установок.

## Почему одной замены фильтра недостаточно

Сейчас `assemblyLength`/`usableToolSegment` принимают расчётные сапожки, а `planToolSegments` и `planToolWindow` намеренно используют Straight. Удалить этот фильтр нельзя: обычная сортировка по длине может поместить левую/правую выемку внутрь сборки. Кроме того, один выбранный только по длине состав не гарантирует правильное положение освобождения относительно детали.

Первичный отбор пары в `ToolSelection::selectTools` и `screenTools` также проверяет длину через прежний планировщик. Если расширить лишь CAD-поиск сборок, профиль с достаточными сапожками, но недостаточными прямыми секциями может вообще не попасть в поиск. Оба потребителя должны пользоваться одним новым ограниченным семейством. Матрица и её планирование окна остаются на прежнем пути.

## Небольшое семейство вместо перестановок

Рассматривать структуру:

1. Прямые секции.
2. Левый сапожок + прямые секции.
3. Прямые секции + правый сапожок.
4. Левый сапожок + прямые секции + правый сапожок.

Левое/правое окончание — конкретная строка фактического склада, не новая выдуманная форма. Несколько известных выемок одной длины дают разные варианты; неизвестные/нулевые остатки не дают кандидата. Совпадающие реальные сборки удаляются из списка. Только ограниченное число вариантов из общего бюджета, без полного произведения всех строк и перестановок середины.

Для каждого выбора окончаний резервировать их количество и число позиций, затем подбирать середину из прямого остатка. Отсутствие середины допустимо: отдельный сапожок или пара не должны ломаться о старый минимальный target=1 мм. Количество секций, 0,001 мм, максимальный габарит, uniform/local gaps и предел 512 остаются общими. Зазоры проверять с учётом **всех** стыков, включая границы окончаний; простое вычитание длин и запуск прежнего gap-solver на середине даёт неверное число стыков.

Таблица достижимых длин прямой середины одинакова для разных окончаний одного снимка: сапожки не расходуют прямой запас. Для пути без зазоров её можно построить один раз в общем лимите и запрашивать остаточную длину. Если понадобятся разные числа стыков, сохранить необходимую информацию о количестве, как в существующем gap-DP. Не менять успешные ответы прежнего straight-only API ради этой оптимизации; сначала сохраняющий поведение перенос с проверкой старых результатов.

Предлагаемый потребитель — отдельная функция в предметном слое, возвращающая небольшой список реальных `ToolAssembly` и признак неполноты. Прежний API прямых секций остаётся для матрицы/окна и reference-регрессий. Нет Qt/OCCT, общего планировочного framework или дискового кэша численного поиска.

## Связь с расположением и реальным столкновением

Сборка с выемкой полезна только там, где выемка действительно находится рядом с мешающей полкой. Длинный инструмент с сапожками далеко за пределами детали может конфликтовать серединой точно так же, как прямой. Положение детали по Z и разворот пуансона меняют соответствие сторон. Направление на экране не определяет нужное окончание.

Текущие три положения D169 и обе ориентации остаются ограниченными пробами, не доказательством отсутствия другого положения. В качестве следующей подсказки можно извлекать численный осевой интервал из уже рассчитанного **Sheet–Punch Common**, аналогично D173 для матрицы. Нужны реальные данные CAD-worker, не пятна/сферы из viewer. Интервал может ранжировать сторону/вариант; большой bbox или подсказка формы не доказывают, что сапожок пройдёт, и не запрещают остальные варианты. Центральный конфликт не объявлять исправленным торцевой выемкой.

Каждая новая установка проходит прежний полный checker: весь активный материал покрыт рабочими кромками, оба инструмента нужной длины, V/углы/контакт/опора, настоящие тела секций/держатели/станок/пол, базы/движение упоров, все промежуточные состояния и полный отвод пуансона. D199/D201 и обе реконструкции прежние. Пригодность конечного кадра не заменяет пригодность цикла.

## Порядок поиска и сохранение общей установки

Сначала прежняя ограниченная попытка исходной общей сборки D174, без изменения её контракта/квот. Затем по явному разрешению подбора секций — ограниченное семейство окончаний и дальнейший совместный поиск с порядком/ориентацией детали. Обычный фиксированный ручной маршрут не должен автоматически менять инструмент.

Для сохранения одной новой сборки на всю деталь нужно отдельно попробовать подходящие общие кандидаты с окончаниями в пределах **того же** общего бюджета. Только после этого разрешать разные составы операций. Не запускать новый полный поиск со свежим лимитом на каждую комбинацию. Между ограниченными семействами нельзя переносить доказанные тупики как всеобщую невозможность; точные проверенные переходы можно сохранять по фактическим входам, как в D174. Улучшение числа смен после первого найденного маршрута — отдельная оптимизация, не обязательное ожидание для пользователя.

Предпочтения среди прошедших проверку вариантов: сохранить подходящую установленную общую сборку, затем сократить изменения состава и неудобные развороты детали; при прочих равных предпочитать прямые секции/меньше деталей сборки. Наличие сапожка не штрафуется настолько, чтобы породить ненужную смену инструмента на обычной операции. Станции, реальные действия переналадки и снятие/перенос детали между установками по-прежнему отдельно не моделируются.

## Кэш, владение и принятие результата

- Численные планы окончаний — локальный ограниченный кэш CAD-worker по точным профилю/наличию/требуемому охвату/пределам/политике. Много состояний маршрута с одинаковыми входами переиспользуют один результат. Неполнота/лимит не `NoRoute`.
- Готовые тела и отвод уже сохраняет D205/D091: геометрия выемки/последовательность/стыки входят в точные ключи. Новая библиотека кэширования не нужна.
- Вердикт перехода остаётся зависимым от состояния детали, активных зон, полного назначения, сторон/осевого положения, станка/упоров/support-policy. Схожая длина или общий артикул не позволяют переносить результат.
- GUI до атомарного принятия сверяет исходный scope, обе ревизии/stop/ID, количество/порядок/полные формы и охват. Менять только строки `punchAssembly`; снимок склада не изменяется и наличие не расходуется между последовательными независимыми гибами. Матрица меняется только в ранее разрешённом scope.
- Новая форма уже помещается в v6/v19 D205; один лишь автоматический выбор существующей формы не требует новой схемы проекта.

## Этапы реализации и проверки

1. Численное семейство и первичный отбор без отсева профильной длины, набираемой сапожками. Прямой reference-путь и ручные назначения сохранить. Проверить по полному перебору на малых собственных складах: неизвестная форма, недостаток/повторное расходование, одинаковые длины с разными выемками, неправильный край, пустая середина, оба окончания/стыки, отмена/лимит.
2. Подключение к совместному поиску и ограниченные общие кандидаты. Собственная асимметричная деталь: обычная операция проходит обоими составами, угол — только правильным окончанием; неверный конец/малая выемка/неправильное положение должны конфликтовать. Проверить сохранение одной сборки в маршруте и отказ настоящего внутреннего конфликта/короткого инструмента.
3. Использование уже готового контактного интервала как приоритета, если измерения покажут пользу. Отдельно сравнить число новых CAD-переходов, время и совпадение результатов reference/optimized; лимиты/отказы не подменять.

Регрессии: уголки/швеллеры/коробки, совместные зоны/составные торцы, фактическое окно матрицы и неизменённые локальные стыки, профили 16–32 гибов, обе ориентации пуансона/детали, полный отвод, кэш/проект/ревизии. Использовать собственные геометрии для fixtures; частные STEP и артикул 1063 не становятся условиями алгоритма.


## Реализовано — D207

2026-11-06. `core::planPunchAssemblies` возвращает ограниченное семейство реальных сборок. Если доступных настроенных окончаний нет, непосредственно вызывается прежний straight-only `planToolSegments` с прежним результатом. При наличии окончаний общая таблица прямой середины строится один раз; запросы по одинаковой сумме длин/числу окончаний разделяются даже между разными формами выемки. Строки окончаний в выходной сборке сохраняются разными, геометрия не склеивается по длине. Пустая середина поддержана. Число всех стыков, точность 0,001 мм, остатки и 512 секций учитываются вместе с окончаниями.

Общий численный бюджет по умолчанию 200000 работ включает построение и запросы обеих таблиц. Для запросов резервируется не более четверти бюджета / 4096 работ, чтобы уже подготовленная часть таблицы могла дать варианты при ограничении. Готовые варианты допустимы и при `SearchLimit`; это частичный набор, а не отсутствие сборки. По умолчанию до 8 планов, для ограниченных потребителей допускается 1–32. Представители левого/правого/парного семейства чередуются, несколько вариантов одной стороны не заполняют весь список раньше остальных семейств. Прежний прямой вариант стоит первым, когда он найден. Матрица/автоокно продолжают использовать прежний планировщик.

Первичный `screenTools/selectTools`, быстрый «Подобрать секции» и проверяемый поиск используют этот общий генератор для пуансона. Профиль с достаточной длиной за счёт сапожков допускается к дальнейшей проверке. Ручной выбор профилей и обычный фиксированный маршрут не получают разрешение на скрытую замену инструмента.

В `RouteSearch` до 128 численных планов удерживаются по точному снимку обоих профилей/склада и требуемому охвату; одинаковые запросы разных зон переиспользуют их. Хранятся маленькие сборки и ссылки на уже интернированные снимки, без копий DXF/кадров в ключах. Прежние четыре пары пробуются в прежнем порядке; затем добавляются альтернативные окончания с исходной/подобранной матрицей, максимум 18 различных пар. Все последующие геометрические переходы и атомарный приём D167 прежние.

После прежней попытки исходной общей сборки допускается предпочтительный проход **до четырёх новых общих сборок с окончаниями**. Требуются явный scope всех исходных зон и одинаковые исходные назначения. Существующая подходящая матрица предпочтительна; один состав пуансона не повторяется с несколькими матрицами в этом раннем проходе. Цикл включает полный потенциальный охват совместных зон. Нужна либо текущая сборка с сапожками, либо недостаточная рабочая длина пуансона, либо основание ожидать пользу для доступа. После реальной прежней попытки ориентиром служит `SheetPunch`-отказ текущего checker или его точный компактный отчёт; при отсутствии такой попытки допускается прежний мягкий осевой рейтинг. Это условие ограничивает только раннее предпочтение: обычное семейство отдельных операций остаётся доступным и после других отказов.

Среди новых общих кандидатов `rankToolAccess` мягко предпочитает меньший осевой избыток пуансона. Это не отбрасывание длинной сборки. На каждую пробу до 4n проверок; остаток первой половины общего бюджета распределяется между оставшимися семействами, чтобы левое окончание не израсходовало всё до парного. В сумме предпочтительные проходы ограничены половиной проверок/времени, глобальный бюджет не перезапускается. После неудачи очищаются тупики/путь ограниченного семейства и мягкие предпочтения; точные состояния/вердикты сохраняются.

Для новой общей сборки подготовлены её собственные интернированные входы всех зон. Рейтинг по предыдущим результатам и размещениям использует **эти реальные входы**, а не исходный прямой пуансон. Иначе повторный поиск мог следовать успешным для другого инструмента префиксам и тратить бюджет до подходящей общей сборки. Точный компактный отказ может быть подсказкой порядка проб, но не подменяет актуальную проверку цикла. Размеры LRU не увеличены, нового кэша маршрутов/дискового менеджера нет.

Вырезанные тела, обе ориентации и полный объём отвода — прежний D205; автоалгоритм выбирает существующие формы. Никаких разрешений проигнорировать контакт, короткую кромку, внутренний зазор, V, опоры, упоры/станок/пол, реконструкции или отвод не добавлено. Каталог v6 / проект v19 / VERSION прежние.

Собственная коробка и собственный симметричный широкий профиль подтверждают общий состав из двух сапожков для четырёх операций, когда оставшаяся короткая прямая секция не даёт нужного охвата, а длинная сталкивается. Увеличенная сборка сапожков тоже отклоняется по реальному столкновению: наличие выемки не является разрешением пройти. Этот маршрут проверяет совместный подбор/сохранение состава; влияние конкретной выемки и полного отвода независимо проверяет `cad.horn-tools`. Результаты, ограничение бюджета/области, тёплое повторение, сравнение с полным перебором маленьких складов и регрессии — [development.md](development.md#d207--автоматические-сборки-с-сапожками). Извлечение контактного интервала из Common как новой подсказки не внедрено: существующие осевые позиции D169 сохранены. Полная оптимальность по всем составам/положениям и реальная переналадка по-прежнему не заявлены.

## Ручные крайние окончания — предложение D210

2026-11-07. Пользователь предлагает удобное ручное добавление доступных левого/правого сапожков с автоматическим заполнением остальной длины. Это **предложение интерфейса и ограничения планировщика**, код D207/D209 пока не изменён.

Фактическая основа: `ToolAssemblyDialog` уже позволяет выбрать настроенные окончания в строках и проверяет их крайнее положение, но схема показывает одинаковые прямоугольники. `ToolSelectionWidget::fitAssemblies` сбрасывает состав и берёт `planPunchAssemblies(...).best()`; повторный подбор не закрепляет вручную выбранные окончания.

Предлагаемый первый сценарий — в существующем окне секций пуансона:

- Схема из трёх областей: левое окончание / прямые секции / правое окончание. Два зеркальных переключателя добавляют конкретные настроенные сапожки по внешним краям. Если доступен один вариант, выбор в один клик; при нескольких — короткий список с длиной и параметрами выемки. Неизвестные a/R/h или нулевое наличие не становятся доступным окончанием; путь исправления ведёт в существующую библиотеку.
- Команда «Подобрать середину» сохраняет выбранные окончания и заполняет длину прямыми секциями. В этом ручном режиме выключенная сторона означает отсутствие сапожка с этой стороны. Отдельный прежний полный автоматический подбор продолжает рассматривать все четыре семейства; незакреплённый конец в автоматическом режиме не становится скрытым запретом. Подпись/состояние должны явно различать автоматическую сборку и закреплённые пользователем окончания.
- Весь сапожок участвует в рабочей длине; прямой середины может не быть. Длина окончания не равна a выемки. Показывать требуемую длину гиба и полный собранный размер; избыток длины сам по себе не запрет, но не доказывает проход боковых полок.
- Добавление/снятие окончания сохраняет нетронутые внутренние секции/зазоры; подбор середины — явная замена её состава и стыков. При отказе/отмене прежняя сборка сохраняется полностью. Применение атомарное, каталог/наличие не редактируются, профиль/ручей/матрица не заменяются.

Расчётный путь — тот же ограниченный `planPunchAssemblies`, с явными ограничениями конкретных крайних строк **до генерации и усечения** списка. Нельзя просто отфильтровать первые восемь свободных планов: нужное ручное семейство могло в них не попасть. Прямая середина остаётся общей DP-таблицей, окончания резервируют склад/число секций; учитываются все стыки, включая границы окончаний. Прежние точность/512 секций/200000 работ/типизированный лимит сохраняются. Не заводить второй перебор или новую 3D-геометрию в Qt.

Для повторного подбора по длине выбранные вручную окончания должны передаваться как явные ограничения. Полный поиск обязан различать разрешённые изменения сборки и сохранение ручного назначения по прежнему scope; произвольное снятие окончания ради успеха недопустимо. Владельца такого выбора определять в текущей сессии инструмента/назначения, не в глобальных настройках каталога. Не добавлять поля формата проекта только ради состояния виджета без отдельного обоснования.

Лево/право в редакторе относятся к обычной ориентации пуансона, как D205. Разворот всей сборки учитывает реальное положение выемок. Численная подходящая длина не сертификат гибки: полный checker/покрытие материала/столкновения/упоры/отвод D205/D207 прежние. Нужны собственные тесты закрепления одного/двух окончаний, разных вариантов одной длины, нехватки середины, отсутствующей середины, всех стыков/наличия/отмены и неизменности прежнего автоматического режима; UI только 100%.
