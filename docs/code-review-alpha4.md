# Саморевью alpha.4 и dev-запуск — D185

2026-11-06, локальный Linux/X11, Qt 6.4.2 / OCCT 7.6.3, UI 100%. Проверены startup/F5, границы модулей, контроллер CAD и прогрев, компоновка чертежа, кэши маршрута/геометрии и владение AIS. Это ревью выбранных узлов, а не доказательство отсутствия любых дефектов или утечек во всём приложении.

## Задержка F5

В сохранённом состоянии VS Code выбран именно «Симулятор — Linux (GDB)». Его preLaunchTask использует `dev-app`, тестовые программы перед F5 не собираются. Последний первый запуск дособирал исходники приложения: запись Ninja для EXE заканчивается на 50,667 с от начала сборки, сама линковка заняла 2,357 с. Пользователь подтвердил, что повторный F5 без изменений быстрый.

| Измерение | Время |
| --- | ---: |
| Configure dev | 0,403 с |
| Повторный app-only build до изменений | 0,035–0,036 с |
| Чтение символов GDB | 0,199 с |
| Обычный запуск с личной библиотекой под GDB, до вызова show | 0,900 с |
| Тот же запуск, после show | 0,921 с |
| Адаптер cppdbg из установленного расширения, до show | 1,335 с |
| Повторные app-only build после проверок, без работы Ninja | 0,030–0,033 с |

Первый build после проверок выполнил дополнительную линковку и занял 2,671 с; он не считается проходом без работы. Замеры прогретые, на текущей машине с другими приложениями. Время адаптера измерено через DAP с конфигурацией проекта и breakpoint перед show, не включает весь интерфейс/активацию расширений VS Code. Длительной паузы внутри приложения не воспроизведено; оснований менять Debug на Release, отключать проверки или вводить асинхронную загрузку пустого окна нет.

## Исправленный дефект сборки

`VERSION` читался через `file(STRINGS)`, но не был зарегистрирован входом конфигурации. Изолированная проверка того же фрагмента CMake показала: после изменения VERSION обычный `cmake --build` сохранял старый сгенерированный номер. Явный configure в задаче F5 маскировал этот дефект, чистый CI тоже его не обнаруживал.

В корневой CMakeLists добавлен [CMAKE_CONFIGURE_DEPENDS](https://cmake.org/cmake/help/latest/prop_dir/CMAKE_CONFIGURE_DEPENDS.html) для VERSION. Контрольная проба теперь автоматически перестраивает конфигурацию; файл присутствует и в настоящем Ninja-правиле регенерации dev/core. Реальный VERSION не менялся, приложение сообщает alpha.4. Дополнительных скриптов, флагов компилятора или кэшей не добавлено.

## Результаты чтения кода

- В `ImportController` и `DrawingLayoutController` сохранены один worker, отмена, замена ожидающего запроса, ревизии и join при завершении. Прогрев не публикует отдельный результат; GUI принимает обычный проверенный снимок. `detach`, принудительное завершение потока и вложенное `processEvents` в этих путях не обнаружены.
- Кэш переходов использует полный ключ, list/hash LRU и ограничение ёмкости; промежуточные CAD-состояния ограничены. Кэш компоновки локален одному compose, ограничен 4096 записями и проверяет отмену на попадании. Нового неограниченного кэша кадров не обнаружено.
- `PreviewRigidScene` принадлежит графическому контексту, обновляет положения готовых тел и очищает старые объекты. Нативная регрессия подтверждает переиспользование, режимы, пересоздание контекста и очистку. Boolean/meshing в новый viewer-путь не перенесены.
- Чтение постоянного кэша адресное: startup не перебирает его папку. Ограничение RAM в 64 МиБ относится к сериализованному весу, а не всему RSS OCCT; это уже явно описано в контракте.

Критических нарушений владения или новых обходов проверки геометрии в просмотренных участках не найдено. Динамический анализ всех выделений heap/VRAM не выполнялся; успешные lifecycle-тесты не доказывают полное отсутствие утечек драйвера/SDK.

## Технический долг

- `MainWindow.cpp` вырос примерно до 4500 строк, `ImportController.cpp` — до 1550. Создание виджетов и сборка производного UI-состояния сосредоточены в большом классе; проверка полного маршрута — в длинном callback. Это первые кандидаты для постепенного выделения связных обязанностей при следующем изменении функции. Сам размер файла не доказывает runtime-замедление; массовый рефакторинг сейчас не выполнялся.
- У постоянного кэша нет общей квоты диска — это прежнее ограничение D091. Локально обнаружено 494 файла, суммарно около 79 МиБ; startup их не загружает. Квота/явная очистка могут быть отдельным улучшением без изменения постоянства валидных записей на каждом запуске.
- В ignored `out` около 9,6 ГиБ, в том числе примерно 6800 C/C++ файлов экспериментов и исходников зависимостей. Фактическая индексация этих файлов C/C++ расширением не измерена. Это кандидат для настройки исключений IDE, а не подтверждённая причина задержки; настройки IDE в этом ревью не менялись.

- `git diff --check`, проверка реального Ninja-входа VERSION и версии рабочего EXE прошли.

Артефакты — ignored `out/dev-startup-review/`: замеры, GDB/DAP, изолированная проба CMake, build/CTest/native-логи. SDK, алгоритмы гибки, геометрические ограничения и опубликованный alpha.4 не менялись. Windows/GPU и remote CI заново не запускались. Действует локальный режим D051.
