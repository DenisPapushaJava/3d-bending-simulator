# Windows portable, CI и ручная проверка обновлений — D042

2026-10-27. **CI упрощён; portable-настройки/runtime и обновление приложения ещё в плане.** Пользователь одобрил компактную схему CI с релизами только Windows portable, добавил проверку новой версии, затем уточнил желаемый путь — обновить программу из интерфейса, а не только получить ZIP. Явно исключена фоновая проверка: **только по команде человека**. Частота проверок, таймеры и автопроверка при запуске не нужны. Ниже уточнён предлагаемый первый объём реализации; он не описывает уже существующие кнопки.

## CI и поставка

Один workflow: качество/версия/независимое ядро, Release-сборки и тесты Windows/Linux, черновик релиза по тегу. Linux остаётся средой разработки и проверки; его DEB исключается из автоматической поставки. Релизный комплект — Windows x64 portable ZIP, соответствующие исходники зависимостей и SHA256SUMS.txt. На PR/main тяжёлые архивы исходников зависимостей не готовятся; Qt/OCCT кэшируются. Повторные правки документации пропускают тяжёлые задачи при наличии подтверждения полного CI для неизменных входных файлов сборки. Отпечаток включает код/CI/CMake/SDK/тесты/примеры и режимы файлов; без подтверждения прогон полный. Теги и ручной запуск всегда проверяются полностью. Итоговый check CI работает и при пропуске матрицы; workflow не пропускается целиком. Подробности — в development.md. Графические проверки — только 100%, по D035.

Точная проверка переносимого комплекта нужна при изменении упаковщика; окончательный ZIP распаковывается в другую папку и запускается с очищенным SDK-окружением. Обычный Windows runner уже содержит средства разработки/часть runtime и не доказывает работу на чистом пользовательском ПК. Перед первой публикацией нужен отдельный запуск на реальном Windows/GPU. Тег/VERSION и draft-only процесс D010 сохраняются; опубликованные версии/теги не перезаписываются.

Portable означает запуск из распакованной папки с Qt/OCCT DLL, плагинами, ресурсами и разрешёнными Microsoft runtime-компонентами. Сейчас упаковщик использует `--no-compiler-runtime`; для обещания запуска без отдельной установки runtime его необходимо доработать и проверить состав по Microsoft Redist. Настройки предлагается хранить в `data/settings.ini` рядом с комплектом, отдельно от заменяемых бинарников. Пользовательские каталоги/проекты и личные чертежи не включаются в публичный ZIP. Копирование старых настроек и правила относительных путей должны быть проверены вместе с portable-режимом; ZIP не должен затирать существующий data-файл.

## Путь пользователя

1. **Справка → Проверить обновления…**. Только эта команда запускает запрос версии. Повторное нажатие во время проверки не создаёт второй запрос; окно остаётся отзывчивым, проверку можно отменить.
2. Показать установленную версию и результат: доступная версия/краткие изменения, новая версия не найдена, опубликованных релизов пока нет или проверить не удалось. Сетевую ошибку нельзя показывать как отсутствие обновлений.
3. Если подходящий Windows-комплект доступен, основное действие — **Обновить и перезапустить**. По нажатию программа скачивает пакет во временную папку с прогрессом/отменой, проверяет и подготавливает замену. ZIP остаётся внутренним форматом доставки; пользователь не должен распаковывать его вручную. **Скачать ZIP отдельно…** и страница выпуска — дополнительные действия. Linux-сборка показывает страницу выпуска и явно сообщает, что готовый комплект предназначен для Windows; Windows ZIP не предлагается как Linux-обновление.
4. Скачивание завершается только после проверки размера/контрольной суммы. Начатый файл сохраняется временно и становится итоговым атомарно после успеха; отменённый/повреждённый ZIP не считается готовым. Проекты `.bend`, открытый STEP, задания и CAD-проверки не меняются.

**Нет таймеров, автозапросов на старте, фонового опроса, уведомлений вне ручного диалога и автоматического скачивания.** Это прямое уточнение пользователя, а не настройка с включённым по умолчанию фоновым режимом.

### Применение обновления по ручной команде

По следующему уточнению пользователя целевой сценарий расширен до применения новой версии из программы. **Ручная проверка остаётся ручной; применение выполняет программа после отдельного явного нажатия.** Согласованное отсутствие фонового опроса не запрещает скачивание и применение по этой команде. Предлагаемый механизм, ещё без реализации:

- Пакет полностью проверяется и распаковывается в staging до выхода основного приложения. Ограничить объём распаковки, проверять состав/версию/архитектуру; отклонять выход путей за staging, абсолютные пути и неподдержанные ссылки. Недоступная для записи папка и занятые файлы — понятная ошибка, не частично применённое обновление.
- Перед закрытием использовать обычный сценарий сохранения несохранённого проекта. Cancel/ошибка сохранения отменяют перезапуск; никаких принудительного завершения процесса или потери изменений. Дождаться корректного завершения CAD-worker.
- Небольшой отдельный помощник ожидает завершения основного процесса, затем заменяет **полный набор файлов приложения** согласованной версии и запускает её. Он запускается вне заменяемой папки и не держит её DLL открытыми. В Windows используемые файлы могут препятствовать удалению/замене; выход приложения и ошибки файловых операций должны обрабатываться явно.
- `data`, личные каталоги, `.bend` и STEP исключены из заменяемого набора. Старые файлы приложения сохраняются до успешного применения; при ошибке предусмотрен откат. Защита от одновременного обновления двух экземпляров и восстановление после прерывания обязательны. Детали структуры папок и подтверждения успешного старта выбрать при реализации и проверить на Windows, не называть многофайловую замену целиком атомарной без такого механизма.

Отдельный сервер и второй пользовательский установщик не требуются: в релизе остаётся единый portable-комплект с помощником. Сначала загружается полный комплект одной версии; дифференциальные патчи не нужны для этого пользовательского сценария. Откат и перезапуск — требования планируемого механизма, не уже проверенные гарантии.

## Источник версий и границы интеграции

Использовать опубликованные GitHub Releases публичного `DenisPapushaJava/3d-bending-simulator`, без пользовательского токена и собственного сервера. Не брать номера из ветки main, обычных тегов, CI-артефактов или черновиков. Для публичных релизов GitHub допускает чтение без аутентификации.

`GET /repos/{owner}/{repo}/releases` возвращает выпуски и assets. Нужны tag_name, draft, prerelease, published_at, html_url и для ZIP — name, state, size, browser_download_url, digest при наличии. Пагинацию учитывать явно; неполный просмотр не доказывает отсутствие подходящей версии. `releases/latest` не подходит как единственный источник: он исключает prerelease, а мы выпускаем alpha/beta/rc.

Сравнение по структуре VERSION: год, выпуск, patch, затем alpha < beta < rc < стабильная, числовой номер предварительной версии. Например, alpha.10 новее alpha.2, а стабильная версия новее rc той же линии. Неподдержанный тег не разбирать приблизительно. Предлагаемый выбор каналов: стабильная сборка по умолчанию предлагает стабильные выпуски, предварительная — также предварительные; переключатель предварительных выпусков расположен в ручном диалоге. Никогда не предлагать понижение установленной версии.

Имя Windows asset связывается с точным тегом/версией и архитектурой; ZIP исходников не может быть выбран вместо приложения. SHA256SUMS.txt и runtime ZIP берутся из одного выбранного выпуска; при несовпадении с доступным GitHub digest/размером операция завершается ошибкой. SHA-256 проверяет целостность относительно источника, не является цифровой подписью издателя. Сетевые адреса должны принадлежать ожидаемому репозиторию/службе загрузки GitHub, HTTPS и сертификаты проверяются; нужны лимиты ответа/файла, редиректов и таймаут, обработка rate limit. Эти ошибки показываются только в ручном диалоге и не блокируют офлайн-работу.

По официальной документации `browser_download_url` предназначен для загрузки asset, а бинарный API может ответить данными или перенаправлением. Конкретный список допустимых адресов CDN и сетевых ограничений уточнить при реализации, не разрешать произвольный URL из JSON. CAD-модели и настройки пользователя не отправляются.

## Архитектура и проверка

Предлагается использовать асинхронный Qt Network (`QNetworkAccessManager`), без нового фонового CAD-worker/общего update-фреймворка. Сравнение версий и выбор выпуска — независимые от Qt/OCCT правила; сеть, JSON, файловая запись и отмена — адаптер. Конкретные компоненты создаются в app, UI отображает состояния. Порт/класс вводится вместе с первым работающим потребителем, пустые модули заранее не добавляются. Qt Network и фактический TLS backend должны попасть в реестр/исходники/плагины Windows-поставки; прежний набор DLL Core/Gui/Widgets уже не будет полным.

Тесты реализации: порядок alpha/beta/rc/stable, каналы и запрет downgrade; выбор только нужного Windows ZIP; пустые/черновые/повреждённые ответы; ошибки сети/rate limit/таймаут; отмена и повторная команда; прогресс/неполный файл/ошибка хеша; сохранность проекта/data; отказ сохранения перед выходом; ожидание основного процесса/worker; занятые файлы и права; сбой применения/откат, повторный запуск после прерывания и два экземпляра; **ноль запросов до ручной команды**, включая запуск приложения и истечение времени. Сетевое поведение проверять на локальном управляемом ответе, без живого GitHub в штатном CTest. Реальный выпущенный ZIP проверить отдельно после появления первого опубликованного релиза.

Это подтверждает доступ к списку и отсутствие опубликованного комплекта на момент запроса, **не** загрузку/целостность архива и не работу будущего GUI. Ограничения операций с открытыми файлами проверены по [Microsoft DeleteFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-deletefilew); выбор помощника после выхода — предлагаемое инженерное решение, не проверенный прототип обновления. При фиксации требований сетевой клиент не реализовывался; текущий этап изменяет только CI/его скрипт и документацию. C++/SDK и упаковщик не изменены. Тесты фильтра и обе ОС проверяются отдельно; дополнительных CAD/GPU прогонов локально не требуется.
