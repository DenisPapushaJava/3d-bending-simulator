# Торцевая опора совместной операции — D163

2026-11-05. Продолжение обработки сложных торцов после D162. Исходные зоны и их ID сохраняются. Совместная операция может иметь небольшую потерю опоры у концов **каждого** своего реального участка по общей policy D100. Это геометрический просмотр с предупреждением, не проверка нагрузки или физической устойчивости.

## Геометрия и отчёт

Сохраняется прежнее непрерывное достаточное условие D161 и прежняя сплошная CAD-полоса от касательной до Q. Для каждого реального интервала отдельно:

- обе выделенные полки вычитаются из требуемых полос;
- отсутствующие объёмы должны примыкать ровно к одному концу данного интервала;
- общий непрерывный поддержанный участок содержит его середину;
- потеря на каждом конце не превышает захваченный лимит (по умолчанию 3 мм), с прежним численным запасом;
- внутри найденной центральной полосы повторяются обе полные разности.

Промежуток между отдельными зонами не заполняется и не считается внутренним вырезом. Вырез внутри любого реального интервала остаётся отказом. Большой промежуток не повышает допустимые потери. Полные различия восстановленного тела и независимого предшественника, охват инструмента с промежутками, проверки инструмента/станка/пола/упоров и отвод прежние.

`BendSupportInterval` содержит начало вдоль общей оси операции и локальный `BendEndSupport`. `SingleBendPreview::endSupportIntervals()` публикует отсортированный ограниченный список **всех** проверенных интервалов, включая полные. У одиночного инструментального перехода одна запись. У совместного — по одной на каждую зону, а не одна полоса общей длины. Диагностический безопасный префикс при столкновении сохраняет тот же список.

Контроллер сверяет число записей с числом активных исходных зон, конечность чисел, отсутствие перекрытий, охват общей оси и центральную/торцевую policy каждого участка. Прежняя отдельная проверка полного однократного покрытия исходных ID маршрутом сохраняется. UI читает готовые интервалы, выводит предупреждение и фактические потери каждого неполного участка; CAD в UI/viewer не добавлен. Чертёж, распознавание, быстрый черновик и `.bend` не меняются.

## Кэш и стоимость

Снимки инструмента/ориентации/упора/допуска остаются входами прежнего ключа. В сохранении полного найденного пути исправлено использование группы: накопленная маска и ключ включают **все** её исходные зоны. Групповой preview не должен попадать в ключ одиночного перехода и заменять ранее проверенный одиночный результат. Квоты LRU не меняются; список отчётов ограничен 32 исходными зонами. Нового дискового кэша нет.

Полные старые полосы проходят прежний путь. Только ранее неподдержанная частичная группа продолжает обычную повторную проверку центральной полосы и общий checker. Оптимизация времени поиска этим изменением не заявляется.

## Проверка и оставшиеся задачи

Собственные независимые STEP-фикстуры: два соосных участка с промежутком 20 мм, четыре разных торцевых потери 0,46/1,25/2,5/3 мм; обе ориентации; строгий 0; превышение 3,2 мм; внутренний разрыв; короткий инструмент; реальное столкновение с сохранением двух отчётов; автоматический/заданный порядок; смена допуска и переход группа → одиночные операции в одном кэше.

Общая собственная фикстура составного радиального торца (`CompositeBendFixtures.h`) переиспользуется одиночным и групповым тестами. Осевой контур одинаков через толщину, содержит наклонный и прямой участки; обе цилиндрические поверхности и реальные края сохраняются. Проверяются BRep и объём каждого кадра. Это не добавляет поддержку произвольного сквозного косого среза с разными внутренней и наружной границами: прежние ограничения `mapTrimmedBend` сохраняются.

На частной стойке B04+B05 геометрический маршрут остаётся из четырёх операций. В каноническом состоянии первого совместного гиба, с остальными зонами плоскими, 1063 / 2067-1 V50 возвращает **EndSupportLimitExceeded**: около 28,156892 мм у одного конца, в обеих ориентациях. Ранее группа завершалась общим Unsupported; новый код не превращает это превышение в разрешение. При V35 обе ориентации также отклонены: около 18,063925 мм у одного конца. Более узкий ручей уменьшает требуемую полосу, но не снимает превышение 3 мм. Исходные STEP/BRep неизменны. Частные контуры, STEP, логи и диагностические программы остаются в ignored `out/front-left-rack-support`.

Полный маршрут стойки с инструментом пока не подтверждён. Следующая отдельная задача — доказательство по реальному охвату контакта для подрезанной полки: отсутствие достаточного прямоугольника ещё не доказывает отсутствия контакта. Нельзя автоматически заменить 3 мм найденными 28 мм, заполнить внешний контур или подменить непрерывное доказательство выборкой углов. Распределение поиска между неподтверждёнными инструментальными вариантами также остаётся отдельным блоком D160/D162.

Работа локальная, без push/PR/тега/релиза. Состав и результаты выполненных проверок — в `docs/development.md`.
