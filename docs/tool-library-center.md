# Единый центр библиотеки инструмента

Актуализация 2026-11-06 — **[D205](horn-section-editor.md#реализовано--d205)**: в строках сапожков появилась кнопка «Настроить…», 2D-схема a/R/h, сохранение и ручные сборки с настоящей торцевой геометрией/проверкой полного отвода. Учётные строки без размеров остаются неизвестными. Автоматический подбор сапожков ещё не включён; ниже сохранена история этапов D119/D120/D202/D204.

Дата: 2026-10-31. Основание: пользователь добавил 2067-1 и попросил объединить редактирование, удаление, длины секций и их количество в одном понятном месте. **2026-11-01: первый рабочий блок единого Qt-центра реализован локально — D120; статус и ограничения ниже.** Исходное предложение/макет сохранены как проект развития. D117 (геометрия только из DXF), D051 (локальная разработка) и существующий учёт секций сохраняются.

2026-11-01: [целевая архитектура D119](tool-library-architecture.md) уточняет разделение общего профиля/вариантов/наличия/сборки, роли существующих модулей, переход схем и кэши. D120 отделяет команды мастерской и вводит каталог с архивом v5; расчётная поддержка сапожков остаётся следующим блоком.

## Реализовано локально — D120

На этапе **Инструмент → Библиотека инструмента…** открывается одно окно: слева поиск/тип/список с настоящими миниатюрами и раздел «Удалённые», справа название, контур/рабочий ручей и встроенный редактор длин/количеств/форм секций. Цвета по длине сохранены. Типовые длины и добавление комплектов доступны здесь же, подробные поля профиля свёрнуты. Отдельные постоянные кнопки импорта, секций и старого просмотра сечений убраны. Быстрый picker по картинке продолжает работать; добавление из него открывает импорт внутри этого же центра.

**Добавить DXF / Заменить DXF** используют прежний importer и общий CAD-worker, встраивая его форму в окно. Один локальный DXF можно перетащить на центр; исходник только копируется/читается. При замене показано прежнее сечение, новый профиль проходит прежнюю проверку; сохранение прежнего наличия требует явного включения «Использовать прежние секции этого инструмента». Иначе наличие нового сечения не указано. Незавершённая/ошибочная загрузка не меняет запись, закрытие отменяет запрос.

Название/производитель/номинальная цельная длина и наличие сохраняются кнопкой «Сохранить», а также при переходе на другую карточку/закрытии. Цвет, как прежде, сохраняется отдельно сразу. Некорректные данные/ошибка записи оставляют черновик и прежний сохранённый каталог; уйти с ошибочного черновика можно явным закрытием без сохранения. Ввод количества сам не запускает CAD, сборку секций или поиск маршрута. Сохранение наличия сохраняет выбранный в окне V; разные ручьи показывают общий запас.

**Использовать** — отдельное принятие текущего профиля/ручья в черновик выбора детали. Оно проходит прежние ограничения DXF/минимального V; изменение другого профиля, имени, количества или удаление из мастерской не заменяет текущую пару, её ориентацию и состав, не отзывает готовые кадры. Даже одноимённая изменённая запись не подменяет захваченный снимок. Для работы с обновлённым наличием технолог явно принимает его или запускает подбор по мастерской. Цвет продолжает обновлять готовый кадр без CAD.

Изменение активной мастерской отменяет выполняющийся проверяемый подбор и его сохранённые кандидаты через прежний механизм отмены; ответ по старому наличию не применяется автоматически. Готовый результат захваченной установки сохраняется. No-op/одни цвета/очистка архива не отменяют поиск из-за неизменившегося активного набора. Карточка с сапожками постоянно показывает, что пока это только учётные позиции без расчётной торцевой формы.

Удаление переносит профиль с полным DXF/параметрами/наличием в **«Удалённые»**. Здесь есть восстановление; через «Ещё» — явное окончательное удаление с предупреждением. Архив переживает закрытие окна, новый процесс и обычный перезапуск ОС как часть первичных данных, без TTL/временной папки. Восстановление не увеличивает количество и не создаёт дубликат ID. Сохранённые проекты автономны от обеих операций.

### Хранение и границы первого блока

- `application::ToolLibrary` — единственный владелец изменяемой мастерской/архива, принимает команды upsert/replace/archive/restore/purge и публикует состояние после успешной записи. `ToolLibraryStorage` — стандартный порт read/write без Qt/OCCT. UI и picker получают снимки, а не отдельные конкурирующие писатели.
- `project::readToolLibrary/writeToolLibrary` читают старые каталоги v1–v4 и новый **v5** (`tools` + `archived`), атомарно сохраняют v5 через QSaveFile без direct-write fallback. Общий предел 4 МиБ, максимум 512 активных и 512 удалённых записей; ID уникальны между разделами. `readToolCatalog` возвращает только активные записи и проверяет архив. Старый export-writer v4 остаётся для существующих внешних потребителей/экспорта; редактор использует полный v5-порт.
- QLockFile и SHA-256 **точно прочитанных байтов** защищают запись от конкурирующего писателя. Неактуальная ревизия/повреждённый файл/невозможность записи дают отказ без публикации новых данных. При конфликте нужно перечитать библиотеку новым запуском; автоматического слияния нет.
- Чтение/открытие не переписывают исходник. При первом успешном редактировании каталога старой версии перед переходом на v5 сохраняется побайтовая копия `tool-catalog.json.pre-v5.json`. Ошибка создания копии не разрешает обновление основного файла. Старый клиент v1–v4 не читает v5; копия позволяет восстановить прежний формат при явном откате.
- Пути прежние: `tools/tool-catalog.json` рядом с настройками; Windows portable сохраняет их под data. `.bend` остаётся **v14**, определения/сборки в нём не переписаны. SDK, зависимости, VERSION и геометрический D091-кэш не менялись.
- В первом блоке по-прежнему один `ToolPreset` содержит общий профиль и строки Straight/LeftHorn/RightHorn. Общий неизвестный запас — `segments=null`; при явном учёте количества целые, 0 означает отсутствие. В первоначальном HTML-макете «—» допускался у отдельной строки, а рабочий редактор сохраняет прежнюю строгую семантику учёта целого профиля: незаданное наличие не сериализуется как ноль. Отдельные ревизии/ID геометрических вариантов, несколько разных выемок одинаковой длины, объединение S/M и точные сапожки — последующие блоки D119. Учебные/условные записи не добавлены.

Проверки и платформы: [D120 в development.md](development.md#d120--единый-центр-библиотеки-2026-11-01). Автоматические проверки не редактируют реальный каталог пользователя; native-осмотр частных профилей выполняется в изолированной временной библиотеке.

## Проверка сохранённого 2067-1

Проверен именно снимок, сохранённый приложением в локальном каталоге мастерской, а не только исходный файл в Загрузках.

| Свойство | Результат |
| --- | --- |
| Источник | 2067-1.dxf, единицы мм, 32 ребра |
| Корпус | Один четырёхручьевой профиль, около 60×60 мм |
| Ручьи | V16 / V22 / V35 / V50 |
| Угол | 85° у всех четырёх ручьёв |
| Радиусы плеч из контура | 2 / 2,5 / 3 / 4 мм соответственно |
| Длина инструмента | 835 мм, введённый номинал |
| Наличие | `segments=null`: секции/количество ещё не заполнены |

Отдельный локальный core-probe передал сохранённые положения в `hasCompleteDrawingToolGeometry`, `toolParameters` и `drawingToolGeometry`: все четыре положения распознаны как полный поддержанный DXF-профиль, параметры извлечены. Поворот источника при импорте учтён; отличающиеся от исходного DXF абсолютные углы сами по себе не являются ошибкой. Это проверка записи/извлечения геометрии, а не подтверждение полного цикла, нагрузки или фактических остатков.

Запись корректна для дальнейшей проверки с выбранным пуансоном. 2067-1 и 2030-1 не объединяются: совпадение четырёх V не означает совпадения углов и радиусов. Ссылка на похожий артикул Delem также не делает контуры тождественными.

## Главная единица интерфейса

**Один профиль — одна карточка; доступные длины и количество находятся внутри неё.** Контур поперечного сечения не дублируется для каждой длины. Цельные 835/415 мм и нарезанные секции показаны в одной таблице. Левая/правая концевая секция и прямая секция одинаковой длины остаются разными позициями.

Многоручьевая матрица имеет одно наличие. Кнопки V16/V22/V35/V50 выбирают рабочее положение одного корпуса, не четыре независимых склада. Порядок отображения кнопок не меняет сохранённые индексы ручьёв. Сборка секций на конкретный гиб остаётся отдельной установкой, ссылающейся на неизменяемый снимок профиля/наличия.

ST1405S и ST1405M сейчас существуют отдельными записями. Возможность позже объединить подтверждённо одинаковое сечение и разные длины полезна, но автоматического объединения по названию, похожему контуру или хешу нет. Нужны явная команда, проверка геометрии/посадки/рабочих данных и разбор пересекающихся остатков; количества не суммируются молча. Такой перенос не входит в первый блок.

## Сапожки одной серии: общий профиль, отдельные тела секций

Уточнение [D204](horn-section-editor.md): пользователь просит задавать специальную форму сапожка тремя размерами через 2D-мнемосхему. Для первого ограниченного класса это новый согласованный путь вместо обязательного дополнительного DXF выемки; общий поперечный профиль остаётся DXF. Интерактивный макет подготовлен, фактическая интеграция вариантов ещё не реализована. Ниже сохранён прежний предложенный путь импорта произвольной подготовленной выемки.

Уточнение 2026-11-06: [D202 — сопоставление с MBend, Delem и другими программами](horn-tooling-research.md) подтверждает практическую направленность этого предложения. Учёт LeftHorn/RightHorn по-прежнему не включает расчётную торцевую форму; новый импорт/ручная сборка/поиск ещё не реализованы.

Уточнение пользователя 2026-11-01: левый и правый сапожки находятся в одной карточке серии с прямыми секциями, но должны различаться для правильной проверки столкновений и подбора под соответствующие гибки. **Это принятое требование. Способ задания их дополнительной геометрии ниже — пока предложение.**

В интерфейсе использовать названия «Прямая», «Левый сапожок», «Правый сапожок» с миниатюрой формы. Технические `LeftHorn`/`RightHorn` остаются именами существующих типов. Количество каждого варианта независимо; одинаковая длина не делает прямую секцию и сапожок взаимозаменяемыми. У одной серии могут быть несколько вариантов сапожка одинаковой длины с разными выемками — будущему учёту понадобится идентичность варианта, одного ключа «длина + сторона» недостаточно.

Поперечное сечение серии задаёт общие рабочий профиль и крепление. Особая форма у торца меняется **вдоль длины секции**, поэтому исходный DXF этого сечения и слово «сапожок» не определяют её объём. Производители [Rolleri](https://www.rolleritools.com/information/tips-and-information/special-horns-and-sectionings) и [WILA](https://catalog.wilatooling.com/WILA-Catalog-GB/76/) описывают разные формы торцевых выемок для доступа к возвратным полкам; универсальный вырез из картинки не подтверждён.

Предлагаемое развитие импорта без ручного редактора:

1. Секция наследует проверенный DXF-профиль серии. Для неё задаются длина, сторона и отдельный **подготовленный DXF контура торцевой выемки в продольном виде**. Программа показывает этот вид с привязкой к рабочей кромке/торцу и итоговую 3D-секцию; неоднозначное расположение пользователь уточняет визуально.
2. Для первого ограниченного класса контур выемки прорезает базовую экструзию насквозь поперёк профиля. Это явно заданное построение, а не восстановление произвольного 3D по двум проекциям. Частичные по глубине карманы, сложные пространственные сопряжения и другие формы требуют дополнительных данных/отдельного расширения импорта; их нельзя молча упростить до такого выреза.
3. Правый вариант можно предложить получить зеркалом левого, когда они действительно зеркальны. Это явная операция с предпросмотром; она не создаёт складское наличие и не заменяет проверку реального чертежа. Разворот пуансона вокруг Y и зеркальная форма концевой секции — разные входные данные.

Это предложение согласуется с D117: новый контур берётся из подготовленного DXF, редактирование размеров выемки числами/произвольный 3D-редактор пока не вводятся. Точные размеры сапожков пользователя неизвестны; значения по умолчанию не объявляются реальными. Наличие геометрии также не определяет допустимую нагрузку модифицированной секции.

### Требования к будущему алгоритму

- Сборка хранит конкретные варианты и их порядок: например, левый сапожок → прямые секции → правый сапожок. Для первой модели окончания размещаются на соответствующих концах одной станции; более сложные установки требуют отдельного описания. Лево/право определяются в локальном базисе инструмента и наглядно показаны со стороны оператора. При физическом развороте вся сборка преобразуется согласованно; названия складских вариантов и остатки не переписываются по экранному положению.
- У каждого варианта нужны фактическое тело, рабочая кромка/её осевой диапазон и посадочный участок. Номинальная длина не доказывает полное покрытие/контакт; выемку нельзя заполнять прямой экструзией или считать пустой по одному флажку. Оба окончания/прямые секции/держатели участвуют в общей проверке, контактная подсветка относится к реальной конфликтующей паре.
- Геометрия промежуточной детали и доступ к её согнутым стенкам помогают ранжировать сапожки для углов/возвратных полок. Сама категория детали или тип секции не доказывают пригодность: конкретное положение выемки, покрытие рабочей кромкой, монтаж, прочие ограничения и столкновения проходят общий checker ручного и автоматического перехода. Специального исключения коллизий «потому что это сапожок» нет. Безопасный ручной просмотр сохраняется по прежним правилам.
- Левый и правый варианты не заменяют друг друга автоматически; допустимую замену определяет фактическая физическая установка. Наличие сапожков расширяет кандидатов сборки/порядка, а не вводит правило под одну коробку. Необходимость смены состава между гибами считается переналадкой. Извлечение/перенос не получают сертификат от покадровой проверки гиба.
- Тело/сетка готовятся в CAD-worker один раз и могут входить в постоянный кэш по исходному профилю, контуру выемки, привязкам, длине, варианту/ориентации и версии построителя. Повторное размещение использует готовую геометрию. Viewer не делает Boolean/meshing. Проверка новой детали остаётся обязательной; отводу нужен занятый объём именно фактического тела сапожка, прежний сертификат прямой секции не наследуется.
- До реализации и проверки геометрии/переходов сохраняется нынешнее ограничение D074: сапожки можно учитывать по наличию, но нельзя выдавать их за рассчитанные прямые секции. Геометрия и ревизия вариантов должны переноситься снимком проекта и входить в ключи кэшей, с чтением старых данных без угадывания недостающей формы.

Будущие регрессии: прямая секция сталкивается с возвратной стенкой, подходящий сапожок проходит; слишком малая/не той стороны выемка всё ещё сталкивается; разные выемки одной длины не смешиваются; два разворота восстанавливают сборку; остатки левого/правого независимы; потеря рабочей кромки не считается опорой; изменение выемки отзывает старую проверку/кэш, смена названия — нет. Это критерии последующей реализации, не результаты выполненного 3D-эксперимента.

## Предлагаемое окно

- Слева — поиск, фильтр «Все / Пуансоны / Матрицы», список с миниатюрами **настоящих** профилей.
- Справа — название, крупное сечение, рабочие ручьи и короткая сводка измеренных размеров. Неподдержанный профиль остаётся доступен для просмотра с явным статусом, без возможности выдать его за рабочий инструмент.
- Сразу под сечением — **«Длины и количество»**: длина, форма концевой секции, количество с `− / число / +`, удаление строки. Добавление длины происходит здесь же; типовой набор только добавляет размеры, наличие не выдумывается.
- Название меняется на месте. «Заменить DXF» открывает в этой же правой части загрузку и проверку нового сечения; геометрические размеры вручную не редактируются.
- «Удалить» относится ко всему профилю. Удаление отдельной длины находится в её строке и явно подписано для клавиатуры/подсказки. Нужен возврат удалённого профиля, в том числе после закрытия окна; одноразового сообщения «Отменить» без восстановления недостаточно для рабочего приложения.
- Производитель, источник, примечание и редкие настройки находятся в свёрнутых «Данных профиля». Цвет длины использует существующие общие предпочтения; не становится геометрическим полем или причиной CAD-пересчёта.

Главная точка входа на этапе «Инструмент» — **«Библиотека инструмента»**. Выбор по картинке пуансона/матрицы может по-прежнему открывать быстрый графический выбор; «Управлять библиотекой» ведёт в этот же центр с нужным фильтром/карточкой. Быстрый выбор не превращается в обязательный большой редактор.

Отдельные команды «Секции и наличие», «Профили из чертежей» и добавление DXF из разных меню заменяются входами в соответствующую часть одного окна. Перенос каталога мастерской остаётся редкой операцией в меню этого окна. «Подобрать инструмент» и «Подобрать секции» остаются действиями **для загруженной детали**, рядом с её выбором; библиотека не начинает поиск маршрута при редактировании запасов.

## Сценарии без цепочки диалогов

**Добавление:** DXF-drop/кнопка → проверенное сечение и автоматически определённые параметры → название → длины/наличие в той же карточке. Неоднозначные единицы/контуры требуют выбора по D117; полная геометрия не подменяется параметрами. Отсутствие данных о наличии явно допускается.

**Редактирование:** выбрать профиль → поменять название или строку секции прямо на месте. Для замены DXF показать прежнее и новое сечения/изменившиеся параметры перед явным сохранением. Пока новый DXF не проверен и не принят, рабочая запись остаётся прежней. Сохранение старых секций допустимо только после явного решения пользователя, если замена действительно относится к тому же физическому инструменту; размеры длины не доказывают совместимость сечения.

**Удаление:** удалить профиль из доступной мастерской с возможностью восстановить. Уже открытый и сохранённый проект продолжает содержать свой захваченный инструмент. Его можно показать отдельно как «Снимок проекта» и предложить явно вернуть в библиотеку; он не возвращается автоматически в автоподбор мастерской.

**Назначение:** изменения библиотеки не подменяют незаметно инструмент технолога и кадры текущего проекта. Команда «Использовать» явно принимает новый снимок/выбор по прежнему сценарию. Общая проверка минимального V, секций и геометрии остаётся обязательной независимо от способа выбора.

## Учёт данных и границы первого блока

1. `segments=null` — прежний номинальный инструмент без подтверждённого наличия. Явный нулевой остаток — отсутствие, а не просьба вернуться к номиналу. Макет дополнительно показывает «—» для ещё не заполненной строки; текущий `ToolSegment::quantity` — целое без nullable-состояния. Это состояние черновика нельзя просто сериализовать как ноль или положительный остаток. При реализации отдельно определить хранение незаполненного шаблона и момент явного перехода к учёту; изменение схемы не считается уже согласованным/выполненным.
2. Ограничения существующего учёта сохраняются: длины в мм, число строк/количества и размеры файла ограничены. Некорректная строка не становится частично сохранённой записью. Дубликат «длина + форма» переводит к существующей строке; повторный импорт/шаблон не удваивает запас.
3. Учёт рогов не означает, что алгоритм уже использует их особую геометрию. Прежнее исключение неподдержанных концевых секций из автоматического подбора сохраняется.
4. Метаданные и цвет не отзывают готовую геометрическую проверку. Новое сечение/состав/влияющие установки получают новую ревизию и прежние guards/ключи кэшей; пригодность не наследуется от старого контура. Индексы секций в захваченном проекте нельзя менять сортировкой строк мастерской.
5. Редактор работает с черновиком и существующим атомарным писателем каталога. Ошибка записи/отмена импорта сохраняет прежние данные. Отложенная запись с объединением частых `+` не должна теряться при закрытии. Политику автосохранения и устойчивого восстановления реализовать и проверить вместе, не обещать её по одному HTML-макету.
6. Нужен один владелец редактирования мастерской, а не несколько конкурирующих копий из прежних окон. `MainWindow` передаёт команды/обновления; измерение DXF и подготовка снимков остаются в существующих сервисах. UI не получает SDK-геометрию. Существующий `saveImportedTool` нельзя без анализа привязать к каждому `+`: он также обновляет выбор/составы, что не должно скрыто менять проект.

Рекомендуемый первый блок реализации: единое окно, просмотр/поиск, переименование, редактирование наличия, добавление секции, удаление/восстановление и встроенный существующий DXF-импорт. Следом — управляемое объединение эквивалентных записей и явное «Обычное / Обратное» в этой же карточке по отдельному плану. Редактор произвольного контура, склад станций и резервирование секций этим поручением не добавляются.

## Историческая проверка концепции перед D120

- Локальный JSON прочитан без изменений; core-probe извлёк все четыре рабочих положения 2067-1.
- Интерактивный макет использует снимки восьми реально сохранённых профилей. Правки в нём не пишут каталог и не запускают CAD/поиск. Это проверка предлагаемого сценария, не новая функция Qt-приложения.
- Проверены переключение ручья, добавление длины/количества, переименование, удаление и возврат в макете. Синтаксис JS проверен `node --check`; при ширине 736 и 320 px нет горизонтального переполнения. Проверки повышенного масштаба не проводились.
- Qt/C++/CMake, форматы, VERSION, зависимости и реальная библиотека не менялись; повтор полной сборки и GPU-тестов для этого проектирования не нужен. Windows-интерфейс нового центра пока отсутствует и не проверен.

## D122 — готовность после ввода длин и секций

2026-11-01. Исправлен сценарий DXF → запись для просмотра с нулевой длиной → заполнение секций: прежде `parametersConfirmed=false` сохранялся и после ввода пригодных данных. На пользовательском 1063.dxf прочитаны 23 ребра, в мм построено корректное пробное тело; core определил сечение 26×134,65 мм, 88°/R0,8. В сохранённой записи была длина 0 при наличии прямых секций 835 мм × 3 и других размеров. Причина блокировки — устаревшая готовность, не ошибка этого DXF.

При `ToolLibrary::upsert` повторно проверяются размеры и соответствие рабочего профиля DXF существующему распознаванию: для пуансона носик/угол/R, для матрицы каждое сохранённое рабочее положение V/угла. Если номинальная длина равна нулю, берётся наибольшая длина **прямой секции с положительным количеством**. Это не сумма секций и не габарит поперечного сечения. Заданный положительный номинал не заменяется; нулевые остатки/шаблон и сапожки не дают выдуманной длины или поддержанной геометрии. Секции, количества, порядок ручьёв и контур не меняются. `parametersConfirmed` обозначает подготовленные данные существующей контактной модели, не нагрузку/крепление или пригодность конкретной гибки.

Открытие/закрытие неизменённой карточки не повышает статус и не переписывает каталог. Для уже сохранённой записи достаточно явно нажать **«Сохранить»** в карточке библиотеки, даже без повторного изменения строк. В дальнейшем обычное сохранение длины/наличия выполняет проверку автоматически; CAD/поиск на каждый ввод не запускаются. Неизменённое повторное сохранение не публикует уведомление об изменении мастерской и не отменяет поиск. Ошибка записи не принимает новую готовность. Проектные назначения остаются захваченными снимками; требуется прежнее явное «Использовать».

В палитре вместо общего «Уточните параметры инструмента» указана необходимость длины/сохранения прямых секций либо состояние просмотра с проверкой рабочего профиля. Форматы каталога v5/`.bend` v14, SDK/VERSION и охват столкновений прежние. [Проверки](development.md#d122--готовность-dxf-инструмента-после-заполнения-длин-2026-11-01). Пользовательский каталог проверен на копии в памяти, не перезаписывался; D051/100% сохраняются.

D123, 2026-11-01: [быстрая палитра](graphic-tool-picker.md#библиотека-и-сохранённый-выбор--d123) теперь предлагает только активные записи мастерской. Сохранённый в детали прежний инструмент обозначается подписью и остаётся автономным; его копии больше не выглядят повторными карточками библиотеки. Архив/наличие/проект не переписываются и не объединяются по имени.


## Стартовый комплект — D128

Чистый запуск создаёт [семь реальных профилей](starter-tool-library.md) только при отсутствующем файле мастерской. Имеющиеся/удалённые записи не меняются. Карточка показывает связанные с исходным сечением стартовые длины с прочерками и выключенным учётом; это подсказки, не нулевой склад. Пользователь может сразу выбирать номинальный цельный инструмент, а затем включить «Указать наличие секций» и задать собственные количества. Изменённая геометрия не наследует шаблон по одному имени/артикулу; уже заполненное наличие имеет приоритет. Форматы/редактирование/автосохранение и отдельное применение к детали прежние.
