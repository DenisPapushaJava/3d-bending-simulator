# Размеры во вьюпорте — предложение D189

2026-11-06. **Исследование и предложение, без изменения реализации.** Пользователь
попросил изучить схожие программы и упростить размеры готовой детали и развёртки
в 3D. Действующий контракт остаётся в [model-dimensions.md](model-dimensions.md).

Последующим поручением реализован **первый контекстный этап D190**, только для
вьюпорта: [актуальный контракт](model-dimensions.md). Остальное ниже сохраняет
статус предложения, а описание прежнего кода — исходная точка исследования.

## Причины перегрузки в текущем коде

Проверены `src/viewer/Dimensions.cpp` и `ViewerWidget.cpp`, а также существующие
снимки из ignored `out`. Старые снимки подтверждают характер пересечений,
но не заменяют проверку будущей реализации на актуальном native-вьюпорте.

- Развёртка одновременно получает два габарита, координатные размеры всех линий
  и полные подписи каждого гиба. Даже четыре гиба дают пересечения; число подписей
  растёт с числом зон. Координатные ряды отодвигаются пропорционально габариту
  модели и индексу ряда, без ограничения доступным экраном.
- Проверка разнесения учитывает приближённую ширину по количеству символов,
  а не фактическую метрику шрифта. Проекция приближена базисом камеры;
  границы окна, Qt-контролы и пересечения выносок не участвуют в проверке.
- Все аннотации назначаются в Topmost. Размерные линии могут читаться сквозь
  деталь/оснастку и складываться с видимыми контурами.
- В исходнике выводятся мировые X/Y/Z; в preview — прямые касательные участки
  П1/П2. Это не автоматически подтверждённые наружные размеры полок.
- В preview подписан поворот от плоскости, на развёртке — внутренний угол.
  Подписи объясняют разные величины, но требуют унификации основного чтения.
- `refreshDimensions` удаляет и создаёт AIS-аннотации заново. Потенциал уменьшения
  работы есть, но стоимость этого пути отдельно пока не измерена.

## Предлагаемый сценарий

Сохранить одну кнопку **«Размеры» / Ctrl+D**. При включении автоматически выбирать
состав по текущему контексту, без новой постоянной панели фильтров.

| Контекст | Постоянно при включённом режиме | При выборе |
| --- | --- | --- |
| Готовая деталь | Небольшой набор габаритов в явно определённой системе детали. Пока она не подготовлена — честно подписанные габариты STEP по X/Y/Z. | Выбранный гиб: внутренний угол, R, осевая длина и подтверждённые размеры прилегающих полок. Остальные подробности скрыты. |
| Развёртка | Два габарита заготовки; компактные B-ID у различимых линий. | Одна выноска к линии: ВВЕРХ/ВНИЗ, внутренний угол, R, L; полезная привязка к известной кромке, если такая база подтверждена. |
| Симуляция | Только текущая операция; при воспроизведении минимальное стабильное показание угла. | На паузе — размеры активной операции. Станок/инструмент/коллизии и транспорт остаются читаемыми. |

Толщину достаточно указывать один раз для текущей детали, а не повторять у
каждого гиба. Детали отверстий/вырезов раскрывать по выбору элемента, когда
измерение поддержано; не добавлять все привязки постоянно.

При плотных линиях сокращать также число одновременно видимых B-ID. Выбранный
гиб остаётся доступен через существующий список/ленту и получает выноску.
Для 16–32 гибов отсутствие подписей остальных зон — политика просмотра,
не доказательство их одинаковости. Типовой повтор показывать только после
прежнего геометрического подтверждения D130.

Следующее возможное дополнение — закрепление нескольких выбранных измерений.
Оно не входит в необходимый первый этап: сначала проверить, достаточно ли
контекстного выбора. Закрепление не должно удерживать старое значение после
смены состояния или источника. Постоянный режим «показать всё» пока не нужен.

## Смысл размеров и ориентация

- Основной угол для готового гиба — **внутренний между стенками**. Текущий угол
  движения и целевой угол различать явно; выбор подписи не меняет кинематику.
- Наружный размер до виртуального угла показывать только с подтверждёнными
  CAD-базами D153. Прямой касательный участок нельзя просто переименовать
  в размер полки. Неподдержанное измерение не угадывать.
- Осевой габарит подрезанной зоны, действительная длина участка гиба и общий
  охват совместного хода с промежутками — разные величины.
- Координаты развёртки не являются X заднего упора. Для косой линии координата
  её середины не является кратчайшим расстоянием от края.
- B-ID остаётся идентификатором исходной зоны, номер шага — порядком операции.
  Выбор шага может подсветить несколько исходных зон совместного хода.
- ВВЕРХ/ВНИЗ относится к показанной физической стороне развёртки. A/B не
  переименовываются; смена стороны согласованно отражает геометрию, привязки
  и направления по D144. Предпочтение большинства ВВЕРХ сохраняется.
- Для чтения развёртки предпочтителен вид по нормали. При свободном вращении
  почти ребром подробные размеры скрываются; переход на обратную сторону
  не должен оставлять направления от прежней стороны. Реальное соответствие
  сторон должно быть подготовлено, экранная эвристика его не заменяет.
- Камеру не поворачивать неожиданно при каждом выборе. При неудобном ракурсе
  можно предложить отдельное действие показа профиля выбранного гиба.

## Размещение и производительность

1. CAD-worker готовит измеренные значения, реальные точки/дуги/плоскости и
   стабильные source ID. Viewer проецирует готовые точки и располагает текст;
   пиксельная длина не участвует в измерении детали.
2. Использовать фактическую проекцию камеры и метрику применённого шрифта.
   Выделить доступную область с учётом куба видов, кнопок, ленты/транспорта
   и текущих сообщений. Геометрия/стрелки/текст сохраняют связь с измеряемым.
3. Порядок размещения: выбранное, затем закреплённое (если добавлено), затем
   габариты и остальные маркеры. Ограниченный набор экранных позиций,
   предыдущая удачная позиция первой; штраф за перекрытия и пересечения выносок.
4. Если места нет, скрывать менее важные элементы, оставляя доступ к ним через
   выбор. Шрифт не уменьшать. Изменение чисел не должно постоянно менять сторону
   выноски; около границы видимости нужен гистерезис.
5. Обычные размерные линии тонкие и нейтральные, выбранные — с умеренным акцентом.
   Красный остаётся за коллизиями. Не выводить все линии сквозь всю сцену;
   точную политику глубины текста/линий проверить на реальных ракурсах OCCT.
6. Сначала сократить число показанных элементов. Затем измерить повторное
   использование AIS по стабильным ID против текущего пересоздания. Поворот
   камеры не запускает HLR, развёртку или CAD-проверку видимости каждого текста.

Общими с PDF могут быть только измерения/базы, совпадающие по смыслу, системе
и ревизии источника. Бумажные координаты/масштабы/компоновку во вьюпорт не
переносить; ради размеров не запускать полную подготовку PDF. Новый глобальный
CacheManager/дисковый кэш размещения не требуется. Ориентация чертежа D150 не
меняет машинную систему симуляции или физические стороны детали.

## Предлагаемые этапы и проверка

Первый ограниченный этап: контекстный состав готовой детали/развёртки и выбранный
гиб вместо подписей всех зон; подтвердить внутренние углы и существующий смысл
каждого числа. Далее — экранное размещение и устойчивость при повороте/resize.
Расширение CAD-баз полок и закрепление — отдельные последующие изменения.

Проверять на 100%: уголок, коробка, длинный узкий профиль, неортогональные/разные
радиусы, совместные зоны, 16–32 гиба, отверстия и обратная сторона развёртки.
Сравнить численные значения/базы, пересечения текста/контролов, выбор/камеру,
переходы CAD–flat–preview, Play/Pause и восстановление native-контекста.
Записать время обновления, количество AIS и кадры до/после. PDF, исходная
геометрия, поиск, проверки коллизий и форматы не меняются этим предложением.
