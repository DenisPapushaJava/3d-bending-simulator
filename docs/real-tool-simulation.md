# Реальная форма инструмента в проверке гибки — D068 / G3

2026-10-28. Пользователь поручил проработать использование формы инструмента из чертежа в симуляции: импорт DXF, отображение и столкновения. Это **проект следующей реализации**, не описание уже работающего расчёта. Принято направление полной геометрии инструмента; первая пара и перечисленные ниже интерфейсы/алгоритмы остаются предложением. Действующие [D037](tool-selection.md), [контакт D025](single-bend-tool-motion.md) и [отвод D023](punch-return.md) не расширяются одним наличием контура.

## Результат для пользователя

Инструмент один раз добавляется в библиотеку и настраивается. При работе с деталью пользователь выбирает готовую пару, видит её действительную форму в сцене и запускает обычную «Проверить гибку». Выбор DXF/единиц/баз не повторяется для каждой детали и при каждом Play.

В сцене отображается то же геометрическое тело, которое участвует в проверке. Для неподдержанного контакта доступен просмотр формы, но результат не выглядит как успешная проверка. Текст «По контуру DXF» отличает такой инструмент от явно обозначенного «Условный профиль». Подтверждение формы не подтверждает соответствие реальному станку, допустимую нагрузку или физику материала.

## Что уже имеется

- `core::ToolDrawing`: один замкнутый контур из линий/круговых дуг, источник, SHA-256 и явные единицы. `ToolPreset` хранит длину, справочные размеры и контур; `ToolAssignment` — снимки выбранной пары. Каталог JSON v2 и `.bend` v6 уже переносят эти снимки.
- `tools/import_tool_profiles.py`: ограниченный офлайн-импорт подготовленных ASCII DXF, без Python в runtime приложения. Это не кнопка произвольного DXF в GUI; LWPOLYLINE/INSERT/SPLINE этим кодом не поддержаны.
- В частном каталоге шесть записей с контурами из пяти DXF: ST1405S/M, ST1701S, ST3408S, ST3412S, ST2263. У ST2263 мм уже подтверждены пользователем; длина и рабочие параметры пока неизвестны.
- В прежнем локальном эксперименте пять сечений дали валидные OCCT face/prism. Эксперимент повторять ради изменения плана не требуется; [доказательства и границы](research.md#полученные-локальные-профили-инструмента--2026-10-19). В текущем приложении эти контуры только просматриваются.
- `SingleBendPreviewBuilder` получает `PressTools`, строит условные тела через `simulation::toolProfiles`, проверяет Common/контакты и публикует кадры. Полный контур назначения не доходит до builder. Следовательно, подмена картинки во viewer не изменит проверку.
- Ошибка столкновения сейчас возвращается как `BendPreviewError`; для показа конкретного места понадобится отдельный диагностический снимок, не фиктивный успешный preview.

## Какие практики перенять

В руководстве автора Delem DA‑66T V0716 (ПО 3.3), §10.11, страницы PDF 253–254, описан импорт контуров инструмента/адаптеров/частей станка из DXF: выбор слоёв, распознавание/выбор формы, затем редактор с высотой и монтажными точками. [Источник](https://www.lzkcnc.com/wp-content/uploads/2022/11/DA-66T-V3.3-English1.pdf#page=253). Наличие этой опции на пульте пользователя не установлено. Перенимаем последовательность подготовки библиотеки, не алгоритм Delem или его численные результаты.

[Profile‑T](https://www.delem.com/en/solutions/offline-software/profile-t/profile-t) отдельно заявляет импорт инструмента DXF, конфигурацию и проверку столкновений. [MBend](https://www.metalix.net/product/mbend/) описывает выбор инструмента и динамическую 3D-проверку детали с элементами машины. Это подтверждает продуктовый подход «геометрия + установка + траектория + отчёт», но не раскрывает внутренние алгоритмы коммерческих систем. Программы не запускались и не копировались.

## Добавление инструмента: короткая однократная настройка

Предлагается действие **«Добавить инструмент → Из DXF…»** в библиотеке этапа «Инструмент»:

1. Программа читает документ и предлагает замкнутый профиль; размерные/осевые линии отделены. При нескольких допустимых компонентах пользователь выбирает слой/контур на картинке. Самый большой контур не назначается молча.
2. Показываются единицы и контрольные габариты. Дюймы переводятся явно и один раз; отсутствие единиц требует выбора. Заявленные мм сопоставляются с контрольным размером — единицы DXF сами по себе не доказывают масштаб чертежа.
3. Выбрать «Пуансон»/«Матрица», артикул и **рабочую длину вдоль инструмента**. Длина не берётся из габарита поперечного сечения или общей длины набора секций.
4. На сечении программа предлагает рабочие участки и систему установки. Для пуансона — носик, направление вверх и монтажная база; для матрицы — выбранный ручей, его рабочие плечи и база. Неоднозначные предложения корректируются здесь же. Поворот/зеркало видны в предпросмотре и задают проверяемое преобразование, не меняют исходник.
5. Короткий 3D-предпросмотр → сохранить в библиотеку. Для уже настроенной записи обычный пользователь видит миниатюру, артикул, длину, R/V и возможность проверки. Полный редактор — по «Изменить…», без новых постоянных технических панелей.

Монтажная база и рабочая геометрия хранятся раздельно. Например, габарит ST1405 160 мм не заменяет рабочую H130; у ST1701 — 180 и 150 мм. Для проверки пары относительно листа обязательна рабочая привязка; отсутствие модели реального крепления остаётся явным ограничением охвата.

## Геометрия и область первой поддержки

Для **постоянного поперечного сечения**: аналитический DXF-контур → общие топологические вершины и рёбра → валидная замкнутая грань → экструзия вдоль оси гиба на известную длину → установка в машинной системе X поперёк / Y вверх / Z вдоль. Используется уже подключённый OCCT. Дуги не заменяются грубой ломаной в точной модели; mesh служит для отображения и возможного быстрого отбора кандидатов.

Импорт должен проверять числа/лимиты, плоскость, OCS/extrusion, замыкание, ветвления, дубликаты, самопересечения, допустимую грань, положительный конечный объём и соответствие контрольных размеров. Общая вершина для соседних рёбер строится явно. Нет произвольного healing/масштабирования или удаления неизвестного крупного элемента. Неизвестная геометрия — понятная причина отказа/запрос подготовленного сечения.

Для первого встроенного читателя предлагаются LINE, ARC, простые POLYLINE/LWPOLYLINE с bulge и выбор слоёв. Толщина/ширина полилинии и нестандартная плоскость не игнорируются молча. Чертежи с INSERT/SPLINE, несколькими движущимися телами, разными сечениями по длине требуют следующего расширения. [Спецификация Autodesk LWPOLYLINE](https://help.autodesk.com/cloudhelp/2017/ENU/AutoCAD-DXF/files/GUID-748FC305-F3F2-4F74-825A-61F04D757A50.htm) — первоисточник семантики тегов, не собственный догадочный формат.

Рожковые торцы, наборы сегментов, переменный профиль и подвижные матрицы нельзя представить одной такой экструзией. Для них далее нужны явно размещённые секции/тела и, где применимо, STEP инструмента. Неподдержанное окончание не достраивается равномерным телом без обозначения приближения.

## Контакт и столкновение — две связанные проверки

Простая замена условного корпуса реальным не делает нынешнюю траекторию корректной: она рассчитана для острых симметричных плеч и круглого носика. У реальных ST3408/ST3412 плечи R0,8 и дно R0,5; ST1405 имеет поднутрение R15. Эти факты подтверждены прежним CAD-аудитом и текущим чтением локального каталога.

Первое предложение — ST1405S + ST3412S, обе цельные длины 835 мм. Для пары требуется проверить рабочие привязки, сопоставление S-вариантов с DXF и контакт. Пилотная учебная деталь — одна полная зона, например t=2 мм, с помещающимся носиком и достаточными полками. V12 не назначается автоматически для распространённых пользовательских t=6 мм: нынешняя граница подбора V/t≥5 сохраняется. Это проверка архитектуры на подходящей паре/детали, не универсальный комплект для всего каталога.

Для этой группы развиваем геометрическую модель контакта с явно выбранными прямыми/круговыми участками: касания полок с настоящими скруглёнными плечами и носика с зоной, отсутствие проникновения и достаточная опора по ширине. Если реальные участки/ориентация не поддержаны, допустим просмотр, но не автоматический переход на скрытый клин с зелёным результатом. Это геометрическая модель движения, не FEM и не расчёт фактического радиуса по усилию.

В каждом проверяемом состоянии используются полные тела «лист–пуансон», «лист–матрица», «пуансон–матрица». Законный рабочий контакт не является аварийным столкновением; положительный общий объём проверяется с документированным допуском. Ошибка булевой операции/невалидное тело — «Проверку завершить не удалось», а не «Пересечений нет» и не доказанное столкновение. Конечный зазор измеряется до всей детали, не только зоны сгиба.

Отверстия остаются видимыми; действующий режим D029 продолжает выполнять обусловленные им проверки по отдельной заполненной копии с явной отметкой. Добавление реального инструмента не отменяет это приближение и не возвращает FEM.

### Как показать проблему

Диагностический результат должен сохранять первую **найденную** коллизию, фазу/положение и неподвижный снимок с конфликтующей парой и, по возможности, общей областью. Столкнувшиеся участки выделяются красным, доступен просмотр участка траектории до отказа. Пользователь получает «Полка касается корпуса пуансона при таком положении» вместо одного кода/исчезнувшей сцены. Первая найденная коллизия не называется математически первым временем контакта без отдельной непрерывной проверки.

Без ошибок: «Пересечений не найдено в проверенных положениях» с кратким охватом. Неподдержанная рабочая геометрия: «Форма загружена; контакт этой пары пока не поддержан». Держатели, станина, упоры и извлечение не перечисляются как проверенные, пока их тел/траекторий нет. Это не безусловный вердикт «можно изготовить».

## Движение между кадрами и скорость расчёта

- Подвод/гибка сейчас проверяются в 41 положении. Более частые/адаптивные состояния улучшают поиск, но сами по себе не доказывают безопасность промежутков. Шаг проверки не зависит от ползунка воспроизведения и частоты монитора.
- Непрерывный отвод старого клина строится из предположения монотонной ширины профиля. Для ST1405 с поднутрением оно не выполняется; `makePunch(..., extension)` нельзя использовать как sweep нового тела.
- Для реального профиля требуется самостоятельный проверенный занятый объём вертикального перемещения (объединение всех положений с доказанной конструкцией для линий/дуг). Выпуклая оболочка и объединение только крайних положений не являются точным sweep вогнутого корпуса. Консервативная оболочка допустима для предварительного допуска: свободная оболочка может исключать столкновение, пересёкшаяся требует уточнения и не доказывает аварию.
- До поддержки нового отвода нельзя публиковать старый `PunchRetractionCheck`. Диагностический показ частичных положений допустим как неполная проверка, без обхода текущего допуска к успешному ToolMotion.
- Сначала AABB-отсев, затем существующие OCCT Common/расстояния. Тело/mesh инструмента кэшируются по геометрии, длине и установке; по кадрам меняются преобразования, не пересобирается DXF. Тяжёлый расчёт запускается по «Проверить гибку» в CAD-worker с отменой/ревизией, не на каждую правку.

FCL может стать ускорителем, если измерения покажут необходимость. Его CCD работает с заданными движениями жёстких объектов; деформирующаяся зона листа не становится жёсткой сеткой между двумя позами. Без модели деформации/границ погрешности он не даёт сертификат всей гибки. На первом этапе новой collision-библиотеки не требуется.

## Границы модулей, актуальность и сохранение

- `core`: чистые значения профиля, единиц, привязок/выбранного ручья и состава установки; подтверждённость геометрии отдельно от паспортных параметров. Индексы исходных рёбер привязаны к хешу нормализованного профиля.
- `project`: ограниченный читатель/писатель библиотеки и переносимых снимков; GUI не читает SDK. Окончательное размещение runtime DXF-читателя выбирается при реализации по потребителю, без пустого нового модуля заранее.
- `application`: неизменяемый запрос включает форму **и** установку пары, ожидаемые ревизии, охват и диагностический результат. Передавать в builder только шесть параметров PressTools уже недостаточно; контур не читается из глобальной библиотеки на каждом кадре.
- `simulation`: контакт/закон движения на чистых математических типах; OCCT в него не приходит.
- `cad`: валидация/тела, контакты и пересечения, sweep; `viewer` отображает подготовленные снимки, не выводит форму по имени артикула.
- `ui/app`: однократный импорт/редактор, команды/предпочтения и композиция; один CAD-worker, поздний результат отвергается после смены STEP/цели/инструмента/баз/единиц/длины/секции.

Изменение любой геометрии/ориентации/рабочего участка/размещения инвалидирует связанный результат. Снимок включает нормализованный контур, происхождение/хеш, масштаб, преобразование, длину и рабочие участки. Один ID артикула или путь DXF недостаточен. Редактирование общего каталога не изменяет задним числом сохранённое назначение проекта.

Новое сохранение привязок и режима геометрии, вероятно, потребует следующей версии каталога/`.bend`; окончательная схема вводится вместе с работающим потребителем. Чтение старых проектов сохраняется: их условный режим не повышается автоматически до реального корпуса только потому, что в записи был контур для просмотра. Текущий v6 этим исследованием не меняется. Частные DXF/контуры не публикуются автоматически.

## План одного законченного функционального блока

| Шаг | Результат | Проверка приёмки |
| --- | --- | --- |
| 1. Контур и рабочие базы | Валидное тело/правильная установка пилотной пары из имеющихся профилей; математическая контактная модель для её носика/скруглённых плеч | Независимые размеры/касания, нет подмены H130 полным H160; неподдержанный контакт явно отклонён |
| 2. Проверка и показ | Одинаковые тела в CAD-проверке и 3D; полная траектория либо честный частичный отчёт; показ обнаруженного конфликта | Свободная/сталкивающаяся полка у поднутрения, геометрия с одинаковыми V/R/углами, но разным корпусом даёт разный результат; новый sweep проверен отдельно |
| 3. Обычный импорт | Кнопка DXF, короткий редактор, однократные рабочие привязки, каталог и переносимый проект | LINE/ARC/POLYLINE/LWPOLYLINE, мм/дюймы/нет единиц, несколько контуров/слоёв, обратная дуга, разрыв/самопересечение/неподдержанная сущность; отмена без частичных изменений |
| 4. Регрессия сценария | Новая пара выбирается прежним способом и использует общий проверяющий сервис | Сохранение/чтение прежних форматов, источник отсутствует после сохранения, stale/cancel/close/новая геометрия, воспроизведение без повторного CAD, обычный масштаб 100% |

Это шаги одной осмысленной фичи, не отдельные PR на каждый пункт. После неё: секции/положение по Z, держатели/адаптеры и части станка, затем проверка всей ручной последовательности и более широкий поиск инструмента. Произвольные специальные матрицы и физика не входят в начальный вертикальный блок. Проверки Windows/Linux — по фактическому изменению; удалённый цикл запрещён D051 до команды пользователя.
