# Общая сборка и приоритет доступа — D174

2026-11-05. По поручению пользователя добавлены два независимых оптимизационных приёма поверх прежнего геометрического перехода. Поиск получает первый полный маршрут, стараясь раньше найти вариант без смены секций. Минимум переналадок/поворотов, станция и перенос детали не подтверждены.

## Численный приоритет

После прежней подготовки `SheetLayout`, осей и габаритов полок для каждого гиба собираются осевые интервалы соседних полок, связанных через общую стенку и непараллельный гиб. Используются уже вычисленные коробки, без новых Boolean, meshing или распознавания. Начало интервала согласовано с нормализованной осью: противоположное направление исходного B-ID не меняет смысл диапазона 0…L.

В текущем состоянии учитываются только ещё сформированные соседи. Для пуансона и матрицы оцениваются относительный избыток длины и перекрытие с интервалами этих соседей. Если разрешено прежнее осевое размещение, сравниваются центр и оба края существующего диапазона. Наименьшая оценка — мягкий приоритет доступности, не доказательство существования свободной установки. Ширина/выемка реального DXF, внутренние вырезы и высота опоры этим приближением не сертифицируются. Габаритное перекрытие не является коллизией; отсутствие препятствия в оценке не исключает реального пересечения.

Оценка следует после известных точных результатов/опоры в прежнем рейтинге кандидатов. Она не удаляет гибы/стороны/позиции и не создаёт обязательных предшествований. Поиск идёт назад: сначала пробуется снять гиб с меньшим риском при существующих сформированных соседях. На коробчатой детали это может дать короткие стороны раньше при изготовлении; правила «всегда сначала короткие», имени STEP, четырёх гибов или фиксированного отношения длин нет. Параллельный профиль сохраняет прежний приоритет цепочки; параллельные зоны не объединяются этим рейтингом.

Численная подготовка ограничена прежними 32 зонами, O(n²) записей на worker-запрос; оценка состояния использует небольшие численные списки и стековый массив. Нет отдельного дискового/геометрического кэша, нового CAD в UI/viewer или дублирования кадров.

## Ограниченный проход

Только автоматический запрос с инструментом и явным `assemblySearch` может предварительно попробовать исходную общую сборку. Все снимки назначений должны полностью совпадать, содержать реальные секции/наличие/обе сборки и покрывать длину каждой зоны. Должен быть численный признак риска осевого избытка. Потенциальная совместная группа дополнительно должна помещаться в исходный общий осевой охват с промежутками; это лишь условие запуска, а не подтверждение общего хода. Разные ручные назначения не приводятся к одной сборке.

В этом проходе не вызываются DP/альтернативные сборки/план окна: фиксированы исходные пуансон, матрица, стыки, профиль/ручей, разворот пуансона, станок и упор. Порядок/разрешённые стороны и прежние осевые положения детали выбираются обычным механизмом. Полные тела DXF, реконструкции/канонический предшественник, опора/длины/V, станок/пол/упор, все прежние положения и отвод обязательны.

Локальная квота — min(2n, треть общего лимита проверок), не менее n для запуска. Время — не более половины общего времени от начала текущего `RouteSearch`, проверяется на прежних границах SDK-операций. Отмена и общий лимит имеют приоритет; один вызов SDK может завершиться после границы. Работа первого прохода входит в общие счётчики/время, прогресс не обнуляется. Локальный лимит не превращается в NoRoute.

Если полный путь не найден, очищаются только тупики/незавершённый путь и его ключи/локальный статус этого ограниченного семейства. Исходные входы, точные кэши состояний/успехов/отказов и оставшийся общий бюджет сохраняются для D167/D173. Отказ общей сборки не отклоняет другую сборку/профиль и не становится глобальной невозможностью. Успешный путь публикуется и валидируется прежним механизмом; дополнительные переоснащения вне найденных независимых установок не моделируются.

## Диагностика и проверка

`rankToolAccess` и `preferCommonAssembly` — независимые reference-переключатели запроса, по умолчанию включены; не часть геометрического ключа и не пользовательский параметр `.bend`. В статистике: состояния с ненулевой оценкой доступа, число ограниченных проходов/проб установки и успех такого прохода. Кэш не переносит времена/счётчики прежней работы в текущий запрос.

Контроли используют собственные STEP из разных габаритов, произвольный поворот/перенос и перестановку входного списка. Отдельно проверяется случай, где общая длинная сборка действительно мешает и необходим переход к прежнему семейству, тёплый кэш, малый общий лимит и отмена. Парные измерения на частном кожухе и конечные регрессии — в development.md; экспериментальные программы/снимки склада остаются в ignored `out/rear-cover-order`.

По последовательным Release-замерам 2026-11-05 рейтинг сократил время на кожухе 81,065 → 72,521 с; сочетание — до 71,024 с. В отрицательном контроле рейтинг дал 16,917 → 17,002 с, сочетание — 23,123 с. Это по одному холодному прогону, не гарантия универсального ускорения: неудачный общий проход может дать проигрыш даже с общим кэшем/лимитом. Следующее улучшение — избирательность его запуска, без ослабления checker и без увеличения квот.
