# Проверяемый подбор инструмента — D116

2026-10-31. Реализовано и проверено локально. Пользователь подтвердил основное действие с проверкой полного маршрута, быстрый/ручной обход, отдельные секции и простое окно реального хода расчёта. D051: без push/PR/релиза.

D139, 2026-11-03: в лёгкое предложение и общий поиск добавлен [рейтинг по форме](tool-selection-analysis.md#рейтинг-по-форме-d139). Готовые проекции соседних полок сравниваются с полными рабочими DXF-контурами; очередность вариантов меняется, жёсткий отбор/подтверждение и существующие обходы сохраняются. Снимки массива вариантов не переставляются: выбранный индекс остаётся исходным.

## Причина результата — D160

2026-11-04. Окно использует типизированный ответ worker: `SearchLimit` — «Проверка не завершена» с прежним «Продолжить»; `Unsupported` — «Проверка ограничена»; `NoRoute` — «Проверенный вариант не найден»; ошибка входов/SDK — «Не удалось завершить проверку». `Unsupported` сохраняет неопределённость проверки. Переход между вариантами при неполном ответе описан в D232 ниже.

В окне видны гиб и причина **последней попытки**: опора, длина, столкновение, упор, неподдерживаемый профиль/промежуточная геометрия и другие известные коды. Форматирование общее с панелью маршрута, без второго перевода CAD-ошибок в диалоге. Подробная диагностика упора и обе длины сборки сохраняются. При изменении высоты текста окно вновь центрируется по родителю. Предварительный/ручной выбор, отмена, существующий кэш и принятие назначений не меняются.

На частной стойке 02.07 с 1063 + 2067-1 V50 воспроизведены `Unsupported`, 27 попыток, последняя B03 / `SupportNotProven`. Это свидетельство последней проверенной установки, а не доказательство непригодности V50, всего инструмента или детали.

## Рабочий сценарий

Первый переход к «Инструменту» для новой детали без назначений делает только лёгкое предложение по параметрам и секциям. Видна подпись **«Предварительный подбор»**; полный поиск не запускается, DocumentSession не получает назначений и editRevision не изменяется. Нормальная ориентация определяется общим правилом библиотеки. Сохранённые назначения/ручной черновик сохраняются; повторный вход не подбирает заново. Нет подходящих подтверждённых DXF — пустые карточки с предложением выбрать/добавить инструмент. Учебный клин не возвращается.

Основная **«Подобрать инструмент»** формирует кандидатов из библиотеки мастерской и запускает общий фоновый проверяемый маршрут. Стрелка рядом содержит **«Быстро по параметрам»**, прежнее лёгкое действие. Графический ручной выбор и **«Подобрать секции»** сохраняются. Секции меняют только сборки текущих профилей; наличие не списывается. Быстрое предложение не получает статус геометрически проверенного.

D141, 2026-11-03: окно подбора **модальное относительно главного окна** и при каждом открытии располагается по его центру, в том числе после перемещения родителя. Пока окно открыто, ввод в главное окно заблокирован. `show()` сохраняет асинхронный цикл Qt и работу worker, без вложенного `exec()`. Ход расчёта: «Готовим деталь → Подбираем инструмент → Проверяем гибку», спокойный индикатор без процентов, текущая пара/V и число проверенных установок. Данные приходят от реального worker, не из таймера имитации. Поиск может возвращаться к другому кандидату; общий процент был бы недостоверен. В окне есть отмена/продолжение и меню быстрого/ручного выбора. Принятие успешного результата закрывает окно без дополнительного подтверждения.

Переходы **Другие способы → Быстро по параметрам / Выбрать вручную** доступны внутри модального окна. Они закрывают его и отменяют старое задание; поздний ответ/прогресс не меняют новую установку. После закрытия ввод в главное окно снова доступен, даже пока текущий OCCT-вызов завершается. Отмена/крестик/Esc используют прежний путь отмены, GUI отзывчив. Сам CAD-worker остаётся последовательным: принудительного завершения потока и гарантии мгновенного прерывания внутри SDK нет. Новая геометрическая операция ожидает освобождения worker; это ограничение не скрывается.

## Кандидаты и общий бюджет

Исходный рейтинг `core::selectTools` сохранён: длина, угол, радиус носика, существующий guard **V/t ≥ 5**, предпочтение V около 8t, сборки из доступных секций с заданным зазором. Это продуктовая граница стандартного режима, не норма прочности. Материал/паспорт могут задавать более строгие ограничения; расчёт нагрузки не добавлен.

Проверяемый подбор требует обеих поддержанных DXF-форм. Многоручьевой корпус и инвентарь не размножаются: кандидат содержит исходный groove и полный корпус. Для пары проверяется текущая/обычная ориентация пуансона, затем обратная. Поворот детали остаётся независимым и может выбираться автоматическим порядком. Вариантов в запросе максимум 64; это ограниченный поиск первого проверенного результата, не глобальный оптимум.

Для режима общей пары вариант заменяет инструмент всех операций; для назначений по гибам — только выбранного гиба, остальные назначения сохраняются и должны быть заполнены. Автоматическое смешивание разных профилей/станций для каждого шага пока не реализовано. Такой маршрут можно задать вручную.

У всех вариантов **один** бюджет попыток и времени, максимум 512 проверок и 120 с. Первоначальный подбор с проверкой использует расширенный бюджет. Обычный поиск порядка сохраняет 96 проверок и 60 с.

D232, 2026-11-08. При нескольких вариантах проба получает до одной доли оставшегося бюджета, с делителем до трёх и достаточным числом попыток хотя бы на один ход для каждого гиба, если остаток это позволяет. После лимита пробы или неподдержанной установки по конкретному гибу продолжается проверка с общим остатком. Следующую отличающуюся пару ставят перед очередной ориентацией той же пары. Общие ошибки модели и некорректные входы по-прежнему останавливают поиск. При отсутствии полного маршрута итог сохраняет статус незавершённой проверки; последующий отказ другой пары его не скрывает. Причина последней попытки сохраняется при лимите. Бюджет времени проверяется между CAD-вызовами.

После SearchLimit можно повторно продолжать с готовыми точными переходами, даже если один расширенный запуск уже исчерпан. Кнопка в окне сохраняет режим подбора всей библиотеки или проверки секций выбранной пары. Каждый запуск ограничен 512/120 с и выполняется только по команде. Стек DFS не сериализуется: обход начинается снова с использованием кэша D081/D114. Новые входы получают новый ключ. Повторение не гарантирует маршрут.

## Контракт, ревизии и прогресс

`BendRouteRequest::toolVariants` — явный запрос выбора инструмента. Пустой список сохраняет обычное поведение; ручной порядок его не получает. `RouteToolVariant` содержит автономный ToolAssignment и необязательный индекс заменяемого гиба. `applyRouteToolVariant` не меняет ID, цели, порядок или сторону детали. Малый V проверяется и в CAD-backend, а не только меню.

Backend возвращает выбранный индекс `BendRoute::selectedToolVariant` только вместе с полным маршрутом. Controller сверяет индекс с исходным списком, формирует фактические ожидаемые входы и выполняет прежнюю проверку каждого preview/отвода/станка/пола. Назначения, сборки, стороны и порядок принимаются одной кандидатной DocumentSession к той же ревизии. Неверный индекс, отмена и устаревший ответ ничего не назначают. При переходе к «Гибке» готовый маршрут сохраняется; нижний этап уже показывает готовые шаги.

`BendRouteProgress` — информационные фазы Preparing / ToolCandidate / Checking, индекс варианта/гиба и число проверок. Callback работает на CAD-worker, не входит в ключ геометрии и не является сертификатом. Controller маршалит данные queued-вызовом с защитой routeId/DocumentRevision/EditRevision/stop и ограничением частоты 100 мс внутри одной фазы. Viewer не выполняет вычисления из уведомлений. Форматы `.bend`, SDK зависимостей, VERSION и лицензии не меняются.

## Безопасное ускорение проверки

- Перед Common используются точные геометрические AABB, без триангуляции, с запасом по максимальным допускам всех face/edge/vertex, Precision и fuzzy value. Перекрывающаяся/неизвестная коробка не разрешает пару. На OCCT 7.6 одного AddOptimal(useShapeTolerance=true) недостаточно для теста увеличенного допуска вершины; максимум каждого типа учитывается явно.
- Локальный FIFO-кэш до 128 пар хранит **только уже проверенные свободные пары** оснастки/станка. Общий точно совпадающий ведущий изометрический TopLoc-фактор можно снять у обеих форм: относительная геометрия неизменна. Ключ сверяет TShape, оставшееся расположение, ориентацию и допуск. Ничего не округляется. Любая относительная смена/другая геометрия/допуск дают промах. Пары V2/V3 не исключаются по ID; первая проверка выполняется. Коллизии/их накладки не кэшируются.
- Объём двух неизменных компонентов измеряется один раз; при строго прямой изометрии каждый кадр проверяет сумму этих объёмов и заново измеренного деформируемого сектора. Для другого преобразования остаётся полный расчёт. Копии геометрии/сеток кадров независимы, обе разности принятого перехода сохранены.
- Не строятся две искусственные прямоугольные полки, которые тут же заменялись точными компонентами. Полные кадры/mesh положительного цикла остаются. Для отвергнутой попытки полного маршрута не готовятся неиспользуемые графические пятна/диагностические сетки: численные пары/положение/класс пересечения уже проверены, а маршрут потребляет компактный отказ. Одиночный/ручной просмотр по-прежнему получает весь безопасный префикс и все локальные пятна.

Проверяются прежние 21/61 положения; непрерывный сертификат относится только к вертикальному отводу. Перенос между установками, физика/пружинение/усилие не добавлены. Кэш оснастки D091 независим, нового постоянного кэша детали нет.

## Воспроизведение и измерения

`wall-panel-1000mm.step`, ST1405S + 2030-1/V16, авто-секции L1000, обычное положение по библиотеке (`punchReversed=true`), DemoPressV3 с полом. Linux Debug, Qt6.4/OCCT7.6, один CAD-worker, импорт исключён из таймера buildRoute. Пользовательский каталог только читается локально, его контуры/наличие не публикуются.

До оптимизации: 96/60 с — **67592 мс / 5 циклов**, затем 512/120 с — **127841 мс / 15 циклов** (10 новых + 5 из кэша). Отказов пересечения не было, полного маршрута не хватило на одну операцию. Без инструмента — 16 попыток за 20472 мс.

Один исходный переход: около 13492 мс внутри buildBendOperation, из них 858 мс самопересечения, 3945 мс пары станка, 3725 мс пары инструмента. Внешний одиночный замер до/после — **13991 → 12571 мс**, примерно 10%; это один прогон, не универсальный коэффициент.

После первой оптимизации при прежнем сценарии: 60555 мс / 5 циклов, расширение **126752 мс / все 16** (11 новых + 5 из кэша). Новый связанный подбор через реальный MainWindow/Controller/native GPU: **126027 мс / 11 циклов**, затем по явному «Продолжить» **54584 мс / все 16** (5 новых + 11 из кэша). Controller принял выбранный вариант 0, на каждом шаге подтверждены обе DXF-формы, 61 кадр, DemoPressV3/пол и отвод. Это около трёх минут холодной Debug-проверки; быстродействие остаётся направлением дальнейшей работы. Бюджет контролируется между CAD-вызовами, поэтому последний вызов может закончиться позже 120 с.

Снимки/воспроизводимые локальные утилиты/логи — игнорируемый `out/panel-1000mm`; в исходники не добавлены частные профили. Новых зависимостей/заимствованного кода нет. Дальнейшие ускорения требуют независимой проверки: отложенная подготовка положительных кадров и специализированный доказанный профильный checker не реализованы.

`cad.collision-reuse`: консервативность коробок, увеличенный native-допуск вершины, общий перенос/поворот, изменённые относительное положение/геометрия/ориентация/допуск и совпадающий точный объём найденного пересечения.

`app.checked-tools`: собственные два полных DXF-пуансона (широкий конфликтует, узкий проходит) и DXF-матрица, обе ориентации, полный двухоперационный маршрут и принятие секций; запрет малого V, лимит, неправильный выбранный индекс, модальный реальный прогресс, центрирование/повторное открытие после перемещения родителя, снятие блокировки при закрытии, отмена/поздний ответ, быстрый и ручной обход, независимые секции, лёгкое первоначальное предложение без изменения editRevision и сохранение ручного выбора при возвращении. Обычные сценарии проверяют быстрый путь через QAction `recommendToolsQuick`; основной QPushButton теперь означает проверяемый подбор.
