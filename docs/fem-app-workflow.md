# Исследовательский FEM из приложения

D028, 2026-10-18. Пользователь поручил связать эксперимент D027 с программой и выбрал учебную пластину для первого запуска. Это ограниченная интеграция запуска/результата, не FEM-импорт произвольного STEP. Физическая постановка, материал и численные границы — [D027](fem-bend-hole.md).

## Сценарий

В меню «Исследование → FEM: отверстие в зоне гиба…» доступно отдельное немодальное окно. У диагностики D на вкладке «Сгиб» есть команда «Исследовать отверстие (FEM)…». Основной OCCT-просмотр и проект остаются доступны. Во время расчёта можно работать с другой деталью.

Модель явно задана: пластина **60 × 20 × 1 мм**, V24/R2, пуансон 85°/R2, ход 3 мм, контакт без трения, учебный изотропный материал D027. Выбираются отверстие Ø4 на линии гиба / на расстоянии 6 мм / отсутствие отверстия, крупная/средняя/мелкая сетка и разгрузка. Крупная сетка предназначена для качественного просмотра; выбор одной сетки не устанавливает сходимость. Новые комбинации могут не сойтись — это показывается как отказ, а не запрет изготовления.

Имя текущего CAD-файла, ревизии и выбранная строка B/D захватываются только как локальный текстовый контекст. Ни толщина, ни радиус, ни отверстия CAD не копируются в синтетическую модель. При смене CAD-контекста старый контекст задания остаётся виден с пояснением. Результат не присваивается операции, не меняет `.bend`, не снимает отказ D026 и не подменяет исходную сцену. Ручные параметры инструмента геометрического просмотра тоже не переносятся.

После завершения отображаются сила и угол под нагрузкой, при разгрузке — остаточный угол. Плоская форма = 0°. Кнопки открывают локальную 3D-анимацию в системном браузере и каталог расчёта. Ползунок/воспроизведение/вращение используют сохранённые FEM-поля; WebEngine/новый GUI SDK не добавляются. Изменение параметров отключает открытие прежнего результата в этом окне; его файлы остаются на диске.

## Окружение и поставка

Приложение работает без Docker. Для расчёта нужны локальный Docker Engine либо Docker Desktop с **Linux containers** и заранее подготовленный образ:

```bash
# Из корня исходного репозитория:
docker build -t bending-fem:ubuntu24.04 experiments/bend-hole
# Из каталога share/3d-bending-simulator/fem установленного комплекта:
docker build -t bending-fem:ubuntu24.04 .
```

Окно содержит эти инструкции. Запуск не устанавливает зависимости, не вызывает shell и использует `--pull=never`: отсутствующий Docker/образ даёт диагностическую ошибку. У контейнера нет сети; монтируются только собственные MIT-скрипты для чтения и новый каталог задания для записи. STEP и весь workspace в контейнер не передаются. Запятая в пути bind mount отклоняется явно. На Linux используется UID/GID пользователя. Удалённый Docker daemon для этого сценария не поддерживается.

Собственные Python/HTML/Dockerfile входят в `share/3d-bending-simulator/fem` DEB/ZIP; интерпретатор, Docker, CalculiX, Gmsh, NumPy и Matplotlib **не включены** в комплект приложения. Они остаются отдельным внешним окружением с прежними условиями [лицензий](licensing.md). Новых обязательных библиотек приложения нет. Рецепт D027 фиксирует solver/mesher из Ubuntu; остальной состав образа зависит от Ubuntu-обновлений. Сам запуск FEM на Windows/Docker Desktop требует отдельной проверки; компиляция Windows-интерфейса её не заменяет.

## Архитектура и жизненный цикл

- `application/FemExperiment.h` — чистые C++ DTO и асинхронный порт `FemRunner`: ограниченные параметры, контекст, прогресс, завершение/ошибка/отмена. Qt/OCCT отсутствуют.
- `fem/DockerFemRunner` — реальный адаптер Qt Core/QProcess. Конкретный адаптер создаётся в `app`; `ui` получает только порт. Геометрия/материал/формулы остаются в экспериментальном backend.
- `ui/FemDialog` владеет состоянием окна и поколением запуска. Один активный FEM-процесс, параметры заблокированы на время расчёта; запоздалый ответ старого задания отбрасывается. CAD-worker не используется и не блокируется. Все callbacks и UI-состояние — в GUI-потоке.
- Сначала `docker create`, затем `docker start --attach`. Это позволяет отменить создание, не запуская solver; после завершения/отмены выполняется `docker rm -f`. Отмена считается завершённой после остановки внешней работы; ошибка удаления показывается с именем контейнера и командой ручной очистки. Создание ограничено 30 с, cleanup — 15 с; неподтверждённая остановка остаётся видимой, запрещает новый запуск и требует ручной очистки/перезапуска. Есть общий предел 40 минут; solver D027 имеет собственный предел 1800 с. При закрытии окно ждёт асинхронной остановки; закрытие приложения повторяется после неё. Деструктор имеет ограниченный по времени дополнительный cleanup.
- Каждый UUID-каталог создаётся отдельно под `QStandardPaths::AppLocalDataLocation/fem-runs`. `backend/` сохраняет собственную копию использованных скриптов до запуска; обновление установленного/dev-кода не меняет это задание. `request.json` фиксирует schema/id/параметры/контекст, `bridge.log` — вывод запуска. `gui_job.py` выполняет ограниченную постановку D027 и проверяет поля, завершение, баланс реакций и проникновение записанных узлов. Только затем атомарно публикуется `completion.json`, в котором повторены ID, параметры и SHA-256 исходного request.
- Адаптер проверяет протокол, соответствие входу, наличие анимации и конечные числовые поля; неполное/несовпавшее/отменённое задание не включает кнопки успешного результата. Численные бюджеты D027 не означают физическую валидацию.

Сырые файлы сохраняются локально для проверки и могут занимать десятки мегабайт на запуск. Автоматического удаления истории и сохранения FEM-данных внутрь `.bend` пока нет. Материал по марке, пользовательская развёртка, трение/повреждение, прогноз трещин и отображение полей в основном OCCT-viewer — следующие отдельные задачи.
