# Смена инструмента между этапами: исследование и предложение

2026-11-01. **Исследование и исходное предложение. Первый блок реализован локально в D125**, по последующему поручению пользователя аккуратно исправить поведение. Основание — пользователь замечает разную скорость возврата из «Инструмента» и прежние инструменты на части шагов; предложил рассмотреть правило «0 — вся деталь, 1…N — выбранный гиб». Ниже сохранено исходное исследование; фактические изменения и границы D125 описаны отдельно.

## Что происходит сейчас

- Каталог мастерской, редактируемая пара в `ToolSelectionWidget` и сохранённые назначения `DocumentSession` — разные данные. Редактирование каталога само по себе не заменяет снимки инструмента в детали, согласно D120.
- `MainWindow::setPunchOrientation` на положительном шаге переводит `toolAssignmentScope` в индивидуальный режим. После этого смена профиля на этапе «Инструмент» применяется к выбранному гибу; остальные снимки остаются прежними. При восстановлении документа отличие назначений также включает индивидуальный режим. Разница даже только в ориентации способна изменить дальнейшую область назначения всей пары.
- `commitStageTools` применяет общую пару отдельными вызовами контроллера для каждого включённого гиба. Каждый изменённый вызов отзывает результаты и сообщает `stateChanged`; интерфейс обновляется с промежуточными смешанными назначениями. Есть готовый образец пакетной операции — `setAllBendPunchOrientations`, публикующий одну подготовленную копию сессии.
- `onChanged` выбора инструмента отдельно отзывает маршрут и preview; это вызывает дополнительные обновления. При возврате запрашивается текущая установка, а не обязательный полный поиск порядка.
- D090 сохраняет старое изображение до готовности замены. Это отдельно от назначения старого инструмента другим гибам. Контроллер сверяет job ID, источник, ревизии и запрос; воспроизведённой ошибки приёма устаревшего worker-результата не найдено.
- Первый ручной шаг готовит общее геометрическое основание. Положительный шаг проверяет 21 положение, шаг 0 — одно; одиночный цикл использует прежние 61 положение. RAM LRU хранит четыре ручных результата по полному запросу, поэтому даже изменение другого назначения может лишить текущий шаг попадания в кэш. Постоянный кэш тел инструмента уже существует и не заменяет проверку столкновений с текущей деталью.

## Локальное воспроизведение

Собственный четырёхгибочный tray из test fixtures, поддержанные профили из `ToolFixtures`, отдельные временные настройки, настоящий CAD-builder/контроллер/MainWindow. Проба в ignored `out/tool-stage-audit`, Debug/OCCT 7.6.3, Qt offscreen, масштаб 100%. Это проверка состояния и затрат CAD/GUI, **не GPU-тест и не обещание времени для частных STEP**.

После выбора шага 2 и разворота пуансона область меняется с общей на индивидуальную. Затем выбор другого профиля на этапе «Инструмент» оставляет его только второму гибу из четырёх — симптом воспроизведён. Разворот вызвал восемь `stateChanged`, возврат без изменений — ни одного и без CAD-задания.

В одном запуске новая подготовка положительных шагов заняла 371–525 мс внутри builder, повторный шаг из LRU — менее 1 мс (около 6 мс на действие GUI). Возврат «Инструмент → Гибка» без изменения занял около 4 мс без задания. Это не сравнительный benchmark будущей оптимизации и не ускорение общего поиска.

## Предлагаемый понятный сценарий

1. Перед уходом из «Гибки» запомнить контекст **по ID гиба**, а не по меняющемуся номеру: 0 — вся деталь, 1…N — конкретная операция. При первом входе начать с общего контекста. Над карточками коротко показывать «Вся деталь» или «Гиб 3», оставляя доступное переключение на всю деталь без обязательной модалки.
2. На 0 изменение выбранного поля применяется ко всем включённым гибам, включая их прежние индивидуальные значения этого поля. На 1…N — только выбранному ID. Смена пуансона не заменяет матрицу или разворот детали; отдельный разворот пуансона не должен переключать скрытый режим всей пары. Это предложение о последовательном правиле, а не молчаливое сохранение исключений под подписью «Вся деталь».
3. Прежний набор секций нельзя переносить на другой профиль без проверки. Пересчитать/проверить набор выбранного профиля по действующему явному сценарию, не подменяя ручной выбор автоматическим выбором другой пары. Разворот детали остаётся независимым.
4. Для локального отличия показать небольшую отметку на шаге и действие «Как у всей детали». Редактировать по ID операции: после перестановки ленты назначение следует за гибом, номер обновляется.
5. При возврате без изменения использовать готовый результат. При изменении применить назначение атомарно, снять прежний положительный отчёт и подготовить только текущий шаг. Остальные готовить по запросу, не запускать полный поиск. Сохранять камеру и D090 без новой надписи «Обновление установки…»; ошибка/неактуальность отражается обычным статусом и недоступностью воспроизведения старого результата как нового.

Одна предметная команда с областью «все включённые / ID операции» и изменёнными полями достаточна для первого исправления. Существующие снимки по гибам можно сохранить; новый формат проекта, универсальный фреймворк команд и отдельный постоянный storage общих значений/исключений не требуются заранее.

## Разные наборы и реальные перестановки

Разная форма пуансона, длина набора для ограниченного гиба, ручей/специальная операция могут потребовать разных назначений. Процент таких деталей по текущим данным неизвестен. Само отличие снимков не доказывает необходимость физической смены после каждого гиба: возможно заранее установить несколько станций. В Delem DA-66T описаны станции, выбираемые в процессе гибки, а также пуансон/матрица и разворот в параметрах отдельного гиба. TRUMPF/LVD явно ориентируют оптимизацию на сокращение смен инструмента. [Первоисточники и уровень проверки](research.md#2026-11-01--назначение-инструмента-по-шагам-и-переход-между-этапами).

Для нас разумный приоритет — пригодность общего набора для всей детали, затем исключения при необходимости. Совместные станции по длине станка пока не моделируются: их позиции, соседние препятствия и общий расход секций требуют отдельной реализации. Изменение инструмента между рассчитанными шагами не подтверждает возможность переоснастки, извлечения или переноса детали. При будущих станциях проверять нужно все установленные тела, включая неактивные.

## Порядок будущей оптимизации

Сначала пакетное применение с одним уведомлением/отзывом результатов, устранение дублирующих сбросов и явный контекст вместо скрытого combobox-режима. Затем измерить повторно на собственных fixtures и частных моделях. Разделение кэша физической геометрии/подписей допустимо только с сохранением всех входов проверки: геометрия и префикс детали, цели/толщина, активный ручей/секции/ориентации, станок/пол/допуски и охват. Старый отчёт не выдавать за актуальный из-за похожей картинки. Параллельный доступ к изменяемой OCCT-геометрии и урезание проверки столкновений не предлагаются.


## Реализовано локально — D125

На этапе «Инструмент» один селектор **«Вся деталь / Гиб 1…N»** показывает область редактирования. При входе из «Гибки» шаг 0 выбирает всю деталь, положительный шаг — соответствующий ID операции. Можно явно выбрать другую область без CAD. Перестановка обновляет номер, сохраняя ID. Открытый проект начинает с общего контекста, индивидуальные сохранённые назначения при этом не переписываются.

Валидный черновик принимается при возврате в «Гибку», кнопкой «Применить выбор» либо при переходе к другой области редактирования. Непригодная пара остаётся в прежнем контексте с диагностикой, без частичного назначения. Смена пуансона сохраняет матрицу/её секции и разворот детали. Быстрый подбор и выбор избранной пары явно принимают обе половины пары для выбранной области, включая совпадение с уже показанной парой. Глобальное редактирование переносит изменённые поля; явный выбор профиля в палитре распространяет именно этот профиль даже тогда, когда он уже показан на первом гибе, но отличается у остальных. Набор другого профиля не копируется по совпавшим индексам секций. Явный выбор поддержанного DXF включает его геометрию у затронутых назначений; старый проект не переписывается при одном открытии. Разворот пуансона на 0 сохраняет индивидуальные пары/секции, на положительном шаге меняет один гиб и не переключает область редактора. Удаление назначения использует ту же область.

`DocumentSession::setBendToolAssignments` проверяет пакет целиком: неверный индекс/исключённый гиб/невалидное назначение/несогласованные параметры/повтор индекса отклоняют всё. Изменение принимает один editRevision; no-op не меняет ревизию. Контроллер один раз отзывает результаты/уведомляет GUI, no-op не сообщает лишнее обновление. Формат `.bend` v14 не меняется. Подготовка общих ориентаций сохраняет прежний отдельный D096-контракт.

Полная проверка теперь имеет два охвата: без инструмента и с назначенным инструментом. В последнем случае полный и ручной запросы всегда читают снимок каждого гиба; область редактирования не подменяет их общей парой. Проверяемый подбор сохраняет прежний механизм общей пары либо варианта для выбранного гиба и показывает принятый результат вместо предложения. Неполные назначения по-прежнему блокируют полную проверку; ручное диагностическое отсутствие инструмента не превращается в проверку инструмента.

При первом изменении черновика выполняется один общий отзыв route/draft/preview; последующие изменения до принятия не повторяют этот отзыв. Возврат без изменений сохраняет готовые кадры и не запускает CAD. Новый инструмент отзывает прежний успех и проверяется только на открываемом шаге через существующий worker/checker. Кэши/число кадров/границы коллизий/станок/пол/допуски прежние; перенос и переоснастка между операциями не сертифицируются. D090 сохраняет прежнюю сцену до успешной замены без новой подписи ожидания.

Отдельная сущность общего эталонного назначения и команда «Как у всей детали» пока не добавлены: сохраняются автономные снимки каждого гиба. Несколько одновременно установленных станций и их соседние препятствия также остаются следующим отдельным блоком. Проверки/измерения — в [development](development.md#d125--явная-область-назначения-и-возврат-к-гибке-2026-11-01).
