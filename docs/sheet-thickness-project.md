Исследование D197: [повышенный допуск рёбер и толщина 2 мм у воронки](funnel-model-audit.md). Локальное измерение исправлено D198 ниже; поддержка составных косых торцов/полной развёртки остаётся отдельным следующим блоком.

Актуальный путь UI и формат .bend v4: [D031, автоподготовка и каталог](guided-bend-check-workflow.md#реализация-g1g2--2026-10-18-d031). Описание этапа ниже сохраняет исходный технический контракт; новые зоны используют цель CAD без ручного подтверждения, старые решения сохраняются.


Текущий формат записи — **v3** с назначением инструмента и чтением v1/v2: [начальная установка](press-tool-setup.md). Ниже описан исходный этап; его геометрические ограничения сохраняются.

Дата: 2026-10-18, D018. Это первая реализация M2. Она определяет толщину ограниченного класса плоских тел, позволяет сохранить ручное значение и открыть переносимый проект. Развёртка, материал, инструмент и изготовление не реализованы. Ограниченное локальное распознавание сгибов добавлено отдельным блоком [M2.1](bend-recognition.md). Постоянная толщина геометрии не доказывает, что деталь изготовлена из листа или пригодна для гибки.

## Пользовательский сценарий

1. Открыть STEP через Ctrl+O. Для `tests/data/step/plate-mm.step` или `plate-inch.stp` программа определяет 2 мм. При загрузке поле сразу заполняется найденным значением; если все локальные измерения неподдерживаемой согнутой формы согласованы в пределах допуска, показывается **предполагаемая** толщина, например 6 мм для `angle-6mm.step`. При разных расстояниях, лимите/ошибке анализа или отсутствии данных поле показывает «Не определена»; произвольного значения 2 мм нет.
2. В панели «Параметры» увидеть происхождение значения. Все поверхности, поддерживающие текущее предложенное значение, автоматически подсвечены оранжевыми рёбрами. Можно выбрать отдельную пару в списке; «Показать поверхности» повторяет подсветку и переносит расстояние в поле ввода, без изменения параметра проекта. Подсветка сохраняется при смене камеры и восстановлении native-сцены; новая модель/закрытие её заменяет. Сохранённое ручное значение имеет приоритет над предложением.
3. При необходимости нажать «Применить толщину вручную». Значение проверяется на диапазон и конфликт с подтверждённой толщиной. Для неподдерживаемой формы интерфейс отдельно показывает локальное совпадение либо отсутствие геометрического подтверждения. CAD-тело не перестраивается.
4. Ctrl+S / Ctrl+Shift+S сохраняет проект `.bend`. Ctrl+O открывает STEP или проект. Исходный STEP для повторного открытия проекта не требуется.
5. Ручное изменение помечается `*`; закрытие/замена спрашивает о несохранённых параметрах, с безопасным выбором «Отмена». Можно отменить закрытие, сохранить проект и повторить действие. Автоматически вычисленные свойства не требуют предупреждения о потере ручных данных.

## Границы геометрического анализа — D113

Распознавание выполняется один раз в CAD-worker до публикации и построения сетки, по исходному BRep с отверстиями/карманами. Мировой bounding box, минимальный размер и большинство одинаковых значений не используются как толщина. Анализ гнутых деталей дополнен локальными измерениями; полный сертификат постоянства толщины остаётся отдельным результатом.

1. **Плоские стенки.** Для каждой плоской грани выбираются до трёх строго внутренних точек: центр площади и ограниченная UV-сетка (до 25 кандидатов). Из точки выполняется луч по нормали внутрь металла. Проверяется начальное нахождение в материале и **первый** выход из исходного тела: только противоположная параллельная плоская поверхность даёт измерение. Более ранний выход через кривую поверхность/край не пропускается ради дальнейшей плоскости. Так воздушный зазор между полками не становится толщиной. Общие intersector/classifier подготовлены один раз, полного перебора пар граней больше нет.
2. **Радиусы гибов.** Используется уже завершённый BendAnalysis исходника. Разность наружного/внутреннего радиусов повторно сверяется с реальными цилиндрами по индексам этого же импорта. Незавершённый/ошибочный анализ зон не используется как полный список измерений. Измерение не подтверждает/не включает операцию гибки и не меняет Pending/Excluded. Ссылки заполненной расчётной копии не переносятся на исходник.
3. **Согласование.** Каждая пара хранится один раз с происхождением `PlanarWalls` / `BendRadii`. Если локальные измерения согласованы в допуске, `suggestThickness` автоматически предлагает значение со статусом `Unsupported` (постоянство всей формы не доказано), а ручное совпадение получает `LocalMatch`. При различных значениях возвращается `Ambiguous`: большинство не выбирается, значения не усредняются. Нет данных, ошибка или достигнутый лимит не дают автоматического значения. Ручной ввод остаётся доступен.
4. **Подтверждение плоской детали.** Кандидаты дополнительно проходят прежнее восстановление **всего** тела призмой: площади/объём, валидность, две булевы разности. Только этот результат получает `Detected`, `thicknessMm` и `Verified`; одних лучей/радиусов для этого недостаточно. Проверка включает исходные вырезы/контур и допускает произвольную ориентацию. Глухой карман/ступень не маскируется заполненной копией.

Лимиты: **4096 исходных граней, 512 плоских граней, 1024 луча, 8 реконструкций**. Это границы работы анализатора, не обещание времени и не технологические нормы. При превышении возвращается `LimitReached`, а частичные измерения не становятся автоматическим предложением. Число граней само по себе не доказывает поддержку/неподдержку формы: прежний общий порог 128 снят, работа ограничена по стадиям. Импорт/просмотр сохраняются и при отказе анализа.

Для локального отбора зазор не больше `sqrt(площадь меньшей грани)/5`. Для полного призматического подтверждения обе ширины локального профиля не меньше 5t, а площадь/диагональ не меньше 5t; узкий брусок не становится подтверждённым листом. Допуски локальных расстояний и топологии разделены D198 ниже. Коэффициенты — инженерные ограничения алгоритма, не допуск пресса.

Выборочные лучи не являются доказательством постоянной толщины всей произвольной формы; редкие локальные особенности могут остаться вне выборки, а неподдержанные криволинейные стенки не получают выдуманного значения. Чистые NURBS/конические оболочки без поддержанных измерений могут требовать ручного ввода. Локальное предложение не подтверждает листовую природу всего тела, развёртку, материал или изготовимость. Особенности меньше допуска могут не различаться.

Отмена проверяется между гранями/лучами/операциями, внутренний OCCT-вызов не обещает немедленного прерывания. SDK-данные и вычисления остаются в CAD; UI показывает готовые измерения и их происхождение без пересчёта на ввод. Поле автоматически сохраняет исходную точность, ручное изменение не выдаётся за вычисленное.

## Разделение допусков — D198

2026-11-06. `ThicknessRecognizer` различает:

- **Топологию:** `max(10 × максимальный входной BRep-допуск, 10⁻⁶ мм)`. Прежние классификаторы тела/грани, проверка внутренней точки и бюджет реконструкции используют эту величину. Исходные кривые, поверхности и записанные допуски не меняются.
- **Локальную пару поверхностей:** `max(10 × max(допуск первой грани, допуск второй грани), 10⁻⁶ мм)`. Она задаёт разрешимость зазора (больше 100 таких допусков), сверку аналитического расстояния с пересечением луча и сверку толщины с разностью реальных радиусов. Удалённое неточное ребро не расширяет неопределённость точных аналитических стенок.

Луч рассматривает пересечения начиная с локального отступа от исходной поверхности, в том числе **до** прежней точки внутренней классификации на расстоянии 10 топологических допусков. Если первый выход находится до этой точки, пара не публикуется: нельзя измерить другую стенку за воздушным промежутком. Более ранняя кривая поверхность/край также не пропускается. Дополнительных лучей/булевых операций или перебора всех пар нет; intersector/classifier и прежние лимиты сохраняются.

Уникальные пары хранят свою локальную неопределённость в прежнем ограниченном наборе анализа. Реальное наиболее точное наблюдение становится первым; остальные сравниваются с ним в пределах большей неопределённости **этих двух** наблюдений. Не используется среднее/минимум расстояния или большинство значений. Неточная третья поверхность не скрывает конфликт двух точных измерений. `ThicknessAnalysis::toleranceMm` остаётся консервативной общей границей опубликованных измерений для приложения; CAD хранит отдельные значения только во время анализа.

Конфликт локальных измерений возвращает `Ambiguous` до попытки призматического сертификата: широкий топологический объёмный бюджет не может затереть реально измеренную ступень. Недостаточная разрешимость радиусной пары пропускается как неподдержанное измерение, а неверный индекс/тип поверхности, неконечное или противоречащее радиусам значение по-прежнему дают `Failed`. Ошибки/лимиты/отмена не дают автоматического предложения.

Для `Detected` сохранены более строгие прежние условия: толщина должна также превышать **100 топологических допусков**, проверяются весь исходный контур/вырезы, валидность и обе объёмные разности с прежним бюджетом `max(V×10⁻⁸, площадь×топологический допуск×2)` мм³. Новое разрешимое локальное расстояние само по себе даёт только предложение `Unsupported`; поддержка развёртки/маршрута из него не следует. Формат проекта, worker, UI, распознавание гибов, кэши и проверки изготовления прежние.

## Значение и происхождение

`DocumentMetadata::thickness` хранит вычисленный результат и пары индексов граней текущего импорта. `DocumentSession::manualThicknessMm` — отдельное пользовательское переопределение. Если его нет, применяется вычисленное значение, когда оно определено. Ручной ввод допускается в диапазоне 10⁻⁶…10⁶ мм; конечность обязательна. При подтверждённом результате конфликт больше допуска отклоняется; в остальных случаях локальное совпадение и непроверенное значение различаются.

`suggestThickness` в application возвращает подтверждённое значение либо согласованное локальное предложение только для завершённого анализа неподдерживаемой формы. Оно не меняет статус геометрического распознавания, не создаёт ручное переопределение и не помечает проект изменённым. Если локальные расстояния различаются, программа не выбирает минимальное/первое автоматически. После сброса ручного значения восстанавливаются предложение и его поверхности.

Индексы граней не сохраняются в проект: при новом импорте они могут измениться. Выделение получает ревизию геометрии и игнорируется для другого документа. Редактирование параметра не меняет геометрию; ревизия редактирования отделена от ревизии CAD-снимка.

## Общие поля `.bend` и исходная версия 1

Один JSON-файл UTF-8:

- `format`: `3d-bending-simulator`;
- `version`: исходная версия `1`; актуальное сохранение использует `2`, чтение v1/v2 поддерживается, неизвестная версия отклоняется без изменения текущего проекта;
- `units`: `mm` для ручных параметров;
- `source`: `name` (имя STEP без каталогов), `data` (строгий Base64 исходного файла), `sha256` (контроль целостности исходных байтов);
- `parameters.manualThicknessMm`: число либо `null` для автоматического режима.

Число версии формата не связано с VERSION приложения. [Версия 2](bend-preparation.md) добавляет подтверждения и целевые параметры сгибов, сохраняя общие поля. После открытия v1 следующее сохранение пишет v2. SHA-256 проверяет целостность вложения, не авторство файла. Исходные единицы STEP сохраняются внутри вложенного файла; reader заново нормализует их в мм и выполняет анализ. Результат распознавания и его номера граней не подменяются сохранёнными данными.

Импорт фиксирует исходные байты STEP вместе с геометрией. Сохранение использует этот снимок; изменённый/удалённый файл на диске не подменяет модель. Начальные лимиты: **64 МиБ исходного STEP**, **92 МиБ проекта**. Base64 увеличивает размер примерно на треть; сжатие и отдельный архивный формат пока не нужны. Это стартовые ограничения, а не результат измерений больших деталей.

Адаптер `project::ProjectFiles` использует уже поставляемый Qt Core для JSON, SHA-256 и QSaveFile; новых сторонних зависимостей нет. Он реализует DocumentImporter/ProjectWriter и соединяется с UI только в app. Сохранение выполняется в том же worker, при захваченном неизменяемом документе/параметрах. QSaveFile пишет временный файл рядом с назначением и коммитит его атомарно, без direct-write fallback. Ошибка/отмена не затирает старый проект. Отмена, совпавшая с уже выполненным атомарным коммитом, может оставить сохранённый файл; поздний ответ не привязывает другой или закрытый документ к этому пути.

Успешное сохранение сбрасывает признак изменений только для той же ревизии редактирования и задания. Ошибка чтения/хеша/версии/параметра/презентации сохраняет текущие геометрию, ручные данные и путь проекта. Контроллер дожидается worker при завершении.

## Проверки

Геометрические фикстуры: пластина в мм/дюймах, поворот вне мировых осей, сквозное отверстие, глухой карман, два противоположных глухих кармана с совпадающими предварительными площадями/объёмом, тонкий диск, куб, диагонально заданный узкий брусок, согнутый уголок, отмена перед анализом. Прикладные проверки: диапазон/NaN, конфликт, происхождение и разные ревизии. Файловые проверки: Unicode, изменение исходного STEP после импорта, удаление источника и перенос проекта, повреждённый JSON/Base64/хеш, версия, конфликт параметра и отказ/отмена записи поверх существующего файла.

Qt-сценарий использует настоящие диалоги открытия/сохранения, ручное редактирование, отмену закрытия, повторное открытие и сохранение прежнего состояния при ошибке. Графический вариант дополнительно проверяет автоматическую подсветку актуальных граней, загрузку до показа окна, смену проекции, восстановление native-сцены и игнорирование устаревшей ревизии. Для локальной проверки стороннего согнутого STEP без добавления файла в репозиторий можно задать `BENDING_THICKNESS_STEP` и ожидаемую толщину `BENDING_THICKNESS_MM`; файл используется только этим локальным запуском теста. Управляемый writer проверяет отзывчивость GUI и запоздалый ответ после новой загрузки/закрытия. Конкретные платформы и результаты — [development.md](development.md).

## Первичная форма — D067

После импорта [окно исходных данных](part-input-workflow.md) показывает `manualThicknessMm` либо `suggestThickness` с источником. Без предложения — «Не определена». Принятие неотредактированного автоизмерения сохраняет его исходное число и не создаёт ручной параметр; изменение создаёт ручное значение с прежней проверкой `ThicknessValidation`. «Вернуть измеренную толщину» очищает ручной черновик. Материал/толщина применяются одним `setPartInputs` к ожидаемым ревизиям, отмена не меняет проект.
