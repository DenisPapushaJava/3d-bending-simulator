# Порядок гибов: предложение алгоритма

2026-10-29. Статус: **исследование и предложение**, не реализованный поиск и не утверждённый охват следующего релиза. Основание — поручение пользователя изучить алгоритмы и открытые решения. Действует D051: только локальная работа.

## Что уже есть

В `core::BendSequence` есть перестановка устойчивых ID, но нет расчёта промежуточных форм. D073 строит теоретическую развёртку связного открытого дерева стенок. D074 проверяет выбранный гиб как последний: остальные зоны остаются в форме STEP. D075 добавляет варианты секций. Несколько успешных независимых последних операций ещё не составляют исполнимый маршрут.

## Модель задачи

Порядок — путь через состояния детали. На каждом шаге выбираются зона, сторона подачи/ориентация, пуансон, активный ручей матрицы, состав/положение секций и доступная база. Проверяется вся промежуточная форма.

Первый ограниченный класс предлагается оставить прежним: постоянная толщина, прямые полные цилиндрические зоны и связное открытое дерево стенок; один проход на гиб до целевой формы CAD. Замкнутые связи, предварительные/повторные гибы, подгибка в замок и одновременная обработка нескольких зон требуют другого охвата. Pending/Excluded не активируются поиском. Требуемые, но не включённые зоны отражаются как неполнота результата.

В геометрическом состоянии хранятся базовая стенка и углы всех зон. На границах операций углы в первом классе принимают значения «плоско» либо «цель». Во время движения активный угол меняется непрерывно в принятой кинематике; точность проверки движения сообщается отдельно. Внутренний угол между стенками не подменяется углом поворота от плоскости.

Для открытого дерева заданные углы определяют каноническую форму относительно базы. Маска готовых гибов подходит для кэша такой формы. Она **недостаточна** как полный ключ поиска: текущая оснастка, установка и условия переноса определяют продолжение и стоимость. В более общем классе с предварительными гибами одной маски недостаточно и для формы.

Следует согласовать общий геометрический контракт: D074 сохраняет среднюю поверхность с K=0,5, тогда как технологическая развёртка D073 использует материальный K/BA. Нельзя незаметно принять материальную развёртку за уже проверенную кинематическую заготовку. Совпадение конечной формы, сохранность исходной геометрии и обе полные разности остаются обязательными; физическая калибровка — отдельная задача.

## Проверка перехода

Ручной маршрут и поиск вызывают один механизм перехода, выдающий готовый снимок/диагностику без SDK-типов за границей CAD-адаптера. Для одной попытки:

1. Построить состояние остальных зон, подготовить ориентации и кандидаты оснастки. Для выбранного пользователем комплекта сначала искать порядок на нём; расширение на другие пары — явный режим.
2. Проверить совместимость t/V/угла, длину зоны, имеющиеся секции/промежутки, поддержанный контакт и опоры. Длинный инструмент для свободного короткого гиба допускается; после коллизии одного состава нужно попробовать другие составы/положения в пределах бюджета.
3. Проверить промежуточное движение всей детали: самопересечения, пуансон/матрицу, отвод. Дополнительно необходимы ввод/извлечение и перенос между операциями: свободные отдельные кадры не доказывают связь между ними.
4. При наличии подтверждённых моделей учитывать держатели, станок, рабочий диапазон, упоры и паспортную нагрузку. При отсутствии данных эти пункты получают «не проверено», а не зелёное разрешение на изготовление.
5. Вернуть успех/доказанную коллизию/неподдержанность/ошибку вычисления/отмену с областью проверки. Ошибка Boolean и исчерпанный поиск не превращаются в коллизию.

Отверстия сохраняются видимыми. Согласованное игнорирование физики вырезов и заполненная расчётная копия D029 остаются явно обозначенными и входят в ключ актуальности результата.

## Поиск

Для нашего входа в виде готового STEP предлагается обратный поиск: выбрать возможный последний гиб, построить предыдущее состояние с этой зоной плоской, затем продолжить. Однако переход принимается только после проверки **прямой** операции из предыдущего состояния в следующее, включая установку/извлечение в заявленном охвате. Свободное геометрическое разгибание само по себе этого не доказывает. Найденные операции разворачиваются в прямой порядок и целиком воспроизводятся общим механизмом. Тот же переход должен поддержать ручное построение от плоской формы.

Первый поиск — детерминированный обход с возвратом и отсечениями; далее best-first/A* или ветви и границы через тот же проверяющий сервис. Для A* обоснованная нижняя оценка нужна для обещания оптимума; нулевая допустима, произвольный «удобный» рейтинг такого обещания не даёт. При добавлении одного гиба на шаг уровни образуют ациклический граф состояний, пригодный для DP при корректном определении эквивалентных состояний.

Правила «маленькие полки раньше», «закрывающие гибы позже», «не менять инструмент» ранжируют попытки. Первые два не универсальны и не могут сами по себе запрещать ветку. Зависимости вида B1 до B2 должны иметь проверенное основание либо явное пользовательское происхождение; ограничение только для одной оснастки/состояния нельзя обобщать на все варианты.

Предлагаемый приоритет качества: сначала выполнимость в заявленном охвате, затем меньше перестановок/смен оснастки, затем меньше переворотов и удобство базирования. Первый допустимый результат доступен сразу, улучшение продолжается по команде до лимита. Первоначальные стоимости — условные оценки; время в секундах показывать после настройки скоростей станка/смены оснастки. Цель «минимум гибов» не имеет смысла для фиксированного списка однопроходных операций.

Нужны лимит времени, числа геометрических проверок и памяти, отмена и сохранение лучшего полного решения. Исходы: найден маршрут с указанным охватом; найден с непроверенными условиями; лимит исчерпан; вариантов нет в полностью просмотренном ограниченном пространстве; неподдержанная геометрия/ошибка. Последние исходы не доказывают общую невозможность изготовления.

## Быстродействие и владение

Распознать/разделить стенки и зоны один раз; кэшировать канонические состояния и проверки переходов. Ключ включает геометрию/задания, углы, инструмент/ручей/секции/зазоры/положение, геометрию станка, режим вырезов, допуски и версию алгоритма. Последняя установка/положение нужны там, где проверяется перенос. Слияние одинаковых масок без этих условий теряет полезные пути.

Сначала дешёвые ограничения и консервативные габариты, затем детальная геометрия. Пересечение габаритов ещё не коллизия; неопределённая сеточная оценка передаётся точной проверке. Кадры для GUI готовятся выбранному пути, не всем веткам. Первый вариант можно построить на имеющихся C++/OCCT; FCL рассматривать после профилирования, без новой зависимости ради одного поиска.

Поиск работает в фоне со снимком входов, отменой и проверкой ревизии перед принятием. Камера/просмотр готовых кадров не меняют входы; изменение материала/задания/инструмента/станка инвалидирует затронутые результаты. Перестановка ручного маршрута инвалидирует изменённый участок и его продолжение. Прежние владельцы GUI и CAD-worker сохраняются; новый planning-модуль появляется с рабочим потребителем, не заранее.

## Предлагаемые функциональные блоки

1. **Проверяемый ручной маршрут.** Общая модель нескольких промежуточных состояний и установок; последовательность из 2–5 гибов; остановка на первой проблемной операции, прямое воспроизведение, сохранение проекта. Первый поддержанный вариант извлечения задать и проверить явно либо сообщить его отсутствие. Обязательные примеры — П/Z, лоток с разными направлениями, дочерняя полка, случаи столкновения/запирания.
2. **Подсказки и поиск на выбранной оснастке.** Возможные следующие/последние операции с причинами; ограниченный поиск полного порядка, прогресс/отмена и сохранение ручных фиксаций. Отдельно показать, если найден лишь допустимый следующий шаг, а полный путь ещё не найден.
3. **Совместный выбор порядка и оснастки.** Альтернативные пары/составы/положения секций и их смены; рабочий диапазон и геометрия станка/упоров, затем расширение контактов и технологическая нагрузка.

Сохранить три основных этапа UI. На «Проверка» — «Подобрать порядок», компактная лента операций и ручная перестановка; в подробностях — ограничения, альтернативы и причина отказа. Автоматический тяжёлый поиск на каждую правку не запускать. Сценарий и конкретные пределы предстоит согласовать реализацией; предложенные пункты пока не добавляют возможности приложению.
