# Ручной порядок и проверка столкновений — D082

D125: инструмент каждого ручного шага читается из сохранённого назначения операции; область редактора «Вся деталь / Гиб N» не подменяет пары в запросе. Разворот пуансона больше не переключает скрытый режим назначения. [Переход между этапами и пакетное применение](tool-stage-transition-proposal.md#реализовано-локально--d125).

D239: при нехватке длины Play и ползунок доступны на выбранном ручном гибе с предупреждением. Коллизии останавливают движение, автоматическая цепочка прерывается. [Поведение](bend-messages.md#диагностический-просмотр-выбранного-гиба--d239).

D104/D105: реализован [независимый разворот детали](workpiece-orientation.md) с сохранением установки по ID, совпадением с полным маршрутом и RAM-кэшем четырёх сочетаний. Шаг 0 меняет только первую установку детали; прежнее общее правило пуансона D096 сохраняется. Формат проекта — v14 с чтением v1–v13.


D101: поддержаны [составные торцы](composite-bend-ends.md) с проверенной радиальной реконструкцией; реальная подрезка сохраняется в материале всех кадров. Старое ограничение полных прямоугольных зон для этого класса уточнено.

Уточнение D099, 2026-10-30: [локальные пятна коллизий и остановка](collision-highlighting.md) заменяют прежнее окрашивание целых тел. В текущем положении подсвечиваются все найденные пары/раздельные участки; неуспешный полный цикл может сохранить безопасные кадры до первого конфликтного. Он остаётся ошибкой без сертификата отвода. Численный охват проверок прежний.

D093, 2026-10-30: активный инструмент ручного шага, включая шаг 0, проходит общий запрет `V/t < 5` до построения/чтения кэша. Старое назначение/ручные параметры не обходят его. При отказе новая установка не публикуется; геометрический просмотр без инструмента не становится проверкой такого назначения. [Контекст малого V и будущего радиуса по инструменту](tool-dependent-bend-radius-proposal.md).

2026-10-29. Реализовано локально по поручению пользователя. Уточнение в ходе работы: разрешено отказаться от автоматического поиска порядка, **но столкновения детали с инструментом отслеживаются всегда**. Это заменяет предложение о просмотре без проверки пересечений; [исходное обсуждение](manual-route-preview-proposal.md) сохранено как история. D051/100% действуют.

## Работа пользователя

На этапе **Проверка** нажать 0 либо номер гиба. Первый запрос однократно готовит геометрическое основание; дальше каждый выбранный шаг строится без DFS и полного расчёта остальных операций. Если назначен инструмент, его фактические поддержанные корпуса и секции показаны и проверяются на пересечения. Неполное назначение позволяет осматривать деталь, но явно сообщает, что инструмент отсутствует и столкновения не проверены. Произвольная неподдержанная STEP-геометрия не получает фиктивную развёртку.

- **0** — полностью разогнутая геометрическая заготовка, один неподвижный кадр. Переставить/удалить её нельзя. D096: переключение ориентации пуансона здесь применяется ко всем включённым гибам с инструментом, с сохранением индивидуальных профилей/матриц/секций. На шагах 1…N тот же переключатель меняет только выбранный гиб. [Подробности](punch-installation.md#разворот-пуансона-вся-деталь-и-отдельный-гиб).
- **k>0** — форма после первых k гибов текущего порядка. Нажатие номера ставит конец выбранной операции; тот же смысл применяется и к ленте полного проверенного маршрута.
- Выбранная зона подсвечена оранжевым в текущем положении; наведение на номер временно выделяет её в подготовленном ручном виде. Исходные индексы STEP-граней на изменённую форму не переносятся.
- Ползунок/Play показывают 21 положение выбранной гибки. Play из конечного кадра начинает эту операцию заново; из 0 начинает первую. После завершения может перейти к следующей операции, отдельно дожидаясь её подготовки/проверки. Вращение камеры и скорость 1×–10× остаются прежними. Пересечение показывается красным, возможность редактировать порядок сохраняется.
- Для одного гиба прежний одиночный сценарий сохраняется; новая лента, как D076, предназначена для нескольких зон.

GUI ручного просмотра всегда запрашивает проверку назначенного инструмента. Переключатель **охвата полной проверки** не отключает её. Самостоятельный прежний просмотр без инструмента скрыт, пока открыт ручной маршрут. Внутренний запрос без инструмента остаётся для диагностического сравнения геометрии, а не как переключатель исключения столкновений в ручном сценарии.

## Перестановка

Перетаскивание **вставляет** операцию между соседними позициями. Маркер показывает место вставки. Проект изменяется только после принятого drop, не при каждом движении мыши. Перетаскивание 0/чужого объекта/файла не становится перестановкой; обычное открытие файлов D040 сохраняет собственный сценарий. Escape/отмена не меняют порядок. Длинная лента прокручивается, у края предусмотрена прокрутка при drag.

Например, `A B C D` → перенос D перед B → `A D B C`. На кнопках остаются **1 2 3 4**: номер обозначает текущую позицию, а не ID. Выбранным остаётся D, теперь шаг 2. Его угол, радиус, профиль, ручей, секции и прочие назначения не переходят к другой зоне.

«Раньше / Позже» используют ту же предметную операцию `BendSequence::move`. Доступны кнопки отмены/повтора и Ctrl+Z/Ctrl+Shift+Z при фокусе в ленте. История до 50 перестановок относится к текущему импортированному документу, не является общим Undo параметров и очищается при новом документе. Смена порядка сразу отзывает отчёт полного маршрута и готовит только выбранный префикс. Главная команда в ручном сценарии называется **Проверить мой порядок** и не запускает автоматическую перестановку. Возврат к исходнику или открытие редактора инструмента не сбрасывают это намерение; автоматический подбор выбирается отдельной командой, новый документ начинает обычный сценарий.

## Геометрия без поиска порядка

Поддержанный класс D076 не расширен: открытое дерево постоянной толщины, все 1–32 распознанных полных прямых зон, цели/толщина согласованы с CAD. Pending/Excluded/непривязанные решения не активируются автоматически. Кинематическое основание использует **K=0,5**, не материальную развёртку для раскроя/PDF.

`FlatPatternBuilder` после прежней проверки полного восстановления STEP сохраняет дерево стенок, зоны, преобразования в плоскость и частичную кинематику. Общий `routePlacement` применяется точным и ручным путём: перемещается вся зависимая ветвь. Формулы секции и размещения над матрицей общие с `simulation::singleBendSection/mapBendPoint` и геометрией `PressMotion`; в UI нет второй реализации деформации.

У ручного пути нет перебора кандидатов/сторон, слияния всех стенок `Fuse` и повторного распознавания зон каждого префикса. Материал собирается из точных отдельных стенок/секторов. Активный сектор перестраивается по общей кинематике. Начальная проверка основания STEP, построение тел инструмента и пересечения сохраняются; термин «быстрый» не означает отсутствие CAD-вычислений или гарантированное время на любой детали.

Исходная кожа с отверстиями/открытым контуром триангулируется и классифицируется по неизменным компонентам один раз. Для кадра преобразуются вершины с проверкой согласованности на общих границах. Нельзя заполнять внешний контур или терять исходные вырезы ради скорости. В D029 столкновения относятся к материалу отдельной заполненной копии; видимые отверстия не обещают реальную опору/физику вырезов.

Положение относительно инструмента задаётся выбранной зоной и её собственной оснасткой. Поддержанные DXF, активный ручей, реальные секции/зазоры и независимые длины пуансона/матрицы сохраняются. Отсутствующий/непригодный для построения профиль не заменяется незаметно клином. Условный инструмент остаётся условным. Короткий инструмент не блокирует редактирование/диагностический просмотр; D126 выводит [постоянное численное предупреждение](bend-messages.md) в панели инструмента и сцене, включая столкновение. Результат содержит раздельные фактические длины пуансона/матрицы; полного подтверждения гибки нет. Опора и контакт на плечах этим не сертифицируются.

## Пересечения и предел результата

При заданном инструменте **каждый публикуемый кадр** проверяет всю деталь против пуансона/матрицы и пуансон против матрицы. Сначала консервативный AABB с допуском исключает заведомо разделённые пары; оставшиеся проходят неразрушающий `BRepAlgoAPI_Common` и проверку занятого объёма. Обычное касание границ не считается объёмной коллизией. Ошибка Boolean/невалидный результат/нечисловой объём дают ошибку подготовки, а не пометку «пересечений нет».

`checkedToolPositions` должен равняться числу опубликованных кадров, если есть показанная оснастка. Флаг конфликтующей пары хранится **для каждого кадра** и управляет красным выделением/сводкой. Нельзя считать весь шаг свободным только по конечному кадру или габаритам. У уже проверенного неизменного кадра переключение слайдера/hover не повторяет CAD-проверку.

Сводка говорит только «В этом положении пересечений с инструментом не найдено» либо «Столкновение». Она не подтверждает весь порядок, сплошную опору, ввод/извлечение/перенос, отвод, станок/держатели, усилие или физику. Интервалы между 21 положением не охвачены непрерывно. Это формирование одной независимой установки без фаз подвода/возврата, а не прежний проверенный цикл 61 положения. Для полного существующего охвата служит отдельная команда проверки D076/D077/D081.

## Владение, кэш и актуальность

D158: при воспроизведении UI заранее [прогревает следующий шаг](draft-prefetch.md) в том же ограниченном CAD-кэше. Предподготовка не публикует результат, не блокирует GUI и не отключает проверки. При выборе готового/ещё готовящегося шага используется прежний foreground-приём; одна совпавшая работа не отменяется ради повторного расчёта. Пауза и новые входы отменяют ненужную спекуляцию, пересечения/D127 остаются обязательными.

`RouteDraftRequest/RouteDraftResult` — отдельный контракт стандартных типов application. Результат не является `BendRoute`. Его графические кадры используют общий формат `SingleBendPreview`, но имеют обязательный `unverifiedDraft`; контроллеры точного маршрута и одиночной операции **отвергают** такой кадр как результат проверки. Принимая ручной результат, контроллер сверяет показанные параметры и признаки DXF с назначением выбранной операции. Сертификата отвода/PressMotion у него нет. Нативные данные остаются внутри CAD; viewer только отображает подготовленные снимки.

Адаптер использует рабочий набор D081 последнего неизменного DocumentPtr/ручной толщины: общая геометрическая развёртка, одно классифицированное основание и до **4** последних ручных результатов LRU. Ключ результата — полный запрос: весь порядок ID/индексов/целей/назначений, выбранный шаг, охват и толщина. Новый угол/контур/ручей/состав/зазор не наследует старую проверку. Это ограничение числа объектов, а не фиксированной RAM. На диск кэш не пишется.

Один существующий CAD-worker исполняет запросы последовательно. Во время ручной подготовки разрешены выбор/перестановка; новый запрос отменяет старый и заменяет единственный ожидающий. ID задания, DocumentRevision/EditRevision, сам источник и stop-token защищают приём. По D090 прежнее положение остаётся в сцене до приёма замены без новой подписи ожидания; обычная правая сводка показывает состояние проверки/ошибку. Старое изображение нельзя объявлять новым результатом. Повторный выбор текущего готового запроса использует его непосредственно, без постановки CAD-задания; камера сохраняется между установками в той же системе координат. [Подробности](punch-installation.md#обновление-установки-в-той-же-сцене--d090). Закрытие/отмена/новый импорт сохраняют прежнюю инвалидизацию. Просмотр не меняет геометрию/байты исходного документа и не выполняет автоматический поиск.

Порядок и инструменты сохраняются прежними полями `.bend` v10/каталога v4. Кадры, история Undo и положительные проверки не сериализуются. VERSION/SDK/внешние зависимости не менялись; Windows/GPU требует отдельной проверки.

Проверки и ограничения экспериментов — в [разработке](development.md) и [журнале исследования](research.md).
