# Замеры постоянного кэша оснастки — D091

2026-10-30, Linux, dev/Debug, системные OCCT 7.6.3 и Qt 6.4. Сравнивается одна и та же финальная реализация с включённым/выключенным кэшем. Три последовательных отдельных запуска `tool_geometry_cache_tests --benchmark`, без параллельных сборок/CTest/native UI. Это небольшой воспроизводимый эксперимент, не гарантия времени на любой детали/ПК.

## Методика

Оснастка: наша синтетическая пара с хвостовиком, 6 секций каждого инструмента (200/100/50/40/20/10 мм), зазор 1 мм, длина набора 425 мм, DemoPressV2. Каждый замер выполняет четыре подготовки в обычной/развёрнутой ориентации, включая построение/выбор частей станка, метаданные секций и контрольный объём. «Первое заполнение» включает запись новых артефактов и повторное использование между этими четырьмя запросами. Новый процесс действительно запускается через QProcess, в нём нет объектов прежнего RAM-кэша; время самого запуска EXE в замер подготовки не входит. Файлы ОС могут находиться в page cache. Это не измерение холодного диска сразу после перезагрузки ПК.

Полный цикл: наша STEP-пластина, Ri=2, t=2, 90°, линия гиба 40 мм, полки 20 мм, известные синтетические пуансон/матрица V16, 61 положение с отводом. Станок выключен. Время включает подготовку результата с проверками, исключает импорт STEP/отрисовку GUI. Все варианты сравниваются по кадрам/объёму/коллизиям, выбранные тела — обеими Boolean-разностями. Отдельная деталь t=3 использует те же локальные инструменты без нового построения. «Новый объект кэша» полного цикла создан в том же процессе; реальный новый процесс проверяется отдельно для оснастки и нативного UI.

| Сценарий | Медиана, мс | Мин–макс, мс |
| --- | ---: | ---: |
| Оснастка: кэш отключён | 769.30 | 753.94–770.99 |
| Оснастка: первое заполнение диска/RAM | 271.18 | 267.63–307.67 |
| Оснастка: готовая RAM | 13.14 | 13.03–13.45 |
| Оснастка: новый процесс, диск | 43.44 | 43.13–43.79 |
| Полный цикл: кэш отключён | 1511.65 | 1489.87–1528.74 |
| Полный цикл: первое заполнение | 1557.68 | 1547.22–1597.19 |
| Полный цикл: готовая RAM | 1453.66 | 1451.46–1454.37 |
| Полный цикл: новый объект кэша, диск | 1461.58 | 1457.02–1468.83 |

Оснастка в этом эксперименте получает около **59×** от RAM и **18×** при восстановлении в новом процессе. В полном цикле этой простой детали выигрыш около **4%** при готовом RAM и **3%** при восстановлении с диска. Первое заполнение полного цикла примерно на **3% медленнее** отключённого режима из-за подготовки/записи. Большая часть времени полного цикла остаётся в материале, контактах и Boolean; они не отключались ради чисел. На других профилях/составе/деталях доли отличаются.

Исторический контроль до изменения кода: `baseline-before.txt`, четыре подготовки 753,216 мс. Он не используется для расчёта основного коэффициента: финальная реализация дополнительно гарантирует независимую подготовку сеток и проверяет метаданные секций. Основное сравнение выше — одинаковый финальный бинарник, только режим кэша различается.

## Корректность и перезапуск

- Новый процесс синтетической оснастки: 10 disk hits, 0 построений; следующие запросы — RAM. С лимитом RAM 1 байт постоянные ключи также совпадают, готовая геометрия читается с диска.
- Нативный Linux/X11 100%, частные ST1405M/2030-1 и проверочные 80-мм секции: первое окно построило 10 артефактов, новое окно/процесс — **0 построений, 10 disk hits, 57 RAM hits**. Поворот/кадр/камера/якорь, сохранение/открытие и режим без станка проходят. Это не подтверждение наличия таких секций на складе.
- Новый Release-процесс принял синтетические артефакты dev той же ОС/SDK без построителя. Новый тест прошёл и в native Release с warnings-as-errors.
- Повреждение конверта/payload, сохранение исходного DXF SHA при изменении контура, переименование/изменение наличия, два писателя, отсутствие записи и отмена проверены отдельно от численных замеров. Нативный ручной сценарий сохраняет обнаружение коллизии и защиту поздних ответов.

`builds` в логах — число построений включённого кэш-слоя; отключённый режим не ведёт его счётчиков. Число 0 у нового включённого кэша подтверждает обход построителей, а не просто неизменность картинки.

## Воспроизведение

```bash
cmake --build --preset dev --parallel 2
ctest --preset dev -R '^cad.tool-geometry-cache$'
# Без одновременно выполняющихся тяжёлых задач:
build/dev/bin/tool_geometry_cache_tests --benchmark
```

Для ручного сравнения приложения есть `--no-tool-cache` и `--tool-cache-dir PATH`; обычный запуск кэширует автоматически. Каталог бенчмарка временный и не смешивается с пользовательской библиотекой.

Сырые логи/агрегат: игнорируемые `out/tool-geometry-cache/benchmark-final-{1,2,3}.txt`, `measurements.json`, `native-first.log`, `native-restart.log`, `cross-build-{debug,release}.log`, CAD/Release-проверки и снимки. Сборки/повышенный масштаб не выполнялись параллельно итоговым трём измерениям. Физический перезапуск ОС, Windows/GPU и перенос артефактов между разными SDK не проверены. Push/PR/релиз не выполнялись по D051.
