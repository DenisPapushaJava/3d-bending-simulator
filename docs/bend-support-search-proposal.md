# Граница опоры и развитие поиска для листовых деталей

Дата: 2026-11-05. Статус: **граница опоры реализована локально — D161**, затем добавлена ограниченная [совместная операция зон D162](joint-bend-operations.md). Блоки реального контура/частичной опоры группы, бюджета инструментальных кандидатов и альтернатив секций остаются отдельными задачами. Это уточнение текущей кинематики, не модель усилия или сертификат изготовления.

Формула зависит только от параметров поддержанного локального гиба и плеч матрицы. Имя STEP, число гибов, мировые оси и принадлежность детали к коробке/швеллеру/профилю в ней не используются. Общая форма и текущие соседние полки по-прежнему проверяются CAD-адаптером.

## Что найдено на стойке

Для B03 исходной стойки t6/R6/90° плоские полки имеют длины 28 и 136 мм. У фактического DXF-ручья 2067-1 V≈50 центр правого плеча расположен на 26,760042 мм от оси, радиус плеча — 4 мм. Размер DXF равен 50,0000000001 мм: в диагностике ручей выбирается по близости измеренного значения, а не точному равенству литералу 50.

| Величина | Значение |
| --- | ---: |
| Меньшая полка | 28 мм |
| Прежняя достаточная верхняя оценка расстояния опоры | 28,844415 мм |
| Максимум по текущей кинематической формуле | 21,844415 мм |
| Минимальный запас прежнего условия контакта | 14,741711 мм |

Прежняя оценка завышает требуемую длину на 7 мм и отклоняет эту конфигурацию до 3D-проверки. Это не доказывает пригодность всего гиба: опора по реальному контуру, другие гибы, станок и упоры проверяются отдельно.

## Реализованный первый шаг: верхняя граница без лишнего запаса — D161

Пусть `h` — половина текущего угла, `H` — половина целевого угла, `L = BA/2`, `a` — полуразнос центров плеч, `b = t/2 + r` с радиусом плеча `r`. Используемая в `calculateState` длина от касательной до контакта:

```
q(h) = (a - L*sinc(h) - b*sin(h)) / cos(h),  h ∈ [0,H]
q(0) = a - L
```

Прежняя более грубая граница `(a - L*sinc(H))/cos(H)` независимо отбрасывала влияние толщины и скругления плеча. Сохранено прежнее достаточное условие контакта `a - L - b*sin(H) > tolerance`, а после него используется `max(q(0), q(H))` с консервативным запасом округления.

Почему этого достаточно для непрерывного интервала нашей модели:

1. Прежнее условие даёт `a > L`, а поддержанный целевой угол даёт `0 < H < π/2`.
2. Знак `q'(h)` совпадает со знаком `N(h) = a*sin(h) - L*(h-sin(h)*cos(h))/h² - b`.
3. `N'(h) = cos(h) * (a - 2*L*(sin(h)-h*cos(h))/h³)`.
4. `sin(h)-h*cos(h) = ∫₀ʰ t*sin(t)dt ≤ h³/3`. Следовательно `N'(h) ≥ cos(h)*(a-2L/3) > 0`.
5. Производная может сменить знак только с минуса на плюс: внутри интервала у `q` возможен минимум, но не максимум. Максимум находится на одном из концов.

К максимуму добавлен `32*epsilon*(a+L+b)/cos(H)`; все эти величины положительны после валидации входа и сохранённого условия контакта. Неконечная граница отклоняется. Проверены реально вычисленные `PressState`, независимые расстояния между касательной и плечом, оба возможных положения максимума, граничные допуски и масштаб до 100000 мм. До штатного CI обеих ОС подтверждён только Linux toolchain. Нельзя применять формулу вне доказанных предпосылок или заменить доказательство несколькими проверенными углами.

Меняется только достаточная граница опоры. Траектории, толщина/радиус, число кадров, контактное условие, угол/носик/V, исходный контур, оба Boolean-подтверждения, коллизии, упоры, отвод и D100/D127 остаются прежними. Прежние успешные движения должны совпадать по позам/геометрии; вновь допустимая по скалярной оценке установка ещё должна пройти полный CAD-checker.

Перенос проверен также сравнением двух настоящих сборок до/после: среди 9072 наборов параметров все прежние 2901 допуска сохранились, 26109 записей геометрии кадров совпали точно. Новыми стали 81 ранее отклонённая по опоре конфигурация; другие коды отказов не изменились. Постоянный быстрый тест проверяет 2982 допущенных конфигурации и 301182 независимо измеренные позиции контакта. Это контроль конечного набора вместе с непрерывным обоснованием выше, не обещание поддержки произвольной BRep.

- Численная проверка: 6000 воспроизводимых комбинаций толщины/радиуса/скругления при углах 5/15/45/90/135/175°, по 257 углов; превышений границы не найдено. Это численный контроль, непрерывное обоснование приведено выше.
- Существующие `simulation_tests` прошли, включая реальные отрицательные случаи опоры, угла и носика.
- Существующие `bend_route_tests --tools` и `multi_bend_operation_tests` с новым объектным файлом прошли на собственной геометрии, включая DXF/секции, полный маршрут и проверку поверхности при движении.
- Для стойки 1063 + 2067-1 V50 скалярный отказ B03 снят, но полного проверенного маршрута **нет**: 33 попытки, последняя причина B04 — отсутствие торцевой полосы 28,156892 мм при разрешённых 3 мм. Исходный STEP/BRep сохранён. Это продвижение диагностики, не завершённая поддержка изготовления.

Частные STEP/прототипы/логи — ignored `out/front-left-rack-support/support-*`, исходная модель не публикуется. Эти пробы не заменяют полный корпус, Windows, native 3D/GPU или проверку производственного процесса.

## Следующие самостоятельные задачи

### Совместные зоны в одной операции

По уточнению пользователя проверены B04/B05 этой стойки через готовые `FlatPatternInfo::bends`, без подмены исходных осей осями экрана. В готовой детали оси перпендикулярны; на развёртке они совпадают, направление одинаковое, обе зоны t6/R6/90°. Родительские стенки разные: между ними расположен B02, который при формировании разводит оси. Значит, это кандидат **до** соответствующего соседнего гиба, а не постоянное объединение распознанных зон.

Длины участков — 376 и 136 мм. На материальной развёртке при K=0,45 промежуток равен 13,665928 мм, общий охват — 525,665928 мм. В текущей кинематической модели K=0,5 это 14,137167 и 526,137167 мм соответственно. Эти представления нельзя смешивать при монтаже/проверке длины; результат развёртки по материалу не является геометрией движения. В пяти диагностических положениях от 0 до 1 матрицы переноса двух подвижных полок из общей кинематической плоскости совпали до 4,55e-12; это поддерживает гипотезу общего движения, но не заменяет проверку всего материала, инструмента, опоры и упора. Проба — ignored `group_flat_probe.cpp` / `group-flat.log`.

По следующему поручению первый ограниченный общий переход/поиск и интерфейс реализованы в [D162](joint-bend-operations.md). Ниже сохраняются ориентиры постановки; частичная торцевая опора группы и полный маршрут стойки этим автоматически не подтверждаются.

- Сохранить исходные зоны/грани/ID и размеры; операция хранит одну или несколько зон. Число распознанных зон и ходов пресса может различаться. В интерфейсе одна операция показывает её зоны, например `B04 + B05`; шаг 0 сохраняет смысл плоской заготовки.
- Генерировать кандидата по общей линии в текущем состоянии, толщине, целевым углам/R/направлению, совместимому движению и одному ходу выбранного инструмента. Совпадения линий на исходной развёртке недостаточно. Проверять целиком переносимые компоненты и все деформируемые участки; не ограничиваться двумя основными полками/одним цилиндром.
- Инструмент и секции проверять на полный осевой охват с промежутками и реальные поддерживаемые интервалы. Для разрыва между отдельными зонами не создавать металл или требование сплошной опоры на отсутствующий материал; разрыв **внутри** реальной опорной полосы остаётся прежним отказом. Корпус в промежутке также может столкнуться с деталью.
- Выбирать одну общую установку/ориентацию и базу X/R, проверять обе зоны/всю деталь, станок, пол, пальцы и отвод прежним охватом. Совместимость локальных преобразований не подтверждает изготовление.
- Состояние поиска остаётся набором выполненных исходных зон, переход отмечает весь набор операции. Полный ключ кэша включает набор зон перехода, входное состояние, инструмент/секции/ориентации/упор/допуски. Не использовать старую проверку одного B-ID для группы и не заменять её успехом каждого одиночного гиба.
- Сохранять одиночные варианты; не объединять постоянно все параллельные зоны и не перебирать заранее все подмножества. Сначала ограниченные геометрически совместимые группы; неизвестный или отклонённый групповой переход не запрещает одиночные переходы/другие состояния.

Первый блок D162 проверяет групповое движение, общий инструментальный переход/упор и сохранение исходных назначений на собственной геометрии. Разные родительские полки, разделяющий соседний гиб и подрезанные торцы требуют дальнейших отдельных проверок; детали текущего охвата/результатов — по ссылке выше. Не добавлять неиспользуемый фреймворк операций заранее и не переписывать рабочие одиночные маршруты ради одного STEP.

### Реальный контур опоры

Для подрезанных полок нынешний checker требует прямоугольную сплошную полосу от касательной до максимального расстояния плеча. Это достаточное условие; при сложном торце отсутствие такого прямоугольника ещё не доказывает отсутствия реального контакта. Нужно отдельно исследовать охват фактического движения контактов по исходным полкам, непрерывность интервала и допустимость конечных торцов. До такого подтверждения сохраняются нынешний отказ и диагностический ручной просмотр.

Не повышать 3 мм до найденных 28 мм автоматически, не заполнять внешний вырез, не отключать проверку опоры ради этой модели. Более точная проверка нужна в дополнение к прежнему быстрому доказательству, когда оно не сработало; новые состояния нельзя выдавать за физически подтверждённую устойчивость.

### Поиск вариантов, а не вывод по одному профилю

Нужны три различимых исхода перехода/кандидата: подтверждённый, отклонённый в текущем охвате и неподтверждённый. `Unsupported` отдельного состояния не является основанием считать остальные пары невозможными. Возможное развитие: дать другим кандидатам ограниченный бюджет, сохраняя неподтверждённые для продолжения. Если успеха нет и остались неизвестные — итог тоже неизвестный, даже если последняя пара получила `NoRoute`. Отмена/ошибка входов/SDK и общий лимит сохраняются отдельно.

Опора и доступ к краям зависят от текущего состояния соседних полок. Измерение короткой полки в готовом STEP допустимо как рейтинг, но не как глобальный запрет матрицы: до соседнего гиба там может быть более длинная плоская поверхность. Аналогично пробный отказ B04/B05 в полностью сформированной детали не превращается в обязательное предшествование на всех остальных состояниях.

### Ограниченные альтернативы секций

После подтверждённого конфликта у торца имеет смысл пробовать несколько сборок того же профиля: меньший выступающий конец, другой разрешённый зазор, другая ориентация. Это не полный перебор наличия и не молчаливая смена ручного выбора технолога. Меньшая сборка по-прежнему не может обходить проверку длины D127. Сапожки не подменяются прямыми секциями без собственной поддержанной геометрии.

## Как переносить без регрессий

Первым отдельным изменением D161 реализовано только уточнение `maximumSupportDistanceMm`. После уточнения пользователя следующие этапы — совместные зоны/проверка их реального контура, затем распределение бюджета и альтернативы сборок. Каждый блок переносится отдельно; совпадение зон не разрешает обойти нынешний checker.

| Класс проверки | Что должно сохраняться |
| --- | --- |
| Уголок, швеллер, лоток/коробка | Старые подтверждённые позы/толщина/радиус; проверки обоих направлений |
| Короткая полка/скруглённое плечо | Новая точная граница; действительно недостаточная полка остаётся отказом |
| Подрезанные/составные торцы | Полная реконструкция, реальные отверстия, отсутствие заполнения внешнего контура |
| Торцевая опора | Строгий 0, 3 мм, превышение, внутренний разрыв; исходные отрицательные случаи D100 не ослабляются |
| Инструмент/станок/пол/упоры | Прежние конфликты/отвод/длина/малый V остаются отказами |
| Волновые профили 16/24/32 | Ограниченное время/память, прежнее переиспользование состояний, корректные лимиты/отмена |
| Кэш и ввод | Полные ключи состояний/ориентаций/инструмента/допуска; неподтверждённое не кэшируется как глобальная невозможность |

Новые предположения ранжируют варианты, а не запрещают их без доказательства. Успехом улучшения считаются снятый ложный отказ и неизменённые проверки на других классах, а не один полученный маршрут на целевой стойке.

## Внешние ориентиры

Проверено чтением первичных страниц 2026-11-05: [CMU Bend Sequence Planner](https://www.ri.cmu.edu/project/bend-sequence-planner/) связывает последовательность с оснасткой, перемещениями и планом заднего упора; [LVD CADMAN-B](https://www.lvdgroup.com/en-us/software/cadman-v8/cadman-b) заявляет совместный подбор последовательности/инструмента/установки/упора и 3D-проверку. Это ориентиры постановки задачи, не описание закрытого алгоритма LVD и не основание срочно заменять наш поиск на A*. Формула границы и её обоснование выше выведены из собственного `PressMotion`, а не заимствованы у этих продуктов.
