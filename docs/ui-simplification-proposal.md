# Простой сценарий проверки гибки

Дата: 2026-10-19. **Статус: архив исходного предложения.** После обсуждения пользователь поручил реализацию; актуальное поведение и границы описаны в [D036](simple-workflow.md). Исходное основание: перегруженное окно, понятный сценарий для человека без глубокого знания гибки, крупные кнопки и понятные иконки. Не все предложения ниже являются реализованными возможностями.

Изучены текущий код MainWindow/ToolSelectionWidget, документы G1/G2 и сохранённый снимок нативного окна при 100%. Для обсуждения подготовлен отдельный интерактивный набросок с учебными состояниями. Он не вызывает CAD/проверку, не подтверждает пригодность выбранной пары и не меняет приложение или Figma.

## Задача пользователя

«Открыть готовую деталь, выбрать свой инструмент, увидеть проблему или посмотреть, как происходит гибка».

Число нажатий сокращается за счёт автоматической подготовки и объединения команд. Подробности показываются в момент, когда по ним нужно принять решение. Расчётные ограничения и происхождение данных сохраняются.

## Почему окно перегружено

- Слева постоянно видны дерево/список зон и техническое описание распознавания, справа — параметры и отчёт. Для одного сгиба эти области конкурируют со сценой.
- Крупные нижние этапы соседствуют с отдельными «Далее», одинаковыми командами проверки в разных разделах и техническими режимами просмотра.
- «Порядок» занимает самостоятельный этап, хотя рабочий многогибовый маршрут ещё не реализован.
- Пользователь видит внутренние понятия программы: подготовку просмотра, статическую установку и кинематику без инструмента. Основная задача требует одной проверки и просмотра результата.

## Предлагаемая компоновка

Большая постоянная 3D-сцена, одна панель текущей задачи справа, крупные кнопки этапов снизу. Общие команды открытия/сохранения доступны в оболочке. Ползунок кадров и скорость появляются при готовом движении. На сцене остаются компактные команды вида и «Размеры».

| Этап | Основное содержание | Основное действие |
| --- | --- | --- |
| Деталь | Короткая сводка: толщина с источником, распознанные сгибы, найденные вырезы | Выбрать инструмент; если данные противоречивы — сначала конкретное уточнение |
| Инструмент | Доступная/последняя пара, активный ручей и понятные рабочие сечения | Проверить гибку |
| Проверка | Короткий результат, область проверки и проблемы со ссылкой на 3D | При успехе — воспроизвести; при проблеме — перейти к её причине |

Нажатие этапа меняет текущую задачу. Оно само не запускает тяжёлый расчёт и не инвалидирует результат. Проходить все этапы последовательно при каждом открытии не требуется. Если инструмент уже назначен и входы однозначны, проверка доступна сразу.

### Крупные кнопки и иконки

Начальный ориентир для Qt: высота 80–96 logical px, иконка около 28–32 px, название и одна короткая строка состояния. Например: «Деталь / 6 мм · 1 гиб», «Инструмент / Учебная · V48», «Проверка / Требуется расчёт». Размеры уточняются на реальном окне при 100%.

Иконки всегда сопровождаются текстом. Для детали — листовая деталь, для инструмента — узнаваемое сечение пуансона и V-матрицы, для проверки — движение детали/воспроизведение. Для Qt предпочтительны масштабируемые векторные изображения. Окончательные иконки ещё не выбраны; набросок использует условные контурные значки. При заимствовании набора сохранить лицензию и уведомления.

Текущий этап, готовые входы и обнаруженная проблема — разные состояния. Посещение раздела не означает успешную проверку; статус сопровождается текстом, не только цветом.

## Что программа берёт на себя

- После загрузки определяет доступные параметры, выбирает единственную поддерживаемую зону, берёт цель CAD и подсвечивает распознанные вырезы. Подсветка не требует подтверждения.
- Подставляет сохранённую или последнюю пару как видимое предложение. Это не утверждение её совместимости с деталью/станком. Автоподбор инструмента остаётся будущей функцией.
- После «Проверить гибку» выполняет нужную подготовку, установку и доступные проверки одной командой. Сам просмотр начинается отдельным Play.
- При изменении входов сразу показывает «Нужна новая проверка». Дешёвые ограничения проверяет сразу, тяжёлую геометрию запускает явно. Изменение камеры, размеров и скорости не требует расчёта.
- Спрашивает только о недостающем решении: неоднозначной толщине/зоне, неполном инструменте или конфликте сохранённых данных. Явные исключения и ручные цели пользователя сохраняются.

## Что показывать по ситуации

Редкие ручные параметры открываются рядом с соответствующими данными; полный отчёт — из результата. Статическая установка и движение без инструмента доступны как дополнительные виды просмотра, не как обязательные этапы. Для одной зоны постоянный левый список не нужен; выбор нескольких зон требует отдельного компактного представления.

Ошибка должна сообщать причину, место на 3D и следующий доступный шаг. Например, «Пуансон пересекает полку» → показать столкновение → сменить инструмент. Если альтернативная установка не проверена, её нельзя предлагать как уже решающую проблему. Неактивная проверка сопровождается понятной причиной.

Вместо общей надписи «Можно изготовить» показывается точный результат геометрической проверки. Рядом остаются краткие существенные ограничения: упрощённый инструмент, физика вырезов не учитывается; подвод/гибка проверяются по кадрам, вертикальный отвод поддержанного клина — непрерывно. Подробности не должны прятать найденную проблему.

## Несколько сгибов и граница предложения

Сейчас расчёт поддерживает один сгиб с двумя полками. При нескольких распознанных зонах нельзя показывать готовый маршрут после выбора одной строки. Нужна ясная причина ограничения рядом с действием.

Когда появится работающий ручной маршрут, можно добавить этап «Порядок гибов» между инструментом и проверкой только для деталей, которым он нужен. Само распознавание нескольких зон пока не включает этот сценарий.

Следующее обсуждение — пройти на наброске обычный случай, неполную пару, устаревший результат и неподдерживаемую деталь; затем определить объём изменения Qt. Эта запись не утверждает автоматически всю компоновку, новые алгоритмы, формат проекта или сроки реализации.
