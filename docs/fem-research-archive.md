# Отложенный опыт FEM

2026-10-18 пользователь решил остановить усложнение FEM и продолжить геометрический просмотр с игнорированием замкнутых отверстий/карманов. FEM сохранён в удалённых ветках без слияния и удаления:

- `feat/fem-bend-hole-experiment`, `41f70881a888c3835fd444b3cef97cf58e33bc2b`, [закрытый PR #12](https://github.com/DenisPapushaJava/3d-bending-simulator/pull/12): отдельные CalculiX/Gmsh Python/Docker-скрипты, девять реальных численных случаев, графики и HTML.
- `feat/fem-app-workflow`, `1c93bb3a32bbf8eea620f2f61b1bd68fe2d00d95`, [закрытый PR #13](https://github.com/DenisPapushaJava/3d-bending-simulator/pull/13): меню/диалог Qt, чистый application::FemRunner, адаптер QProcess/Docker, отмена и открытие результата. Ветка включает весь эксперимент; её можно восстановить отдельно. CI [39121856591](https://github.com/DenisPapushaJava/3d-bending-simulator/actions/runs/39121856591): core 3/3, Windows 16/16, Ubuntu 20/20, DEB/запуск. Интерактивный Windows/GPU и сам FEM на Windows не подтверждены.

В активную геометрическую ветку исходники/модуль/процесс FEM не переносятся. Следующее развитие определяется текущим поручением пользователя; возвращение к FEM не должно происходить автоматически из-за наличия старого плана.

## Что проверено

Синтетическая пластина 60×20×1 мм, отверстие Ø4 мм, V24/R2, пуансон 85°/R2, ход 3 мм. CalculiX 2.21, Gmsh 4.12.1 из Ubuntu 24.04, условный изотропный материал, контакт без трения, симметрия половины ширины. Девять случаев: упругая проверка балки, контроль без отверстия, положение отверстия, три сетки, шаг нагрузки, жёсткость контакта и разгрузка. Последние две сетки различались по силе на 1,4%; это численная чувствительность, не физическая валидация.

Отверстие на линии гиба дало 275,04 Н против 339,10 Н без отверстия; смещение на 6 мм — 332,31 Н. Разгрузка: угол 30,87° → 27,21° (плоская форма = 0°). Эти числа относятся только к данной учебной постановке, не являются поправочными коэффициентами для производственных деталей. Материал не калиброван по реальной марке/образцу, повреждение и трещины не рассчитывались. Произвольный STEP в FEM не импортировался.

Нативный Linux/X11 сценарий из окна программы завершил реальный расчёт, сохранил CAD/editRevision и удалил контейнер. Отдельно проверена реальная отмена. Истории, исходные сетки/поля и снимки остаются локально в игнорируемом `out/fem-study` и `out/fem-app-live`; публичные собственные контрольные данные сохранены в ветках.

## Уроки для возможного возвращения

Подробные `docs/fem-bend-hole.md`, `docs/fem-app-workflow.md`, Dockerfile и скрипты находятся в сохранённых ветках. Читать их до повторного запуска; не считать подготовленное ранее окружение обязательной частью приложения. Docker/solver/mesher не распространялись в DEB/ZIP; собственные скрипты MIT не меняют GPL-условия внешних инструментов.

- Равновесие/перемещения/реакции и конечный шаг обязательны; отсутствующее поле нельзя заменять нулём. `Job finished` одного недостаточно.
- Контакт face-to-face прошёл простой упругий контроль; ранние другие постановки не сходились. Отказ одной сетки/закрепления не доказывает невозможность гибки.
- Узловые S/PEEQ не являются пиками в точках интегрирования; проекция неплоского контура не равна собственной овальности отверстия. Проверка записанных узлов не охватывает весь объём или непрерывную траекторию.
- Отдельный процесс требует явной отмены внешней работы; прекращение Docker-клиента не останавливает контейнер. В прототипе использованы create/start/rm, пределы времени, отдельный случай неподтверждённой очистки, UUID/SHA-256 и снимок скриптов на задание.
- Qt 6.8 требует Q_OBJECT для класса, переданного в findChild; соответствующий заголовок должен входить в AUTOMOC. Успех на Qt 6.4 сам по себе не подтверждает совместимость.

Перед прогнозом реальной детали нужны подтверждённая плоская заготовка, материал/условия процесса, контроль контакта/локальных полей и сравнение с образцом. Обратная деформация согнутого STEP не восстанавливает технологическую историю.
