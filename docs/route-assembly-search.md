# Поиск сборок секций вместе с порядком — D167

D173 по последующему поручению добавляет отдельное разрешение на [ограниченный подбор окна](automatic-die-window.md) после реального Sheet–Die конфликта. Ниже описано базовое семейство до четырёх пар, которое пробуется до планирования окна.

D174 при выполнении условий сначала пробует [исходную общую сборку](common-assembly-search.md) с общей квотой и мягким приоритетом доступа. Если полного пути нет, используется описанное ниже семейство; точные геометрические кэши сохраняются, тупики ограниченного семейства сбрасываются.

2026-11-05. Реализован первый ограниченный связанный поиск для отдельных и совместных операций. Цель — получить первый полный маршрут в поддержанном геометрическом охвате. Глобально минимальное число переналадок/поворотов и все возможные составы секций не обещаются.

## Команды и область изменения

- **«Подобрать инструмент»** подбирает пару/ручей прежним механизмом и теперь может выбрать разные сборки этой пары для разных операций полного маршрута.
- В меню рядом добавлена **«Порядок и секции выбранной пары»**: профили, рабочий ручей и ориентация пуансона сохраняются; меняются только разрешённые сборки и порядок/ориентации детали. Повтор «Продолжить подбор» сохраняет этот режим, не расширяя его до чужих профилей.
- Область 0 разрешает подбор для всей детали; индивидуальная/совместная область — только для перечисленных исходных зон. Снимки остальных операций остаются фиксированными.
- Обычные **«Подобрать порядок» / «Проверить мой порядок»** читают сохранённые назначения без разрешения изменять секции. Прежняя кнопка **«Подобрать секции»** сохраняет быстрый расчёт по длине без полного поиска.

`BendRouteRequest::assemblySearch` — временный снимок явного разрешения: список исходных индексов и максимальный межсекционный зазор. Без него инструмент фиксирован. Разрешён только автоматический поиск с инструментом и полными захваченными DXF-формами; повторные/неизвестные индексы, учебные профили, неконечный/отрицательный зазор отклоняются. Наличие читается из снимков, мастерская не изменяется. Собранные секции могут повторно использоваться в последовательных независимых установках; одновременные станции и их суммарный склад этим не моделируются.

## Варианты одного перехода

Требуемая длина одиночной операции — осевой размер исходной зоны. Для группы сначала подтверждаются текущие соосность/касательные/параметры и рассчитывается **общий охват вместе с промежутками**. Длина материальной развёртки при выбранном K не подменяет этот охват.

Существующий ограниченный `planToolSegments` вызывается независимо для пуансона и матрицы. Он сохраняет прежние правила наличия/целочисленной точности 0,001 мм, отсутствия выдуманных секций, предпочтения сборки без зазоров и исключения сапожков без поддержанной объёмной геометрии. Добавлены stop-token и типизированный `Cancelled`; отмена проверяется внутри DP, результат после отмены не публикуется.

Рассматриваются до четырёх различных пар:

1. Подобранный пуансон + подобранная матрица.
2. Исходный пуансон + исходная матрица.
3. Подобранный пуансон + исходная матрица.
4. Исходный пуансон + подобранная матрица.

При разрешённом осевом размещении D169 исходная пара пробуется раньше подобранной; одинаковые пары исключаются. Дополнительный проход D174 вообще не запускает DP, пока пробует исходную общую сборку.

Семейство содержит только небольшие списки секций/зазоры; полные DXF не копируются четыре раза. Неизвестное наличие/неподдержанная сборка не создают нового инструмента: остаётся исходная разрешённая установка. Для совместного хода разные исходные сборки можно согласовать только при явном разрешении **каждой** зоны и полном равенстве остальных полей назначения, включая профиль, инвентарь, ручей, разворот, станок и упор. Единственная общая сборка затем применяется ко всем членам группы.

Заведомо недостаточный осевой охват отбрасывается до CAD. Затем каждая пара/сторона проходит прежний общий переход: реальные секторы, распределение тела D166, обе объёмные реконструкции, каждый опорный интервал, V/длины/углы, точные DXF-корпуса, станок/пол, контакты и отвод упора, отвод пуансона и прежние 61 положение. Разрешение искать секции не является разрешением воспроизвести короткий инструмент. D099/D127 сохраняются; внешние торцевые потери отдельно регулируются D165.

Один оптимум DP не является полным перебором физически различных сборок: другой порядок секций, другие допустимые промежутки/их размещение, сапожки, смещение станции и все варианты близкой длины пока не генерируются. Отказ текущего семейства не доказывает невозможность изготовления.

## Поиск, бюджет и память

- Планы DP переиспользуются внутри запроса по исходному индексу и точному требуемому охвату; профиль/инвентарь и максимальный зазор неизменны в этом `RouteSearch`. До 128 таких запросов, по 200000 состояний каждого DP. Лимит планирования оставляет `SearchLimit`, а не `NoRoute`, если проверенный маршрут не найден.
- Общие лимиты времени/переходов и отмена сохраняются. Проверка бюджета выполняется перед DP/CAD; один ограниченный вызов SDK может закончиться после временной границы, как и раньше. Метрики `plannedAssemblies` — фактические вызовы DP, `reusedAssemblyPlans` — попадания в таблицу пар планов текущего запроса.
- Канонические состояния детали остаются независимы от инструмента. Все пробуемые сборки проверяются до отметки состояния как просмотренного. Маска допустима только в текущей модели независимых установок и одного снимка разрешений; при будущем моделировании переноса/станций состояние потребует расширения.
- Геометрический ключ содержит фактический снимок каждого участника, все биты, разрешённую сторону, секции и зазоры. Разрешение на поиск не подменяет физический ключ. Провал длинной сборки не переносится на короткую; другая величина разрешённого зазора не выдаёт старую сборку вне нового разрешения.
- Успешный путь сохраняет **те же точные ключи переходов**, с которыми он проверялся. Дополнительная реконструкция ключа по исходным назначениям не нужна. При исключении из дочернего поиска откатываются и шаги, и ключи, чтобы неподдержанная ветвь не загрязнила следующий вариант.
- Новое поле шага `assemblyAssignment` ссылается на интернированный immutable-вход через shared alias. Нет полной копии DXF в каждом LRU-отказе. Таблица планов локальна, старые лимиты LRU/состояний/прогрева и постоянный кэш тел оснастки прежние.

## Приём, просмотр и сохранение

`applyRouteAssemblyResult` сначала проверяет полный однократный охват ID/индексов и разрешение каждого изменения. Любое изменение вне двух полей сборки запрещено. Новая сборка должна состоять из допустимых прямых секций в захваченном наличии и укладываться в явно заданный предел зазора. Лишь затем одним снимком уточняются ожидаемые инструменты для прежней проверки preview в контроллере, включая охват обеих сборок, все зоны группы, упор/станок/отвод. Подменённый профиль/разворот/склад/неполный результат, отмена и поздний ответ ничего не назначают. Для обычного фиксированного маршрута дополнительные копии DXF не создаются.

Принятые назначения и порядок сохраняются атомарно в `DocumentSession`. Они уже представимы действующим `.bend`: новый формат не нужен, исходные зоны не объединяются. После открытия сохраняются реальные секции, а проверенный маршрут, как раньше, пересчитывается. Чертёж/распознавание/стороны листа прежние.

При выборе шага, перед которым отличается оснастка, существующая панель сообщений во вьюпорте показывает **«Перед гибом смените сборку инструмента»**. Состав доступен в инструментальной области этого шага. Сам процесс переналадки, извлечение и перенос детали не проверены; найденные независимые установки не объявляются единственной неизменной станцией.

## Проверки и наблюдения

- Собственный `cad.route-assemblies`: совместные зоны 45/55 мм с промежутком, общий охват 120 мм, исходные сборки 80 мм, наличие 80+40. Поиск выбирает 120 мм, полный цикл/отвод и общий ход; тёплый запрос не строит переход заново. Проверяются фиксированный режим, изменённое наличие, разные исходные сборки, слишком короткий фиксированный инструмент, разные пределы зазора и отмена. Зазор 4 мм допускается только в реальном пустом промежутке между зонами; предел 3 мм не переиспользует эту сборку.
- `app.joint-assemblies`: контроллер принимает обе изменившиеся зоны атомарно, сохраняет/открывает реальные сборки в `.bend`, показывает один шаг, групповой инструмент и разворот. `app.checked-tools` проверяет явное разрешение, отдельную команду выбранной пары, сохранение режима продолжения, отказ подмены ориентации и прежние отмену/быстрый обход.
- Независимые application/core-тесты отклоняют изменение профиля/ориентации, выход за склад/предел зазора, закрытую зону группы, пропущенные/повторные ID и отменённый DP.
- Частная стойка, 1063 / 2067-1 V50, DemoPressV3/упор, предупреждения D165: из исходных сборок 1400 мм автоматически найдено **B03 → B04+B05 → B02 → B01** со сборками **1400 → 530 → 1400 → 1385 мм**. 8 проверок, 8 вызовов DP и 2 повторных использования пар планов, около 79 с в локальном Debug-запросе без импорта, полный результат принят проверкой снимков; STEP/BRep неизменны. Размеры/порядок не записаны в правила алгоритма. Это первый проверенный результат, не минимальное число переналадок.

### Контроль смен секций на четырёхгибовом кожухе — 2026-11-05

По поручению пользователя проверена частная КСР-1505 10.11: t2, B01/B03 по 1899 мм, B02/B04 по 531 мм. Воспроизведены кандидаты обычного GUI из текущего снимка библиотеки, включая её наличие и предел зазора 4 мм, DemoPressV3 и упор. Первая найденная пара — 1063 / 2067-1 V16. Обычный поиск вернул B01 → B02 → B03 → B04: пуансон 1900/1900/1900/535 мм, матрица 1905/1905/1905/835 мм (11 проверок). Это допустимый в текущем охвате маршрут, но смена секций здесь необязательна.

Отдельный запрос с фиксированным порядком **B02 → B04 → B01 → B03** прошёл тот же полный checker с неизменными сборками на всех операциях: пуансон **835+835+200+20+10 = 1900 мм**, матрица **835+835+100+50+40+20+15+10 = 1905 мм**, стыки без зазоров. Разворот пуансона прежний, стороны/осевые смещения детали заданы отдельно; выполнены четыре полных перехода, исходный STEP не менялся. Упор, станок/пол, коллизии, обе реконструкции, опора и длины не отключались. Локальные исходники пробы, логи и SHA снимков — ignored `out/rear-cover-order`; библиотека и пользовательские настройки не перезаписывались. Время фиксированного порядка и автоматического поиска не является сопоставимым benchmark.

Последующим поручением реализован [первый ограниченный блок D174](common-assembly-search.md): проход исходной общей сборки с прежним checker/бюджетом/кэшем и численный приоритет доступа. Другие общие составы секций этим проходом не подбираются. DFS с возвратом первого полного пути по-прежнему не минимизирует число смен глобально. «Короткие стороны первыми» — результат исходной пробы, не универсальное правило/запрет для других деталей. Перестановка, извлечение и перенос по-прежнему не проверены.

Финальные сборки, наборы тестов и границы проверки — в [development.md](development.md). Частные модели/контуры/утилиты остаются в ignored `out/front-left-rack-support` и `out/rear-cover-order`. SDK, зависимости, VERSION, `.bend` и каталог прежние; публикации нет, D051 сохраняется.
