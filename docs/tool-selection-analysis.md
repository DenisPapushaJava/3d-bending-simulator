## Что хранит библиотека

Пуансон и матрица выбираются независимо. DXF задаёт сечение, но сам по себе не сообщает доступные длины/количества, допустимую нагрузку, стандарт крепления или пригодность для определённого материала. Для многоручьевой матрицы кандидат — конкретный ручей с его V, углом и ориентацией полного корпуса. Геометрия и рабочие параметры должны относиться к одной ревизии записи.

Пользовательская библиотека остаётся локальной; добавленные DXF не удаляются при изменении встроенного набора. Встроенных записей больше нет (D117); мастерская содержит только пользовательские захваченные DXF-сечения. Учёт секций включается отдельно; незаполненное количество не следует считать наличием. Старый автономный `.bend` сохраняет собственный снимок инструмента.

## Как выбирает наша программа сейчас

Реализация: `src/core/ToolSelection.cpp`, `src/core/ToolSegments.cpp`, `src/ui/ToolSelectionWidget.cpp`; требования формируются в `MainWindow.cpp`.

| Этап | Фактическое поведение |
| --- | --- |
| Требования | Толщина, поворот от плоскости, внутренний радиус и длина гиба. Для общей пары — максимальные длина/поворот и минимальный Ri всех целей; для отдельного назначения — выбранный гиб |
| Кандидаты | Полный перебор пуансон × матрица × ручей из библиотеки мастерской; не из чужих снимков открытого проекта |
| Полнота | Отсеиваются записи без подтверждённых рабочих параметров и учебные записи. Импортированный неподдержанный рабочий контур исключается перед предложением |
| Длина | Оба инструмента должны перекрыть длину гиба. Если включён учёт наличия, отдельно рассчитываются сборки пуансона и матрицы |
| Угол | `turn + max(punchAngle, dieAngle) ≤ π`. Запас на пружинение не вычисляется |
| Радиус | Носик меньше целевого Ri с допуском 10⁻⁵ мм; дополнительно проверяется соотношение носика и V. Это проверка размещения носика, а не прогноз полученного радиуса |
| Матрица | `V/t ≥ 5` — граница текущего стандартного режима. Предпочтение близкому к `8t` ручью |
| Порядок предложений | `abs(log(V/(8t))) + 0.1*(Ri−nose)/Ri`; при равенстве — ID и номер ручья |
| Результат | Первая пара переносится в обычные поля выбора. Затем пользователь запускает проверку; полный DXF используется, если включён режим известных форм |

Состав секций ищется ограниченным динамическим программированием: сначала минимальное превышение нужной длины без зазоров, затем меньшее число секций при одинаковой длине. Если такой сборки нет, допускается равномерный зазор до заданного пользователем предела. Секции с нулевым количеством и рожковые окончания не используются как обычные прямые секции. Исчерпание бюджета отличается от нехватки секций. Длинный цельный инструмент допустим; возможный конфликт его выступающих концов проверяется в 3D.

Отсутствие DXF пока допускает явно условный корпус; наличие неподдержанного DXF не разрешает молча заменить его клином. Проверка `drawingToolGeometry` подтверждает распознавание рабочих участков, но не отсутствие столкновения с конкретной деталью.

**Главный пробел:** ранжирование не видит формы зева пуансона и всей детали. Два пуансона с одинаковыми носиками могут получить одинаковую оценку независимо от того, какой из них столкнётся с уже согнутой полкой. После CAD-отказа следующий профиль, другой состав секций, ручей или ориентация сейчас автоматически не пробуются. Поиск порядка работает с уже назначенным инструментом; сам по себе он не является поиском по библиотеке.

Материал уже выбирается для развёртки, но в `ToolSelectionRequest` он не передаётся. Усилие, прочность материала, допустимая нагрузка инструмента/ручья/крепления и запас на пружинение в автоподборе отсутствуют. Геометрическая проверка учитывает назначенные тела станка в текущем охвате; предварительный численный фильтр не подтверждает монтаж. `DemoPressV2` остаётся приближённой демонстрационной сборкой.

## Предлагаемый следующий шаг

Сохранить быстрый фильтр, затем пробовать кандидатов через существующую общую CAD-проверку. Не вводить отдельную упрощённую геометрию столкновений только для автоподбора.

1. Получить требования каждого активного гиба и все пригодные по параметрам пары/ручьи. Для общей пары пересечь допустимые наборы; сохранить независимые требования, а не только сводный максимум/минимум.
2. Раньше пробовать текущую пару, если она допустима, затем лучшие параметры и доступные сборки. Непроверенная привычная установка не получает статус успешной.
3. Для кандидата проверить действительные DXF-корпуса, обе доступные ориентации пуансона, длины/расположение секций, опоры и препятствия в состояниях маршрута. Быстрый ручной просмотр сохраняет обязательные проверки пересечений; успешные ручные кадры не подменяют полный цикл.
4. При отказе переходить к следующей паре. Сначала искать одну установку на всю деталь; индивидуальный инструмент по гибам и штраф за переналадки — следующее расширение. Не обещать независимый от порядка «идеальный пуансон».
5. Ограничить поиск по времени/переходам, поддержать отмену. Первый пригодный вариант можно показать раньше окончания оптимизации. Ограничение первыми несколькими кандидатами допустимо лишь как бюджет поиска: оно не доказывает отсутствия решения в остальной библиотеке.
6. Использовать постоянный кэш тел D091 и существующие кэши состояний/переходов D081/D082. Проверка столкновений другой детали не переносится; изменение геометрии, ручья, ориентации, сборки, станка или целей меняет входы проверки.

В UI достаточно одной команды подбора и выбранной пары с короткой причиной: «V16 для 2 мм», «без пересечений в проверенном маршруте». Альтернативы и причины отклонения раскрываются по запросу. Не запускать полный поиск на каждый клик/hover; текущий ручной просмотр обновляется прежним ограниченным механизмом. Неполные данные о нагрузке показываются отдельно от геометрического результата.

После геометрического перебора следует блок усилия: подтверждённая прочность материала, метод гибки, действительная длина линии, паспортные пределы станка, крепления, пуансона и выбранного ручья с согласованными единицами. Контур DXF не позволяет восстановить эти пределы. Семейство «сталь/нержавейка/алюминий» и K-фактор недостаточны для подтверждения нагрузки. Чужие коэффициенты и веса коммерческих программ здесь не заимствованы.


## Рейтинг по форме D139

Поручение пользователя 2026-11-03 — реализовать следующий шаг оптимизации, включая близкие разнонаправленные гибы и полный корпус матрицы. Новый рейтинг не использует артикулы, имена файлов или специальный порог 25/30/60 мм.

### Подготовка признаков

CAD-worker при импорте один раз готовит `DocumentMetadata.toolShapeHints`. Первый поддержанный случай — две распознанные цилиндрические зоны с параллельными осями, общей исходной плоской гранью и перекрывающимися осевыми интервалами. Индексы относятся к исходному `bendAnalysis`. Из второй пары плоских поверхностей соседнего гиба берутся крайние проекции вершин; получается численный четырёхугольник полки с её толщиной/наклоном/протяжённостью. Направление вверх/вниз определяется геометрией, а не знаком абсолютного угла распознанной зоны.

Система координат соответствует активному гибу в плоском состоянии и уже сформированному соседу. Ось X направлена вдоль плоской полки, Y — к внутренней стороне активного гиба. Учтён сдвиг на половину кинематического припуска K=0,5, как в существующем просмотре. Это не материальная развёртка K=0,45 и не изменение исходного STEP. Пространственный поворот/перенос исходника не задаёт направление установки станка. Подсказки используют проекцию наружного протяжения полки; вырезы/изменения вдоль оси могут сделать её приближённой.

Подготовка не выполняет Boolean, meshing или перестройку тел. Неподдержанная геометрия/ошибка SDK даёт отсутствие подсказки и прежний отбор. Во внутренних `routeState` исходные подсказки очищаются: их индексы не переносятся на заново распознанные промежуточные грани.

### Оценка контуров

`core::toolShapeRisk` получает только числа и захваченные DXF. Матрица поворачивается через общий `activeDieDrawing`, затем нормируется по `dieTopCentre`; пуансон — по рабочему кончику с учётом его разворота. Проверяется **весь замкнутый контур**, включая остальные ручьи и выемки, а не только V, общая ширина или тип «четырёхручьевая».

Дуги аппроксимируются хордами не более 5°, численная полка пробуется сеткой 17×3. Оценка 0…1 — доля пробных точек внутри сечения инструмента, **не вероятность столкновения или пригодности**. Граничное касание не получает штрафа проникновения. Для каждой соседней пары берётся лучшая оценка двух порядков (если доступны обе подсказки) и двух сторон установки; худшая из локальных пар задаёт оценку инструмента. Это оптимистический локальный признак: выбранные для разных пар порядки могут не составить общий маршрут.

В предварительном выборе профиля также пробуются обе ориентации пуансона; исходная нормальная ориентация в UI не переписывается автоматически. В проверяемом запросе оценивается каждая конкретная ориентация назначения. Станок, адаптер/держатели, осевые окончания/сапожки и перемещения между операциями этим рейтингом не подтверждаются.

Вспомогательная работа ограничена: до 256 подсказок, 4096 хорд на контур и оценка до 2 млн посещений рёбер на вариант. Отсутствующие, нечисловые, вырожденные, неподдержанные и превышающие бюджет данные дают `nullopt`, а не «свободно». Режим старого условного тела не ранжируется по неиспользуемому DXF.

### Применение в сценарии

- В `selectTools` сначала действуют прежние проверки параметров/инвентаря, V/t ≥ 5, длины, угла и носика. Сборки из наличия передаются оценке. Только затем известные кандидаты сортируются по форме; при равенстве сохраняется прежний параметрический рейтинг около 8t/радиуса и стабильный порядок.
- Кандидаты без оценки сохраняют свои места в исходном списке. Рейтинг **не удаляет** широкую матрицу/пуансон и не делает новую норму из отношения шага к габариту.
- MainWindow копирует готовые численные подсказки только для включённых гибов и исходных CAD-заданий. Ручной профиль и команда подбора секций не заменяются новым выбором. В GUI нет CAD-проверок/нового окна/настройки рейтинга.
- Общий worker `buildRoute` ранжирует конкретные `toolVariants`, в том числе для backend-вызовов. Меняется отдельный массив индексов, сам входной список не переписывается. `selectedToolVariant` и прогресс продолжают ссылаться на оригинальный снимок D125/D116.
- Диагностический флаг запроса `rankToolShapes=false` оставляет исходный порядок, не меняя checker или порядок гибов. `shapeRankedToolVariants` считает полученные оценки, `toolShapeRankingUs` — работу этой стадии, включая неуспешные попытки оценить доступные подсказки. Метрики не входят в кэш геометрии/`.bend`.

Ручной/полный переход, упоры, D100/D127, плотность положений и остановка столкновений прежние. Положительный результат рейтинга не получает сертификата; назначение принимается только после существующей 3D-проверки. Нормы нагрузки и физический расчёт этим блоком не добавлены.

### Проверка и дальнейшее развитие

[Регрессии и условия измерений](development.md#d139-рейтинг-инструмента-по-форме-2026-11-03): полные контуры, корпус с выемкой при той же ширине, склад/зазоры, поворот рабочей стороны, источника и зеркальная деталь, разные размеры Z, панель с 16 гибами, обычный/ручной/проверяемый выбор. На собственном тесном Z широкая матрица 60×60 получает более позднюю попытку; первый полный маршрут с упорами строится узкой матрицей, не нарушая минимум V.

Следующие отдельные задачи: рейтинг сохранности баз в промежуточном состоянии, распределение бюджета между трудными парами и улучшение стоимости переориентаций. Они не считаются реализованными D139. Идеи ARA*/CP-SAT не подключены.

### Повторный замер корпуса матрицы

2026-11-11. На контрольной Z-детали со ступенью 25 мм сравнили узкую и четырёхручьевую матрицы с одинаковым V16. При учёте полного DXF-корпуса проверена одна пара вместо двух. Время до маршрута 5,39 → 4,71 с, само ранжирование 0,80 мс. Выбранная пара, порядок, стороны подачи и положения упоров совпали. Отдельный численный тест сохраняет нулевой штраф для матрицы шириной 60 мм, если выемка корпуса освобождает место полке. Это один локальный прогон Linux Debug. Логи находятся в `out/horn-order-audit/`.

Для дальнейшей проверки положения можно сопоставлять фактическую глубину корпуса от оси активного ручья на высоте полки и осевое перекрытие с конкретными секциями. Для отсева требуется доказанный конфликт в проверяемом положении с учётом выемок и зазоров. Для отсева всей сборки требуется такое доказательство по всем разрешённым положениям и сторонам.
