# Постоянный кэш оснастки — D091

D104 добавляет [RAM-кэш четырёх установок детали/пуансона](workpiece-orientation.md#кэш-и-производительность). Он отделён от описанного ниже постоянного кэша оснастки: выбор детали сохраняется в v14, проверенные переходы детали между запусками не сохраняются.


2026-10-30. Реализован локально. [Первоначальный анализ](tool-geometry-cache-proposal.md) сохранён как история. Кэш включён автоматически при обычном запуске, без нового шага интерфейса. Он хранит производную геометрию на диске и переиспользует её между деталями, запусками программы и обычными перезапусками ОС. Срока годности по времени и очистки на старте нет.

## Что сохраняется

| Артефакт | Представление |
| --- | --- |
| DXF-пуансон/матрица и условный инструмент | Точное локальное BRep-тело и готовая сетка |
| Назначенный набор секций | Compound с упорядоченными секциями, включая их сетки; подписи длин/положения восстанавливаются из текущего назначения |
| Повторяющиеся части станка | Нормализованная призма и сетка; размещение держателей/рам применяется отдельно |
| Занятый объём вертикального отвода пуансона | Точное BRep без ненужной для проверки сетки; величина отвода входит в ключ |

Нормализация убирает текущие переносы Y/Z и монтажные смещения из локального тела там, где геометрия допускает такое разделение. Разворот остаётся физическим поворотом на π вокруг Y, включая Z-расположение секций. Два положения используют одно тело с разными Location, отдельные копии всей геометрии ради зеркалирования не сохраняются. Координаты исходной детали в ключ инструмента не входят.

Состав секций сейчас сохраняется готовым compound, а не отдельным файлом на каждую длину. Первое построение секций через Common сохранено. Отдельная прямая экструзия каждой секции остаётся возможной следующей оптимизацией; новые рога/3D-торцы этим не поддержаны. Вспомогательные тела построения sweep и пробная экструзия проверки импорта не засоряют постоянный кэш.

Геометрия сохраняемых ревизий DemoPressV1/V2 не менялась: добавлено внутреннее нормализованное представление с возвратом в прежние мировые позиции. Правила монтажного контакта, видимости станка и охвата проверок остаются D088/D089.

## Актуальность

Ключ строится по фактической геометрии после перевода в мм/выбора рабочей стороны: координаты и типы рёбер/дуг, рабочая база, длина, геометрия условного профиля, состав/порядок/тип/зазор секций, нормализованные контуры частей станка и параметры sweep. В нём также находятся версия алгоритма `tool-assets-v1`, OCCT, формат BinTools, платформа/разрядность/порядок байтов, SHA-256 SDK manifest и triplets. Для сеток учитываются абсолютная deflection и угол; точный sweep не зависит от качества сетки. VERSION приложения в ключ не включён: совместимый выпуск не обязан пересоздавать артефакты.

SHA исходного DXF, имя/артикул/путь, количество на складе и цвет не являются отпечатком тела. Данные берутся из текущего снимка назначения, включая сохранённый контур старого `.bend`; изменение одноимённого каталожного инструмента не подменяет проектный снимок. Допуск/алгоритм построения или валидации без изменения явных входов требует новой версии ключа. При изменении SDK namespace выбирается заново; совместимость файлов разных ОС/SDK не предполагается.

Для составных артефактов происхождение SDK-тел учитывается в пределах запроса. Это не зависит от присутствия исходного тела в RAM-LRU: вытеснение/лимит памяти не меняет постоянный ключ. Для произвольного тела без такого происхождения используется его точное BRep-представление; ошибка вычисления производного ключа отключает кэш данной операции, а не проверку.

## Хранение и отказы

- Windows portable: `data/cache/tool-geometry/` в корне комплекта, вне `runtime/<VERSION>`/`.updates`. Обычное обновление сохраняет `data`.
- Обычная установка Windows/Linux: `cache/tool-geometry/` внутри `QStandardPaths::AppLocalDataLocation`, не системный временный каталог и не `CacheLocation`.
- `--tool-cache-dir PATH` задаёт отдельный каталог для диагностики; `--no-tool-cache` отключает уровни RAM/диска. Эти параметры не записываются в проект/настройки.

Запрос использует RAM, затем один адресуемый по SHA-256 файл `.brepc`, иначе строит и записывает тело. На старте весь каталог не загружается. Файл содержит версию конверта, SHA-256 дескриптора/содержимого и бинарное BRep с сеткой при необходимости. Максимальный payload — 64 МиБ. Перед SDK-чтением проверяются размер/контрольные суммы, после — валидность BRep, конечный положительный объём, наличие/конечность узлов и корректные индексы треугольников нужной сетки. Это контроль артефакта, не подтверждение пригодности инструмента к конкретной детали.

Запись через QSaveFile с отключённым direct-write fallback и QLockFile по ключу. Одновременный писатель может пропустить запись и продолжить с готовой геометрией в памяти. Незавершённый/повреждённый/несовместимый файл не принимается; нужная запись перестраивается. Ошибка чтения/записи/сериализации не превращает корректную геометрию в отказ проверки. Недоступность записи отмечается один раз в журнале, без обязательного диалога. Отменённое задание не публикует частичный артефакт. Обычный перезапуск сохраняет завершённые файлы; аварийное питание/поведение конкретной ФС отдельно не сертифицированы.

RAM-LRU по умолчанию ограничен 64 МиБ **сериализованного веса плюс ключи**, это не предел всего RSS OCCT. Кадры, viewer и активное задание могут удерживать свои ссылки после вытеснения. Файлы не удаляются автоматически по времени; папку кэша можно удалить для полного перестроения. Каталог инструмента, STEP и `.bend` хранятся отдельно и для очистки кэша не нужны. Сами контуры и `.brepc` не включаются в Git/релиз/сетевые запросы автоматически.

## Архитектура и проверки

`application::GeometryArtifactStore` — стандартный порт байтов/дескриптора без Qt/OCCT. `project::GeometryCacheFiles` реализует хэши и атомарные файлы на уже используемом Qt Core. `cad::ToolGeometryCache` владеет SDK-телами и LRU; путь/store задаёт app. Scope на существующем CAD-worker обслуживает одиночный цикл, ручной маршрут и поиск. `discardRouteCache` при смене детали не стирает независимые инструменты. Дополнительного CAD-пула и зависимости CAD от Qt нет.

Все загруженные/построенные тела подготавливаются до публикации. Boolean может разделять неизменённые грани с исходным телом, поэтому сетка строится только на собственной глубокой копии. После публикации тела не ремешатся: кадр отдельно мешит материал, инструменты переиспользуются с Location. AIS/GPU-ресурсы на диск не сохраняются.

Источник детали, материал, контакт, длина/допуски, пересечения и монтажные ограничения проверяются прежним путём. Включение кэша не отключает ни одного кадра/Boolean и не переносит положительную проверку на другую деталь. Готовые ручные/полные результаты по-прежнему используют отдельные кэши D081/D082/D090; их сериализация этим блоком не введена.

Проверки: новое тело/диск/RAM, новый процесс с нулём вызовов построителей, вытеснение RAM, нормальная/развёрнутая геометрия и секции, одинаковый артикул/SHA с другим контуром, переименование/изменение наличия без смены тела, неполный конверт/испорченный payload, два процесса, недоступная запись, отмена, полный цикл с кэшем/без и другая толщина без перестроения инструмента. Отдельно пройден нативный Linux/X11 UI с частным ST1405M + 2030-1: после нового запуска **0 построений, 10 disk hits**, проверка/поворот/сохранение и прежняя камера работают. Эти временные 80-мм секции — проверочная установка, не утверждение о реальном наличии.

Численные замеры/команды и ограничения — в [результатах](tool-geometry-cache-performance.md). D051: без push/PR/релиза; графика только 100%. Windows/GPU и физический перезапуск ПК не выполнялись; сохранение после нового процесса проверено реально, обычное приложение использует постоянную папку данных.
