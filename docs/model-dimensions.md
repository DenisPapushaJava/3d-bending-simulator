# Размеры во вьюпорте

D192, 2026-11-06: реализация уточнений D191, наружных размеров в симуляции и
компактных выносок. **Оформление PDF и его набор размеров прежние.**
[Исходное исследование](viewport-dimensions-proposal.md),
[анализ двух слоёв](viewport-measurement-layers.md).

## Постоянные размеры

Одна кнопка **«Размеры» / Ctrl+D** управляет слоем. Изначально он скрыт;
прежняя команда показа развёртки включает его. Выбор элемента не удаляет базовые
размеры. Состояние остаётся локальным окну, не меняет проект и расчёты.

- Исходная деталь: габариты X/Y/Z по осям STEP и подтверждённые наружные размеры
  полок в подготовленных локальных сечениях. Мировые габариты не объявляются
  автоматически лучшими конструкторскими базами. Переменная полка может иметь
  несколько разных измерений; неизвестное не подменяется прямым участком/средним.
- Развёртка: два габарита и координатные привязки осей гибов. Для совпавшей
  координаты в одной системе — одна подпись с перечислением исходных B-ID.
  Для косой линии остаётся идентификатор: координата середины не выдаётся за
  расстояние от края. Это теоретические координаты развёртки, не X упора.
- Одинаковые подтверждённые наружные размеры полок объединяются с количеством
  разных стенок. Разные сечения одной стенки не увеличивают количество полок.
  Полка не дублируется отдельно, если её направление и полный измеренный интервал
  совпадают с уже показанным габаритом; одного равенства чисел недостаточно.
  Привязки к разным базам/осям не смешиваются по одинаковому значению.
- Подписи располагаются около геометрии с ограниченным местным сдвигом. Поиск
  свободного места у далёкой границы окна исключён. У линии развёртки выноска
  начинается от конца реального участка, а не пересекает всю заготовку.
  При нехватке места шрифт не уменьшается и числа не удаляются молча: выводится
  предложение увеличить окно/вписать деталь. Проекция почти ребром не даёт нулевых
  или выдуманных размеров; подробности линий скрыты до читаемого ракурса.

## По клику

Режим использует реальные CAD-грани/рёбра исходника и подготовленные контуры
развёртки. ЛКМ заменяет одну выбранную группу, Esc/пустое место снимает подробности,
оставляя постоянный слой. Выбор измерения не меняет `drawingBase` или `.bend`.

| Выбор | Подтверждённые величины |
| --- | --- |
| Распознанный гиб | Внутренний угол между стенками, Ri, t, осевая длина. Подрезанный торец сохраняет смысл «Осевой габарит». |
| Замкнутое круглое отверстие | Диаметр, центр и доступные привязки к базовым прямым кромкам. Цилиндр сам по себе не объявляется отверстием/сквозным отверстием. |
| Поддержанный симметричный вырез | Полные размеры по подготовленным осям, центр, контур и привязки. Произвольная центральная симметрия не означает стандартный овальный паз. |
| Плоская грань / участок | Площадь; длины сторон только при подтверждённом прямоугольном внешнем контуре. Габарит произвольной грани не объявляется размером полки. В развёртке это перенесённый плоский участок исходника, не площадь всей заготовки. |
| Ребро / дуга | Реальная CAD-длина; R только для окружности. Длина не измеряется по экрану или фасетам сетки. |

Два произвольных выбранных элемента остаются следующим отдельным этапом.
Режим выбора здесь — исходная деталь/развёртка; промежуточные тела симуляции не
получают произвольный измерительный CAD-редактор.

Для отверстия по умолчанию выбираются ближайшие две подтверждённые перпендикулярные
базы с конечными точками контакта внутри прямых рёбер. В исходнике граница
касания плоскости с радиусом гиба исключается из автоматических внешних кромок.
В развёртке базы заново берутся с **внешнего контура заготовки**, а не с внутренних
границ исходных полок. Если таких баз нет, показывается размер отверстия без
придуманной привязки. Shift+клик по подходящей прямой внешней кромке выбирает
свои базы; сохраняются до двух, третья начинает новую пару. Это локальный выбор
просмотра. Толщина листа не выдаётся за глубину кармана.

ВВЕРХ/ВНИЗ у выбранного гиба относится к показанной физической стороне развёртки;
при переходе +Z/−Z меняется направление, а не идентичность A/B. B-ID — исходная
зона, не номер шага или автоматическое объединение совместных операций.

## Наружные размеры в симуляции

Точки размерных линий готовятся CAD worker из текущего `BendSection`: наружные
концы полок и **виртуальное пересечение наружных стенок**. Это не переименование
касательных П1/П2. При 90° прямой участок 30 мм, Ri=8 и t=6 дают наружные 44 мм.
Для другого угла используется пересечение реальных текущих направлений, не
постоянная прибавка Ri+t. При равных размерах — одна подпись «Полки … · 2 шт.».

Наружные размеры и осевой охват сохраняются во время воспроизведения; подробный
текст Ri/t возвращается на паузе. В плоском положении конечного виртуального
угла нет: показывается габарит текущего геометрического положения. Кинематическая
модель K=0,5 не объявляется производственной развёрткой — последняя строится
отдельно по материалу/выбранному K. Осевой охват совместного хода может включать
промежутки и не подменяет длину отдельной исходной зоны.

Если виртуальный угол выходит далеко за экран, вместо огромных продлений
используется короткая выноска от видимого конца с тем же значением. Угол/R
относятся к реально показанному кадру; исходные CAD-измерения не подменяются целью
или прогнозом инструмента. Это геометрические величины, не расчёт пружинения.
Остановка столкновения/короткого инструмента и D127 прежние.

## Данные, актуальность и ограничения

`ModelMeasurements` — SDK-free численные значения, source ID и точки. Подготовка
работает в прежнем CAD-worker на независимой копии геометрии без сетки; индексы
сверяются с историей Copy. Площадь переиспользуется из импорта. Наружные полки
используют измерительную основу DrawingProfiles/D153, без HLR/компоновки/PDF.
В UI нет Boolean/распознавания по клику/повороту. Старый доступ к UV-поверхности
из `Dimensions` заменён подготовленными точками грани.

После заполнения отверстий номера граней не переносятся в развёртку напрямую:
сопоставление требует единственного полного владельца реальной площади на
расчётной стенке. Новый Common работает в non-destructive режиме и только в
worker. Частично перекрытый/неоднозначный элемент не угадывается. Через область
гиба отверстие не переносится как целая жёсткая окружность.

Оперативный слой ограничивает записи рёбер 10000 и кандидаты замкнутых контуров
256; сопоставление ограничено 2048 Common. Это ресурсные границы дополнительных
измерений, не запреты импорта/гибки. В PDF прежний полный режим распознавания
контуров. Сбой дополнительных измерений не отменяет валидный импорт/развёртку;
отмена и ревизии по-прежнему обязательны. Результат хранится только с текущим
документом/снимком развёртки, без нового CacheManager/дискового кэша/формата файла.
Синтетические рёбра баз развёртки имеют локальные ID; подробности очищаются при
переходе между системами, чтобы не переносить их как source-индексы.
