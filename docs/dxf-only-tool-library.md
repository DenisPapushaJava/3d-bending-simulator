# Библиотека только из DXF-профилей — D117

D120, 2026-11-01: импорт/замена встроены в [единый центр библиотеки](tool-library-center.md#реализовано-локально--d120). Геометрический контракт D117 сохранён. Каталог с архивом пишет v5, читает v1–v5; `.bend` v14 прежний. Описанные ниже первоначальные отдельное окно и формат v4 относятся к этапу D117.

D121: подготовленный DXF может содержать внутренние вложенные INSERT-блоки. Импортёр сам раскрывает поддержанные установки, сохраняя дуги и проверку всего сечения; предварительное ручное раскрытие для TOP.205.85.R08 больше не требуется. [Поддержка и ограничения](tool-dxf-import.md#блоки-dxf--d121). Неизвестные единицы по-прежнему требуют явного выбора.

2026-10-31. По прямому поручению пользователя удалены 15 встроенных справочных записей без сечений. Новая геометрия инструмента и размеры его сечения поступают только из заранее подготовленного DXF. Редактор контура/размеров внутри приложения отложен. Реализовано и проверено локально на Linux, D051 сохраняется.

## Источники и совместимость

Чистая установка запускается с пустой библиотекой. Нет встроенного JSON, скрытых параметрических заготовок или автогенерации инструмента по артикулу. В уже наполненной мастерской используются её локальные DXF-снимки. Удалён ресурс, функция builtInToolCatalog и её вызов при запуске.

Пользовательский каталог и переносимый проект не удаляются. При восстановлении мастерской/импорте JSON записи без корректного миллиметрового сечения и учебные записи не попадают в рабочую библиотеку, палитру и инвентарь; при явном импорте показывается число пропущенных записей. Исходный импортируемый JSON не переписывается. Следующее явное сохранение библиотеки сохраняет её актуальный состав. Сечение с неподдержанным контактом/неизвестной длиной остаётся контуром для просмотра, недоступным для назначения/подбора. Это отличается от прежней записи с одними числовыми параметрами.

JSON остаётся форматом хранения и переноса уже подготовленной библиотеки с захваченными контурами, не новым редактором геометрии. SHA-256/sourceFile обозначают захваченный DXF; наличие этого поля не является независимой проверкой подлинности чужого файла. Отсутствие исходного DXF после сохранения не ломает библиотеку. Старые .bend читаются с прежней семантикой; сохранённый условный инструмент не превращается в новый реальный профиль и не запускается в GUI. Чужие проектные снимки не становятся наличием мастерской.

Пустой ToolCatalog теперь допустим для хранения/восстановления. Остальные ограничения размера/идентификаторов сохранены. Каталог v4 и .bend v14 не изменены. Утилита tools/import_tool_profiles.py больше не берёт удалённый встроенный каталог: для её архивного сценария требуется явный --catalog; основной способ добавления нового инструмента — GUI DXF.

## Добавление и замена

Основное окно содержит три поля: **тип, название, длина инструмента**. Название предлагается по имени файла, тип определяется автоматически при единственном поддержанном рабочем профиле; при неоднозначности остаётся явно выбранный тип. Запуск из палитры матрицы/пуансона первоначально выбирает соответствующий тип. Ручная смена типа сохраняет приоритет до загрузки другого файла.

1. Выбрать подготовленный текстовый DXF или перетащить один локальный DXF в окно. Drop действует только здесь; STEP/JSON/удалённые URL/несколько файлов не принимаются. Всегда используется Copy, исходник не перемещается и не перезаписывается.
2. Единственный контур и известные единицы выбираются автоматически. Если контуров несколько, ни один не назначается произвольно; нужно выбрать сечение. При неизвестных/неподдержанных единицах нужно явно указать их. В обоих случаях раскрывается **«Дополнительно»**, сохранение до решения недоступно.
3. Проверить крупный профиль и информационную сводку угла/R/V/габаритов. Редактируемых инпутов размеров нет. Повернуть сечение кнопками ±90° или отразить рядом с изображением. Произвольный угол исходного положения доступен в дополнительных настройках; эти действия не меняют размеры профиля. Пуансон должен быть носиком вниз, матрица — рабочим ручьём вверх.
4. У многоручьевой матрицы видны кнопки V. Нажатие меняет рабочую сторону картинки и сводку; полная таблица V/угол/поворот находится в дополнительных настройках. В библиотеке остаётся один корпус с общим инвентарём.
5. Указать **длину инструмента**, например 835 или 415 мм, — размер вдоль балки станка, вглубь поперечного сечения. Она не выводится из 2D-сечения. Секции/количество настраиваются отдельно в библиотеке; нагрузка/крепление по одному DXF не выдумываются.
6. **«Добавить»** проверяет замкнутый wire/face и пробное тело в общем CAD-worker, затем атомарно записывает библиотеку. Ошибка/отмена не меняют прежнюю запись. Трансформации/ручьи/метаданные во время финальной проверки недоступны. Неподдержанный рабочий профиль можно сохранить только для просмотра с явным сообщением.

Производитель, запись библиотеки для замены, контур/единицы, точный угол исходного положения, таблица ручьёв и диагностика DXF собраны в свёрнутом блоке **«Дополнительно»**. Для замены существующего сечения нужен новый DXF; сохраняются ID/секции, геометрические параметры измеряются заново. Редактора контура/размеров пока нет. Смена строки ручья и ввод имени/длины не перестраивают аналитические измерения или неизменившийся предпросмотр.

## Измерения и границы

Core вычисляет аналитические габариты линий/дуг, включая экстремумы внутри дуг, без mesh. Круглый носик распознаётся теми же признаками касательных соседей и нижней опорной точки, которые использует геометрическая проверка. R берётся из окружности, угол — из дуги носика. При неоднозначности либо неподдержанной форме значения не угадываются. Прежняя проверка уже заданных параметров при симуляции сохранена; новые измерения не расширяют автоматически класс контакта.

Матрица автоматически проверяется в положениях 0/±90/180° общим detectDieGrooves. Одна четырёхручьевая форма создаёт одну запись, четыре рабочих положения и общий инвентарь. Текущее ограничение — уникальные V; при повторяющихся V или нераспознанных/специальных рабочих поверхностях нет ручной подмены размеров: доступен только просмотр контура. Расширение этих контактов требует отдельной реализации, а не ввода подходящих чисел.

Предпросмотр и измерения переиспользуются до изменения самого контура/его положения/типа. Ввод имени, длины и выбор строки ручья не запускают CAD Boolean или поиск порядка. Предпросмотр сохраняет один QWidget и обновляет его QPainterPath; смена стороны/поворота не пересоздаёт canvas и не оставляет промежуточный пустой кадр. Неподдержанное сечение не получает статус пригодности. Рабочие усилия/прижим/пружинение не добавлены, существующие проверки инструмента/станка/пола сохраняются.

Проекты сохраняют чтение прежних версий. Linux Debug: сборка dev успешна; 15 затронутых CAD/GUI/project/startup-сценариев прошли, включая повтор после уточнения legacy-фикстур. Независимый core — 8/8, Python-импорт — 3/3. Native XCB при 100% прошёл: DXF-drop, единицы, многоконтурность, интерактивные ручьи/повороты, добавление/замена/сохранение. Снимки тестовых собственных сечений и логи находятся в игнорируемом out/.
