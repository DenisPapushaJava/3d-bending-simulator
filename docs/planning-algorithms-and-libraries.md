# Алгоритмы и открытые компоненты планирования гибки

2026-10-31. Исследование по вопросам пользователя о кэшах, отсечении невыполнимых вариантов и готовых библиотеках. Статус: прочитаны первичные описания/указанные исходники, новые компоненты не установлены и не испытаны на наших моделях. Это дополнение [D109](setup-and-sequence-planning.md), а не реализованное ускорение.

## Уже имеющаяся основа

Текущий поиск — обратный ограниченный DFS по каноническим состояниям, а не независимый полный прогон каждой перестановки. Есть тупиковые состояния внутри запроса, ранние ограничения параметров, мягкий рейтинг кандидатов, кэш промежуточной детали/переходов D081 и постоянный кэш инструмента D091. По чтению `BendRouteBuilder.cpp` удерживаются до 32 промежуточных CAD-состояний и 8 результатов полных переходов; ручные/одиночные кэши имеют собственные пределы. Счётчики уже различают построение и повторное использование.

При неизменной установке совпадение канонического состояния позволяет не исследовать его заново для разных историй порядка. После добавления разных составов/позиций область эквивалентности расширяется: маски гибов уже недостаточно. В общем случае количество состояний остаётся экспоненциальным, кэш не превращает задачу в линейную.

Прочитать открытый код не означает принять его геометрические допущения. В `open-mrp/dfm/brake.go` поиск прямо предполагает, что заблокированный сейчас гиб остаётся заблокированным при добавлении других согнутых зон. Наличие такой проверки подтверждено чтением `Sequence`; её применимость к произвольным нашим деталям не доказана. Контрпример на реальном STEP не строился. Это причина не переносить данное отсечение как общее правило: иной гиб может изменить препятствие/доступность.

Наличие разрешительной лицензии не заменяет проверку конкретной версии, транзитивных зависимостей и notices. Исходники не заимствовались; MIT нашего проекта и текущий состав поставки не меняются. FreeCAD SheetMetal из прежнего исследования полезен для моделирования/развёртки, но не установлен как готовый решатель всей рассматриваемой задачи.

## Предложение для нашего поиска

1. **Состояния вместо историй.** Повторно использовать одинаковую промежуточную деталь. Для решения поиска учитывать существенную физическую установку и ручные фиксации; при оптимизации — также предыдущую установку/стоимость, если от них зависит продолжение. Одного набора согнутых B-ID недостаточно после расширения на разные инструменты/составы.
2. **Подтверждённые ограничения раньше CAD.** Убрать заведомо недопустимые V, отсутствующее количество секций, несовместимые подтверждённые параметры и пустые геометрически обоснованные диапазоны установки. Условные ограничения на выступ/очередность относятся к конкретной промежуточной форме. Нельзя выводить их только из финально согнутой детали.
3. **Переиспользование отказов.** Запоминать отрицательный результат точного перехода вместе с его входами. Отмена, ошибка SDK, лимит времени/поиска не являются доказательством тупика. Обобщать конфликт на другие состояния можно лишь при доказанной неизбежности; «если этот гиб сейчас нельзя, вся ветка невозможна» не принимается по умолчанию.
4. **Выбор перспективной ветки.** Вначале пробовать совместимые с текущей установкой и наиболее ограниченные по доступности действия, использовать уже успешные переходы. Это мягкий приоритет, не вечный запрет коротких/длинных/последних гибов. При общей установке распространять подтверждённые ограничения на допустимые составы.
5. **Устранение эквивалентных вариантов.** Два пути можно объединить, когда совпали состояние и все влияющие на будущее условия. Симметрию всей задачи нужно подтвердить с учётом инструмента, станка и ручных фиксаций; похожих размеров полок недостаточно. При поиске лучшего маршрута оставлять более дешёвый путь только при одинаковой будущей области допустимости.
6. **Геометрический каскад.** Подтверждённое разнесение консервативных объёмов может исключить пару из точной проверки. Пересечение габаритов/оболочек ещё не доказывает коллизию. Для ускорителя на сетках необходимо учитывать ошибку аппроксимации и рабочие контакты; произвольное отсутствие пересечения треугольников не заменяет нынешний CAD-результат.
7. **Разделение компактных ответов и тяжёлых кадров.** Рассмотреть отдельный более ёмкий кэш статусов перехода/причин, сохранив малый LRU готовых кадров. Графику готовить по найденному маршруту/запрошенной диагностике, не ослабляя геометрические проверки отвергнутых веток. Это ещё требует отдельного проверенного перехода и реального потребителя; сейчас полные результаты остаются в прежнем кэше.

Текущий DFS с ограничениями и кэшами — подходящая исходная база. A*/best-first/ветви и границы/CP-SAT — варианты дальнейшей организации, выбор делать по замерам. Для обещания оптимальности нужны корректные нижние оценки и полный охват; эвристический рейтинг, beam-ограничение или исчерпание бюджета этого не дают.

## Постоянство кэша и измерения

Уже постоянен кэш оснастки D091. Результаты переходов детали сейчас относятся к RAM/неизменному документу. Для их будущего дискового хранения нужны отпечатки захваченных STEP-байтов, алгоритма/SDK, геометрии/установки/допусков и остальных существенных входов, целостность/атомарная запись и ограничение размера. Имя файла не является ключом. Старый/неполный результат не становится подтверждением новой проверки.

Критерии следующей реализации: время до **первого** проверенного маршрута, число дорогих переходов/Boolean/подготовок сетки, попадания в кэш и пик памяти. На малых случаях сравнивать отсечения с ограниченным эталонным полным поиском: найденный там рабочий вариант не должен исчезнуть из-за неверного правила. Отдельные случаи — допустимый длинный инструмент, коробка с зависимым порядком, изменение состава/ориентации, тупик, нехватка данных и отмена. Плотность текущих проверок и охват геометрии ради скорости не уменьшаются.
