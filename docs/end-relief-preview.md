# Торцевые подрезы как предупреждение — D165

2026-11-05. По прямому поручению реализовать [предложение D164](end-relief-policy-proposal.md) основной GUI допускает торцевую потерю опоры при подтверждённой общей центральной полосе обеих полок. Результат остаётся геометрическим: локальное выворачивание, смятие и устойчивость не рассчитываются.

## Единая policy

В параметрах установки добавлен флажок **«Допускать торцевые подрезы»**, включённый по умолчанию. Значение сохраняется локально в `checks/allowEndReliefs`. При включённом флажке численный предел отключён. При выключенном действует прежний редактор `checks/maximumEndSupportLossMm` с начальным значением 3 мм; 0 требует полную опору. Переключение отзывает результаты/незавершённый подбор, не запускает CAD автоматически и не меняет параметры проекта. Новая модалка не добавляется.

Запросы одиночной установки/движения и полного ручного/автоматического маршрута передают одинаковый `std::optional<double>`: число — строгий предел, `nullopt` — предупреждение о конечных торцевых потерях. Значения NaN/отрицательные не являются отдельными режимами. Низкоуровневые вызовы одиночного builder без явного аргумента сохраняют строгий 0. Для полного маршрута используется прежний `allowPartialEndSupport=true`; существующая optional-семантика D077 переиспользована, дублирующего доменного флага нет.

Новые предпочтения отделены от `.bend`; при повторном открытии выполняется проверка с текущей локальной policy, как в D100. Формат проекта, VERSION, зависимости и геометрический SDK не меняются. Пользовательская альфа-версия не получает скрытый автоматически подобранный миллиметровый допуск.

## Обязательное доказательство и остановки

Сохраняются полосы D161 и разности D163 для **каждого реального участка** совместной операции. Отсутствующие объёмы должны относиться к одному наружному концу; общий центральный интервал содержит середину участка. Обе полки повторно вычитаются из найденной центральной полосы. Внутренний разрыв, отсутствие центральной опоры или ошибка CAD остаются отказом при любом режиме. Консервативный отказ не превращается в разрешение для неподдержанного контура.

Политика отключает только численный предел конечных торцевых потерь в явно разрешённом режиме. Строгий 0 по-прежнему может возвращать `SupportNotProven`, положительный превышенный предел — `EndSupportLimitExceeded`. Затем продолжается **тот же** общий цикл, а не возвращается искусственный успех из ошибки. Прежние реконструкции/обе разности исходного и независимого предыдущего состояния, контакты, реальный DXF-профиль, длины инструмента с промежутками, минимальный V в прикладном сценарии, столкновения детали/инструмента/станка/пола/упоров и отвод сохраняются. Исходные торцы не заполняются/не обрезаются; D029 отверстий не меняется.

`CadPreview` захватывает применённый optional-предел и все интервальные отчёты. Диагностика столкновения переносит тот же снимок. Контроллер дополнительно сверяет policy с запросом: подходящие численные потери сами по себе не разрешают принять кадры от другого режима. При выключенном `allowPartialEndSupport` эффективный предел равен 0. Пустой/неполный интервальный отчёт инструмента остаётся недопустимым.

GUI использует готовые отчёты. Для частичного маршрута выводится **«Маршрут найден. Торцевые подрезы: возможна деформация»**, для одиночного цикла — предупреждение о торцах. Подробности содержат потери по участкам; численный допуск показывается только если он действительно применён. Коллизия/короткий инструмент сохраняют более высокий приоритет, D099/D127 не обходятся. Шаг 0, ID исходных зон, групповые назначения, чертёж и отображаемые отверстия прежние. Новых CAD-вычислений в GUI/viewer нет. Быстрый ручной черновик D082 по-прежнему не получает подтверждения полной опоры от этого флажка; новая policy относится к проверяемым одиночному/ручному/автоматическому переходам.

## Поиск и кэш

Optional-предел входит в прежние ключи одиночного LRU (4 записи) и переходов полного маршрута. `nullopt`, 0 и положительное число — разные входы. Увеличение/снятие/восстановление ограничения не использует чужой успешный цикл или отказ. Постоянный кэш тел инструмента не меняется: их геометрия от этой policy не зависит.

Мягкий рейтинг **уже измеренных успешных переходов** использует два отношения: максимальную долю потери среди реальных участков и суммарную потерю/суммарную длину участков. Промежутки группы не уменьшают рейтинг. Среди одинаково известных вариантов меньшая потеря имеет приоритет; неизвестный нейтрален. Прежний приоритет доступного проверенного результата, стороны подачи и остальные tie-breakers сохраняются. Для группы подсказка обращается к точному групповому ключу, не к одиночному.

Рейтинг не запускает новые CAD-переходы, не вводит допустимый процент и не удаляет кандидатов. Не обещает глобально минимальную деформацию или поиск всех маршрутов: первый найденный условный путь может остаться с предупреждениями. Это ограниченное предпочтение и повторное использование прежней работы, без нового оптимизатора/полного перебора и без заявленного ускорения без измерений.

## Проверки

Проверяются собственные STEP-фикстуры: конечный подрез 8 мм при L=50; строгие 0/3 мм и включение предупреждения; реальная коллизия с сохранением diagnostic policy; короткий инструмент/узкое V; внутренний разрыв и потеря середины; неизменность объёма и валидность кадров. Совместный ход проверяет отдельные интервалы, превышение лимита одного члена, ручной/автоматический порядок и переключение ключей кэша. GUI проверяет режим по умолчанию, жёлтое предупреждение, отзыв результата без CAD/изменения проекта и локальное восстановление настройки. Подменённый снимок policy отклоняется контроллером.

Фактические команды/итоги записываются в `docs/development.md` после завершения проверок. Частная стойка/контуры/пробы и снимки остаются в ignored `out/front-left-rack-support`; новые пользовательские примеры этим изменением не добавляются. Работа локальная по D051, без push/PR/тега/релиза.
