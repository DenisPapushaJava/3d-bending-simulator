# Сборка: короткий цикл и полный набор — D155

Повторная проверка 2026-11-06: [D185 — саморевью и dev-запуск](code-review-alpha4.md). Первый F5 досбирал приложение около 51 с; повторный без работы Ninja — 0,03–0,04 с. Обычный запуск до show через адаптер cppdbg занял 1,335 с. Подтверждён и исправлен отдельный пропуск зависимости конфигурации от VERSION; полный отчёт содержит границы замеров и проверки.

2026-11-03. Локальное ревью настроек после сообщения о задержках. Изменения касаются выбора целей и числа параллельных задач; алгоритмы программы, SDK и режимы Debug/Release прежние.

## Что обнаружено

- Перед F5 выполнялась полная сборка `dev`, включая тестовые executable. Изменение UI-библиотеки требовало перелинковать ещё 25 тестовых программ, хотя для запуска они не нужны.
- VS Code и его задача явно ограничивали сборку двумя потоками. На проверенной машине Ryzen 7 5700X (8 физических ядер, 32 GiB RAM) принят умеренный предел четыре. Включать все 16 логических потоков без измерения потребления памяти не требуется.
- Инкрементальные зависимости работают: сборка без изменений заняла 0,03 с. У всех 156 записей объектных файлов в Ninja есть непустой список зависимостей. Qt/OCCT подключены как готовые SDK и не компилируются при этих локальных сборках.
- Общие заголовки дают обоснованную широкую пересборку: `BendingDrawing.h` присутствует в зависимостях 43 объектов, из них 26 тестовых. Изменение контракта может менять ABI; исключать такие зависимости ради скорости нельзя.
- `build/release` оставался от Docker с исходным путём `/workspace`. Native CMake завершался ошибкой несовпадения каталога. Старый каталог сохранён как `out/build-settings-review/previous-container-release`, native Release настроен заново. Инструкция Docker теперь использует `build/docker-release`.

## Рабочие команды

```bash
cmake --preset dev
cmake --build --preset dev-app          # приложение и необходимые библиотеки
./build/dev/bin/3d-bending-simulator

cmake --build --preset dev              # приложение и все тестовые программы
ctest --preset dev
```

Для одной затронутой проверки можно вместо полного набора собрать её цель: например `cmake --build --preset dev --target drawing_tests`, затем `ctest --preset dev -R '^app.bending-drawing$'`. Сам `ctest` исходники не собирает.

`dev-app` — build preset, наследующий `dev`; configure preset остаётся `dev`, рабочий каталог и Debug-символы прежние. F5/Ctrl+F5 и Ctrl+Shift+B вызывают `dev-app`. Полная сборка вынесена в «Linux: собрать всё (dev)», задача «Linux: проверить dev» зависит от неё. Ручная команда CMake Tools может по-прежнему использовать ранее выбранный build preset: для короткого цикла выбрать `dev-app`.

Dev использует четыре задачи, Release/core — две. Команда `--parallel 2` ограничивает dev на машине с меньшей доступной памятью; `--parallel N` переопределяет значение пресета. CI уже передаёт `--parallel 2` и не меняется. Одновременно два Ninja в одном build-каталоге запускать нельзя. Новый каталог или смена компилятора всё равно требуют первоначальной сборки.

## Измерения

GCC 13.3, CMake 3.28.3, Ninja 1.11.1, Linux. Один и тот же `DrawingDialog.cpp` с неизменным SHA помечен обновлённым по времени; сборки последовательные, без параллельного Ninja. Время измерено до завершения команды, без запуска тестов.

| Сценарий | Время |
| --- | ---: |
| Прежний F5: полный dev, два потока | 32,40 с |
| Новый F5: только приложение, четыре потока | 7,03 с |
| Новый повтор без изменений | 0,04 с |
| Явная досборка оставшихся тестов, четыре потока | 14,55 с |
| Configure dev перед запуском | около 0,4 с |

Выигрыш короткого запуска — примерно 4,6 раза в этом случае, за счёт исключения ненужных линковок. Для одного изменённого файла компиляция сама по себе не распараллеливается. Полный состав всё равно доступен: два новых прохода заняли суммарно около 21,6 с. Это отдельный локальный замер с прогретым файловым кэшем, не гарантия для любой правки/машины. Журналы и SHA — ignored `out/build-settings-review`.

Самые долгие недавние единицы компиляции Debug: `drawing_tests.cpp` около 7,3 с, `MainWindow.cpp` около 7,2 с, `DrawingSheet.cpp` около 5,1 с. Такие файлы остаются возможным объектом предметного рефакторинга, но их разбиение не входит в настройку сборки.

## Проверки и границы

CMake принимает все пресеты; фактический build `dev-app` содержит только приложение и зависимости, полный `dev` успешно досбирает тесты. Проверены связь F5 с app-only и задачи проверки с full build, независимый core, стартовые сценарии, native install и запуск установленного приложения. Итоговые числа Release/проверок — в [журнале разработки](development.md#d155--профиль-сборки-2026-11-03).

Флаги компилятора, зависимости, PCH/unity/LTO и собственные CMake-цели не менялись. Компиляторный кэш `ccache` на машине не установлен; его подключение через штатный `CMAKE_CXX_COMPILER_LAUNCHER` и PCH рассмотрены как отдельные будущие измеряемые улучшения. Общий принудительный PCH/новая обязательная зависимость сейчас не добавлены. Отладка, корректная инвалидация общих заголовков и возможность полного CTest сохраняются.

Windows/его GPU и удалённый CI не проверены в локальном режиме D051. Сборка Windows по-прежнему выполняется на Windows; на Linux не требуется кросс-компиляция. Полный CTest из 85 сценариев, успешно выполненный перед этой задачей, заново не дублируется из-за изменения выбора build target.
