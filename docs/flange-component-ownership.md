# Распределение тела по реальным прилегающим граням — D166

2026-11-05. По поручению продолжить поддержку сложной стойки устранён ложный отказ разделения целого тела. Это общий CAD-переход для произвольных поддержанных конфигураций, без правил по имени STEP, числу гибов или мировым осям.

## Причина и исправление

После удаления настоящего сектора прежний `splitAtBend` относил полученные тела к сторонам через объёмные пересечения с **прямоугольными оболочками** прилегающих полок. Оболочка содержит и пустые места реальной полки: вырезы, скошенные края, пространство между её участками. Уже сформированная удалённая полка может находиться в этом пространстве. Тогда одно связное тело пересекает обе оболочки и операция ошибочно остаётся неподдержанной, хотя сектор отделил ровно два тела.

Теперь сторона определяется по истории того же `BRepAlgoAPI_Cut`:

1. В текущем CAD-состоянии берутся реальные внутренняя и наружная плоские грани, прилегающие к каждой касательной выбранного гиба. Для совместного хода добавляются грани всех согласованных зон; повтор одной грани на одной стороне исключается. Порядок согласуется с текущими касательными и разрешённой ориентацией, а не с исходной мировой осью.
2. `SetNonDestructive(true)` и `SetToFillHistory(true)` сохраняют исходник и дают соответствие граней результату. У неизменённой грани используется её собственная топология; у изменённой — все уникальные `Modified`-потомки.
3. Каждый потомок должен быть гранью одного однозначно определённого выходного тела. Все потомки одной исходной грани должны принадлежать одному телу. Сохранение площади проверяется в прежнем CAD-допуске: `max(A·1e-7, P·tolerance·2)`, где P — суммарная длина границ. Это дополнительный консервативный guard, а не замена объёмной реконструкции.
4. Нельзя присвоить одному телу обе стороны или оставить тело без реальной прилегающей грани. Удалённые/неполные/неоднозначные данные истории дают `UnsupportedGeometry`. В одиночном ходе по-прежнему нужны ровно два тела; в совместном допускаются несколько, однозначно распределённых по двум сторонам.

Дополнительные Boolean-пересечения прямоугольников для назначения сторон больше не выполняются. Прямоугольные оболочки остаются там, где они нужны для построения начального сечения и достаточной опорной полосы; это изменение не заменяет алгоритм проверки опоры.

Все последующие проверки прежние: обе объёмные разности с исходным телом, сравнение с независимо собранным предшествующим состоянием маршрута, сохранение исходного skin/отверстий, пересечения регионов в движении, длина/минимальный V/углы инструмента, станок/пол/упор и отвод. Само распределение не разрешает коллизию или замкнутую материальную перемычку. Viewer/UI, кэши, форматы, SDK и зависимости не менялись; история принадлежит одному локальному CAD-вызову и не сохраняется глобально.

## Проверяемые случаи

`multi_bend_operation_tests` содержит собственную аналитическую деталь с открытым вырезом и жёсткой возвращённой полкой другой стороны внутри него. Исходная версия ошибочно отклоняла обе ориентации. Новая проверка требует полный кинематический цикл, валидность и сохранение объёма каждого кадра, принадлежность отображаемой поверхности и неизменность исходной BRep. Повторяется произвольный мировой поворот/перенос. Острые углы жёсткого возврата намеренны: fixture проверяет CAD-переход последнего гиба, а не распознавание дополнительных операций изготовления.

Добавленная настоящая перемычка соединяет стороны в обход сектора: такой случай обязан остаться неподдержанным. Проверяется также отмена; прежние независимые тесты одиночных/совместных зон, коробок, составных торцов, коллизий, коротких инструментов и профилей 16/24/32 сохраняются. Фактические результаты — в [development.md](development.md).

## Диагностика частной стойки

Данные остаются в ignored `out/front-left-rack-support`, исходная модель в репозиторий не включается. На полностью сформированном теле удаление B04 или B05 давало два тела. Прежняя оболочка второй стороны захватывала постороннюю полку: ложное дополнительное пересечение около 3020,86 мм³ для B04 и 2307,28 мм³ для B05. Новая привязка устраняет именно этот отказ; проверка затем возвращает настоящую коллизию с пуансоном при прежней общей сборке 1400 мм.

Дополнительно найден **полный геометрический маршрут с предупреждением о подрезах**:

- пуансон **1063**, матрица **2067-1 / V50**, DemoPressV3, упоры включены;
- сборки пуансона и матрицы **1400 мм** у B01/B02/B03;
- одинаковые сборки **530 мм** у B04/B05, по результату планировщика секций для общего кинематического охвата примерно 526,14 мм, включая промежуток;
- прямой порядок: **B01 → B03 → B04+B05 → B02** — четыре хода для пяти исходных зон;
- B01 имеет разрешённую обратную ориентацию детали; остальные установки согласованы общим checker;
- режим внешних торцевых потерь D165, без численного предела при доказанной центральной полосе. Деформация торцов не рассчитана, исходные подрезы не заполнены;
- исходные STEP-байты и сериализованная BRep совпадают до/после запроса.

Отдельная проба TOP.205.85.R08 / V50 с общей сборкой 1400 мм также отклонена по пересечению с инструментом (26 переходов, исходник неизменён). Это результат одного ограниченного запроса, не доказательство невозможности остальных профилей или установок.

Это результат **диагностически заданных сборок**, а не новая возможность общего автоподбора. В исходном запросе одна длинная сборка 1400 мм назначалась всем зонам; новая геометрическая привязка сама по себе не делает её подходящей. Изменение сборок между операциями означает переналадку: перенос/извлечение и процесс перестановки инструмента по-прежнему не проверены. Не объявлять найденный маршрут доказательством изготовления на единственной неизменной станции.
