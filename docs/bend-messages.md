# Сообщения проверки гибки — D126

2026-11-01. Реализовано локально по сообщению пользователя о коротком инструменте и поручению объединить предупреждения в удобной области вьюпорта.

## Текущий интерфейс

В левом верхнем углу сцены «Гибка» расположена компактная панель. Куб видов/якорь справа и нижняя лента остаются отдельными. Заголовок показывает наиболее важное сообщение со стандартной пиктограммой Qt; ещё до двух заголовков видны одновременно. При большем числе указан счётчик дополнительных сообщений. Нажатие/клавиатурная активация заголовка раскрывает прокручиваемые подробности всех сообщений. Подтверждений и таймеров нет, критическую причину нельзя убрать одним закрытием уведомления.

Класс `ui::BendMessagePanel` получает значения `BendMessage` с типом, важностью, заголовком и подробностями. В первой реализации типы: Collision, ToolLength, Support, CheckIssue, Approximation, Scope; важности Information / Warning / Error. Ошибки выше предупреждений, предупреждения выше информационных сообщений; порядок внутри уровня стабилен. Столкновение не скрывает одновременную нехватку длины. Исчерпанный поиск/отсутствие найденного порядка сообщаются предупреждением, без утверждения невозможности изготовления.

Панель показывает текущие данные, не историю. Одинаковые сообщения не перестраивают виджеты и не сбрасывают раскрытие. Смена кадра/результата убирает устранённые причины; переход к исходнику/инструменту/развёртке скрывает панель. При фоновой замене D090 прежняя сцена и её сообщения остаются до результата, без новой подписи ожидания. Старый кадр не становится новым проверенным результатом.

Справа сохраняются существующие сводка и подробный охват проверки. Неполная опора, отсутствие инструмента, приближение с заполненными отверстиями и причины отказа не получают новую семантику из-за места вывода. Панель не запускает CAD, не меняет проект/порядок и не отключает остановку при столкновении. Физика/нагрузка/перенос между установками не добавлены.

## Недостаточная длина

В «Инструменте» предупреждение показывается постоянно, в том числе для цельных профилей без инвентаря и при редактировании одного гиба. Содержит длину гиба, длину пуансона и матрицы и отдельные дефициты. Для общей области применяется максимальная длина включённых гибов, для индивидуальной — выбранный гиб. Изменение одного численного допуска отображения не запускает подбор секций.

Используются фактические осевые длины назначенных сборок, включая предусмотренные зазоры, а не номинальные 835 мм каталога и не одна общая длина пары. Более длинный инструмент допустим по этому критерию; его возможные столкновения проверяются отдельно. Зазор внутри сборки не подтверждает сплошной контакт/качество гиба. Допуск берётся из геометрического анализа CAD; 3 мм D100 относятся к торцевой опоре материала и не разрешают молча короткий инструмент.

`BendRouteToolLengthIssue::coversBend` используется ручным и полным маршрутом. Ручной результат при нехватке несёт отдельный `RouteDraft::toolLengths`; контроллер сверяет числа/наличие отчёта с активной операцией и исходной ревизией. Это производные данные в памяти, не новый формат проекта или постоянного кэша геометрии.

Короткий профиль можно выбрать для последующей сборки секций. По уточнению пользователя D127 обычные Play/ползунок заблокированы; установка остаётся неподвижной, сообщение содержит **«Воспроизведение заблокировано»**. Все подготовленные положения по-прежнему проверяются на столкновения. Полный маршрут отклоняется с ToolTooShort до тяжёлого поиска. Размеры в CAD, допустимые зазоры, опорные и столкновительные допуски не ослабляются.

## Явный диагностический просмотр — D127

2026-11-01. Одного предупреждения недостаточно для обычного запуска. На шаге 0 с коротким первым инструментом Play недоступен. На положительном шаге с нехваткой пуансона либо матрицы показывается начальное положение операции, Play/ползунок недоступны. Автоматическое воспроизведение останавливается при переходе к такому шагу, без продолжения после ответа worker.

Для специального осмотра положительного шага в «Подробностях проверки» доступен переключатель **«Диагностический просмотр»**. Он разрешает движение только текущего принятого ручного результата; при переключении обратно воспроизведение останавливается и возвращается в начало. Смена шага, инструмента/ориентации, уход к исходнику/другому этапу и новая подготовка снимают разрешение. Возврат к закешированному результату не восстанавливает его автоматически. Это временное состояние UI, не параметр проекта/геометрического кэша.

Команда не меняет входы и не запускает CAD: используются уже подготовленные и проверенные кадры. Дефицит длины/пометка диагностического просмотра остаются видны; коллизии продолжают останавливать Play. Программная смена значения заблокированного ползунка также не позволяет показать движение. Выбор достаточной длины восстанавливает обычное воспроизведение без отдельного подтверждения. Проверка полного маршрута не принимает диагностическое разрешение.

## Отображение и ограничения

Viewer позиционирует Qt-панель над нативным canvas тем же отложенным механизмом, что нижнюю ленту. Ширина оставляет место кубу, высота ограничена доступным местом над транспортом и половиной окна. Раскрытие не поворачивает камеру и не строит сцену заново. Явное вписывание учитывает обе панели с сохранением цели орбиты. `captureImage(true)` захватывает обе панели, `false` — прежнюю графику без Qt-контролов; PDF/геометрия чертежа не менялись.

Новых библиотек/ресурсов/форматов нет. Проверки только 100%; Windows/GPU остаётся отдельной проверкой. Сведения о тестах — в [development](development.md#d126--длина-инструмента-и-сообщения-в-сцене-2026-11-01).
