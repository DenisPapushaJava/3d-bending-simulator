# Автоматическое окно матрицы после коллизии — D173

2026-11-05. Продолжение [ручной компоновки D172](local-tool-gaps.md). Реализован первый ограниченный поиск **одного** окна между реальными зонами общего хода. Паз/вырез сам по себе не создаёт окна: сплошная матрица и обычные установки остаются первыми вариантами.

## Разрешение и входы

`RouteAssemblySearch::allowDieWindows` — явное разрешение для автоматического поиска с инструментом и заданной областью исходных ID. По умолчанию false у порта, true у GUI-команд проверяемого подбора инструмента/секций. Обе полные DXF-формы должны реально использоваться в расчёте; параметрический/неполный профиль не подменяет корпус. Все члены совместной операции должны входить в область изменения и иметь согласованные неизменные профили/параметры.

Окно подчиняется прежнему **максимальному зазору** из настройки. Программа не повышает его сама. Например, при пределе 3 мм она не создаст окно 20 мм; технолог может явно изменить предел либо настроить сборку вручную. Это геометрическая настройка, не расчёт допустимого неподкреплённого материала.

Ручной фиксированный маршрут не перепланируется. Профиль/ручей/пуансон, ориентации, станок, упор и прочие входы не меняются ради окна. Сборки исходных четырёх вариантов D167 остаются первым семейством; окно является отдельной последующей ограниченной попыткой.

## Откуда берётся окно

При реальном объёмном пересечении Sheet–Die адаптер читает **уже вычисленный Common** текущего кадра. Его Z-границы с наружным округлением до 0,001 мм и запасом 4 CAD-допуска задают предложение. Новых Boolean или meshing для этого нет. Предложение выдаётся только если весь интервал помещается в один промежуток между реальными активными зонами и в этом положении нет одновременно другого конфликта инструмента/станка.

`BendPreviewError` переносит только численный `ToolWindow` и вид конфликтующей пары. Компактный LRU сохраняет их вместе с точным состоянием/интернированными назначениями/группой/стороной/offset. Ни BRep пересечения, ни аварийные кадры в кэш отказов не добавляются. Граница Common является **предложением**, а не доказательством отсутствия последующих пересечений.

Для одной операции сначала пробуются обычные составы, стороны и положения. Затем используются не более четырёх точных отказов-оснований, с мягким приоритетом меньшего наружного охвата/интервала коллизии. Заведомо более широкий, чем разрешённый зазор, конфликт не запускает DP. Порядок/пара ниже по общему поиску могут оказаться удобнее без окна: глобальный минимум окон, смен и манипуляций не заявлен.

## Численный подбор

Core `planToolWindow` распределяет один захваченный склад между левой и правой частями. Ограничения:

- общий наружный охват матрицы сохраняется **точно**; внутри одного плана обе стороны используют общий счётчик наличия;
- левый конец окна не заходит на требуемую зону слева, правый — на требуемую зону справа;
- окно покрывает предложенный конфликт, не превышает максимальный зазор; на остальных стыках зазор нулевой;
- только прямые секции, прежние 64 строки/512 секций/100000 мм/точность 0,001 мм; рожки без собственной 3D-геометрии не допускаются.

Разреженный ограниченный DP хранит достижимые пары сумм, не координатную сетку. Для одинаковых сумм достаточно варианта с меньшим числом секций на обработанном префиксе склада. Первая найденная пригодная сборка возвращается без обещания глобального оптимума. Лимит — 200000 рассматриваемых добавлений, отмена внутри цикла. Ограничение/отмена не становятся ответом «невозможно».

На одну проверку операции — не более четырёх предложенных сборок, до двух уточнений одного окна по новому реальному конфликту позднего кадра. Новое окно не выводится из другой пары столкновения, не объединяет разрывы через активную зону. До 32 компактных планов живут только в текущем worker; ключ содержит фактический интернированный отказ, весь численный интервал и предел зазора. Между запросами повторно используются прежние точные переходы/отказы и кэш тел. Нового дискового кэша маршрутов нет.

Положение детали и сторона фиксируются по тому отказу, который вызвал предложение. Сохранённый охват матрицы сохраняет привязки к пуансону и станку, диапазоны Z упоров не сдвигаются. Новая сборка получает свою подготовку и точный ключ; подготовка D170 не переносится между разными сборками.

## Проверка и применение

Каждая новая сборка проходит общий checker: исходный материал, обе реконструкции, поддержанные интервалы, длины/V, все кадры/коллизии, станок/пол/упоры, sweep и независимое сравнение канонического предшественника. D172 отклоняет инструментальный разрыв под активным материалом; D100/D165 не разрешают внутреннюю потерю опоры.

Application до атомарного применения проверяет разрешение на новый список стыков матрицы, область каждого ID, неизменность профилей, наличие, предел каждого зазора и соответствие параметров реальному preview. Дополнительно численно пересчитывает охват каждой требуемой зоны новой сборкой, чтобы старый preview той же общей длины не принял окно, перенесённое под материал. Дополнительный зазор пуансона этим разрешением не создаётся.

Успешный путь хранит фактические ключи и назначения всех членов группы; отклонённый путь откатывается прежним способом. Сборки сохраняются в существующем `.bend` v18. Правила переоснастки/станции/переноса не добавлены. Неподдержанный вариант, неполный поиск, лимит и неизвестная коллизия остаются отличимыми от подтверждённого маршрута. При отказе пояснение может указать, что для одной из установок не хватило предела зазора или состава секций; это не утверждение о всех возможных установках.

## Границы следующего этапа

Не поддержаны несколько независимых окон, свободный перенос станции или изменение наружного охвата ради окна, изгиб над непрерывным неподкреплённым материалом и физика деформации/жёсткости. Реальный корпус оставшихся секций/адаптера не заменяется оболочкой. Точный импорт других креплений/станков и реальных сапожков остаётся отдельной задачей. Частный STEP не определяет правила алгоритма.

Контроли и результаты — в development.md. Исходный собственный fixture имеет два совпадающих по оси гиба и обратный центральный отгиб на общей стенке; геометрия повернутого STEP также проверяется. Отдельный паз без коллизии должен проходить со сплошной матрицей и нулём планов окна.
