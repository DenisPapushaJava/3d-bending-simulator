## Схема

`YYYY.RELEASE.PATCH[-CHANNEL.N]`, например **2026.1.0-alpha.1**. Это календарная схема с привычными prerelease-суффиксами, не обещание SemVer-совместимости по полю major.

| Часть | Значение |
| --- | --- |
| 2026 | Год начала линии выпуска |
| 1 | Номер функционального выпуска в этом году, начиная с 1; не месяц |
| 0 | Исправление в рамках линии |
| alpha.1 | Канал и номер предварительной сборки |

Пример продвижения: `2026.1.0-alpha.1` → `alpha.2` → `beta.1` → `rc.1` → `2026.1.0`. Затем `2026.1.1` для исправления или `2026.2.0-alpha.1` для следующего выпуска. Новую линию в следующем году можно начать с `2027.1.0-alpha.1`. Год не пересчитывается автоматически при сборке старого тега.

`alpha` — неполные возможности и изменения; `beta` — проверка завершённого целевого сценария; `rc` — кандидат на стабильный выпуск. Стабильность и поддерживаемые операции должны следовать из проверок, а не только из имени версии.

**VERSION** — единственный источник версии. CMake и окно читают VERSION, числовая часть передаётся в `project()`. vcpkg.json содержит зависимости без версии приложения: для корневого проекта она необязательна, а изменение номера выпуска не должно сбрасывать кэш SDK. Тег имеет префикс `v`: `v2026.1.0-alpha.1`.

## Минимальный процесс

1. Закончить изменение и проверить main.
2. Обновить VERSION и запись в CHANGELOG.md одним PR/коммитом. Для каждой новой предварительной сборки увеличивать N.
3. После зелёного CI создать новый тег на проверенном коммите:

```bash
git switch main
git pull --ff-only
git tag -a v2026.1.0-alpha.1 -m "3D Bending Simulator 2026.1.0-alpha.1"
git push origin v2026.1.0-alpha.1
```

4. CI повторно проверит тег, выполнит сборки/тесты обеих ОС и подготовит Windows-комплект с соответствующими исходниками. Только после успеха создаст **draft GitHub Release**; наличие LICENSE обязательно.
5. Проверить состав, контрольные суммы, запуск на целевой Windows/видеокарте и заявленные ограничения. Опубликовать готовый черновик через GitHub. Для alpha/beta/rc выставляется prerelease, для стабильного — нет.

Не перемещать опубликованный тег и не перезаписывать опубликованные артефакты. Исправление выпускается новой версией. Повторный запуск workflow обновляет только существующий черновик; опубликованный релиз отвергается.

### Проверка черновика перед публикацией

- Скачать оба ZIP и `SHA256SUMS.txt`, сверить SHA-256 и целостность архивов. В Windows ZIP проверить EXE x64, Qt Core/Gui/Widgets/Network DLL, OCCT/FreeType DLL, `platforms/qwindows.dll`, `tls/qschannelbackend.dll`, ресурсы OCCT, учебные STEP, VERSION и лицензии, включая OFL шрифта в `share/doc/BendingSimulator/licenses/fonts`. Начиная с alpha.2 пути bin/share находятся внутри `runtime/<VERSION>`.
- Проверить соответствующие источники: Qt base 6.8.3, OCCT 7.9.3 и FreeType 2.14.3 с патчами зафиксированных портов, рецепт vcpkg, triplet и уведомления. Пользовательские STEP, чертежи инструмента и локальные каталоги в архив не добавлять.
- Проверить в логе тега оба запуска из упакованного каталога с очищенным PATH: окно и импорт учебного STEP. Это проверка загрузки комплекта offscreen, не интерактивного OpenGL.
- Проверить отдельный font-probe из того же каталога: растеризация латиницы/кириллицы/знака градуса в обычном и жирном sans-serif без GPU. Временный EXE проверки удаляется перед архивацией; FreeType DLL и её уведомления остаются в поставке.
- Для первого alpha явно указать в описании, если интерактивная Windows/GPU ещё не проверена. Снять эту оговорку можно только после реального запуска на целевой системе; успешная сборка/CTest её не снимают.
- На странице скачивания поставить Windows ZIP и краткую инструкцию запуска первыми; исходники зависимостей и контрольные суммы обозначить отдельно.

## Комплекты первого выпуска

Целевая система комплекта — **Windows 10 (1809 или новее) / Windows 11, x64**, в соответствии с [платформами Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html). Это ограничение выбранного SDK, а не результат интерактивной проверки нашего приложения на каждой ОС/видеокарте.

- `3d-bending-simulator-2026.1.0-alpha.1-windows-x86_64.zip`: приложение, Qt/OCCT/FreeType DLL, плагины, уведомления. В Windows может потребоваться Microsoft Visual C++ 2015–2022 x64 Runtime; он не включён в ZIP. Это пока не установщик и не подписанная поставка.
- `3d-bending-simulator-2026.1.0-alpha.1-dependency-sources.zip`: соответствующие источники Qt, OCCT и FreeType с патчами портов, рецепт vcpkg и лицензионные материалы. Публикуется рядом с Windows-комплектом.
- `SHA256SUMS.txt` для обоих ZIP. На PR/main релизные архивы не готовятся.
- GitHub автоматически предоставляет снимки исходников проекта для тега.

Локальный CPack DEB остаётся доступен для Ubuntu 24.04 / Mint 22.x, но не входит в CI и релизные assets. У него prerelease записывается как `2026.1.0~alpha.1`, чтобы он сортировался до стабильного выпуска; внешнее имя файла и версия приложения сохраняют `2026.1.0-alpha.1`.

Первый выпуск `2026.1.0-alpha.1` включает импорт/просмотр STEP, толщину и локальное распознавание сгибов, `.bend` v5, предварительный подбор инструмента по параметрам, геометрический просмотр одного поддержанного сгиба и справочный PDF готовой формы. Полный состав и ограничения — в [CHANGELOG](../CHANGELOG.md). Полный маршрут, физика материала и встроенное обновление ещё не реализованы. Интерактивный Windows/GPU-пункт M1.1 проверяется отдельно от сборки CI; первый экспериментальный alpha должен явно сохранять эту непроверенную область в описании выпуска.

## Почему пока так

Один main и выпуск по явно созданному тегу достаточны для старта. Автовыпуск при каждом коммите, GitFlow, обязательные согласования, публикация пакетов в менеджеры, автоувеличение версии не нужны. D042 добавляет ручную проверку и, по следующему уточнению пользователя, применение обновления кнопкой «Обновить и перезапустить». Программа должна сама подготовить комплект и заменить его после корректного выхода; без команды человека проверка/установка не запускаются. Механизм D065 реализован локально, Windows-приёмка впереди. Перед первым стабильным выпуском потребуется решить формат установщика, подпись и политику поддержки.

Основа правил: [CalVer](https://calver.org/) и [порядок prerelease в SemVer](https://semver.org/). Скрипт разрешает только alpha/beta/rc с положительным N; `2026.1.0-alpha` без номера не используется.


## Значок в комплекте — D046

Значок окна встроен в binary как PNG и не зависит от соседних файлов/Qt SVG. Windows EXE также содержит ICO resource, поэтому создаваемые средствами Windows ярлыки используют собственный значок программы. Существующий portable ZIP не требует нового Qt-плагина. Политика Windows-only релизов и ручных обновлений D042 сохранена; новый тег/установщик ради значка не создаётся.

## Архив зависимостей для сборки — D049

Отдельный технический prerelease `sdk-windows-x64-2026.1` хранит `windows-sdk-2026.1.zip`, описание семи ABI-пакетов и SHA256SUMS.txt. Он сохраняет уже собранные OCCT 7.9.3 / FreeType 2.14.3 и служебные пакеты, не содержит Qt или приложения. Бинарные ZIP сохраняют уведомления, дополнительно вложены LGPL/исключение OCCT, FTL, MIT/X11/zlib и Bitstream/DejaVu notices. Соответствующие исходники и патчи — [опубликованный companion](https://github.com/DenisPapushaJava/3d-bending-simulator/releases/download/v2026.1.0-alpha.1/3d-bending-simulator-2026.1.0-alpha.1-dependency-sources.zip), его SHA-256 зафиксирован в sdk.json. Дублировать исходники Qt внутри SDK не требуется.

SDK публикуется после проверки отдельной командой, без отметки latest. Тег начинается с `sdk-`, поэтому не запускает CI выпусков `v*` и не сравнивается как версия приложения. Клиент D065 выбирает только допустимые `vYYYY.RELEASE.PATCH…` и asset приложения; SDK не является предложением обновиться. VERSION и опубликованный первый alpha остаются прежними. [Экспорт, восстановление и проверки](development.md#постоянный-архив-sdk--d049).


## Следующий комплект с обновлением — D065

Новый ZIP запускается через EXE в корне; payload находится в `runtime/<VERSION>/bin` и `runtime/<VERSION>/share`, настройки отдельно в `data/settings.ini`. Упаковщик пишет манифест с хешами, VERSION/.ready, portable-format/current и включает native launcher protocol 1. Существующий опубликованный alpha.1 не меняется: его структура/ограничения выше исторические, первый переход на новый формат — вручную. VERSION при локальной разработке не повышается автоматически.

Qt6Network.dll и tls/qschannelbackend.dll обязательны; OpenSSL backend исключён, Qtbase source companion/уведомления сохраняются. Пробы упаковщика без SDK PATH проверяют шрифт, startup и `--update-runtime-probe` без сетевого запроса; затем повторяются startup/TLS через root launcher. GUI по-прежнему может требовать Microsoft Visual C++ x64 Runtime; только bootstrap использует статический CRT. No-compiler-runtime не означает автономность GUI.

Перед следующим выпуском дополнительно проверить на Windows два **различных** номера версии: ручную команду, реальный HTTPS/Schannel, ZIP/SHA, отмену, сохранение/ошибку сохранения, ожидание завершения, повторное открытие проекта и сохранность INI, откат после отказа нового процесса и восстановление журнала. Финальный ZIP распаковать в другую папку с чистым SDK окружением. Нужен запуск на целевом Windows/GPU; Linux fixture это не подтверждает. По D051 эти Windows/CI-проверки и выпуск пока не запускались. [Подробный контракт](portable-releases-updates.md).

Bootstrap protocol 1 не заменяется при штатном обновлении. Исправление самого bootstrap/новый protocol требует полного ZIP в новую папку; неподдержанный пакет отвергается до выхода. Старые версии/помощники автоматически не очищаются. Механизм SHA-256/HTTPS пока не имеет подписи издателя.


## Стартовые профили — D128

Следующий runtime содержит встроенный фиксированный DXF-набор из [семи профилей](starter-tool-library.md). Он входит в EXE как Qt-ресурс и автоматически учитывается хешем binary в portable-манифесте; отдельная копия личной библиотеки для упаковки не требуется. Упаковщик продолжает исключать data/.updates. На реальном первом запуске отсутствующий `data/tools/tool-catalog.json` создаётся атомарно из ресурса без остатков; обновление не меняет существующую мастерскую/удаления. Проверить это на чистой Windows и при обновлении с изменённой библиотекой перед выпуском. Smoke-probes читают встроенный ресурс, но не засеивают пользовательские настройки.

Состав явно зафиксирован по поручению пользователя; новые личные DXF/архив не захватывать при сборке. Исходные заводские файлы в ZIP не входят, происхождение технических снимков — в src/project/data/README.md и лицензионном реестре. По D051 Windows ZIP/удалённый CI/новый тег ещё не выполнялись.


## Стартовые детали — D129

В состав установки и Windows runtime входит явный список из `cmake/example-parts.json` и `examples/README.md`: четыре STEP, включая панель L1000 с 16 гибами. Каталог `tests/data/step` в комплект не попадает. Пользователь открывает примеры из `runtime/<VERSION>/share/3d-bending-simulator/examples`, без дополнительных экранов/кнопок. Изменение файлов в личной папке примеров не меняет поставляемый набор. Smoke-test упаковщика загружает `profiled-bend-6mm.step`; штатный CI Windows остаётся необходимым перед выпуском. D129/D130 проверяются локально, релиз в этом поручении не создаётся.
